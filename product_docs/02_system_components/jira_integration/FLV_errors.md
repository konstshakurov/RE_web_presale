# FLV — отказы Jira, карта ошибок, деградация

Источник: `backend/app/integrations/jira/errors.py`, `sync/service.py`, `assign/service.py`, `jira_session/`. Требования: FR-029, NFR-003, NFR-008, NFR-009, BR-001.

## Принцип

«Jira недоступна» и «сессия истекла» не смешиваются: первое лечится ожиданием, второе — повторным вводом пароля. Приложение не разбирает HTTP-коды и классы клиента — только `code` единой карты. Текст отказа Jira показывается пользователю как есть (после `redact`, ≤2000 символов); введённые пользователем данные не теряются.

## Единая карта (`JiraIntegrationError.code`)

| `code` | Когда | Что делает приложение | Повтор |
|---|---|---|---|
| `needs_reauthorization` | 401 `login_required` / `invalid_cookie_or_expired` / нет cookie; токен не расшифровывается (`CryptoError`) | запросить пароль (`/auth/jira-relogin`); опрос помечает токен «отвергнутым» и ждёт нового входа | после ввода пароля |
| `no_permission` | 403 / «нет прав» | показать отказ; опрос пробует токен другого пользователя | не поможет |
| `auth_failed` | неверный логин/пароль при входе | показать отказ | после исправления |
| `login_blocked` | Jira требует подтверждение входа в браузере (CAPTCHA/блокировка) | показать отказ; по REST не лечится | нет |
| `jira_unavailable` | сеть, TLS, таймаут (10 с), 5xx, 429 | «Превышено время ожидания ответа Jira (N с)» / текст Jira; не спрашивать пароль | да, позже |
| `jira_error` | 400/404/409, 500 на переход или ставку, прочее | показать текст Jira как есть | по смыслу |

Исключения из общего правила «5xx = недоступна»: **500 на `do_transition` и на `set_rate`** — это отказ запроса (`jira_error`), а не недоступность: повтор бессмыслен (KON-42 D3, KON-99).

## Ошибки до обращения к Jira (проверки приложения)

`rate_required`, `bad_request` (ставка ≤0 или >1 000 000; нет причины/комментария для «Кандидатов нет»; не заполнены обязательные поля перехода), `employee_no_profile` (у сотрудника нет «Профиля сотрудника»), `support_option_missing`, `file_not_found`, `employee_not_found`, `need_not_found`. Jira при этом не вызывается.

## Деградация по сценариям

| Сценарий | Поведение |
|---|---|
| Фоновый опрос: Jira недоступна | кэш остаётся прежним; в `sync_state` пишется ошибка; штамп `stale=true`, «актуально на» = последний успех; перебор токенов прекращается |
| Фоновый опрос: 401 | токен помечается «отвергнутым» (`_dead[login]`); берётся токен следующего активного пользователя; если все отвергнуты — Jira не дёргается, статус `needs_reauthorization` |
| Фоновый опрос: нет активных сессий | `paused`; новый вход замечается через 15 с |
| Опрос уже идёт | второй запуск возвращает `busy`, без ошибки |
| Эпик: отказ Jira | есть кэш → кэш с `stale=true` и `error`; нет кэша → код отказа и текст Jira |
| Запись: сессия истекла | 409 + `completed`; повтор с `completed` дорабатывает остаток |
| Запись: сбой ставки после назначения | назначение не откатывается; 200 + `rate_pending` + предупреждение |
| Запись: обход 11506, не удалось вернуть «Да» | операция выполнена, в `warnings` — «верните «Да» вручную в Jira» |
| Запись: «потребность изменилась» | перед записью потребность и переходы перечитываются; если перехода уже нет — 409 `transition_unavailable` |
| После записи перечитать не удалось | операция остаётся выполненной, `refreshed=false`, кэш обновится ближайшим опросом |
| `JIRA_BASE_URL` не задан | `not_enabled`; приложение работает на кэше, запись недоступна |
| Падение приложения | Jira не блокируется (NFR-003): все данные в Jira первичны |

## Лимиты

* Таймаут одного вызова: 10 с (NFR-009); повторов нет; суммарное время операции может превышать 10 с (назначение = 3–6 вызовов, до +2 при обходе 11506) — см. D-7 в `README.md`.
* Страницы поиска: 100 записей, до 200 страниц за опрос.
* Устаревание: потребности ≤ 5 мин при живом опросе (NFR-008); без активных пользователей — пауза и пометка.

## Что не покрыто (открыто)

* Срок жизни сессии Jira не измерен (определяет частоту повторного ввода пароля) — `architecture/README.md`, вопрос 3.
* Поведение при блокировке учётки Jira после серии неверных паролей (`login_blocked`) на проде не проверялось.
