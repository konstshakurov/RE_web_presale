# KON-79 — действия со статусом потребности: логика кнопок

Основание: решение владельца 15.10.2026 (статусная модель Jira, скриншоты workflow «Department requirements workflow»), CR-005. Прототип: `variant_a.html` (список).

## Правило
В столбце «Статус» под чипом показываются **ссылки-кнопки** (синий текст без рамки, как «Правила клиента»). Кнопка показывается по двум условиям, **без запросов к Jira** (решение KON-96, владелец, 20.10.2026, вариант A):
1. целевой статус входит в **белый список действий РН/РО/Presale**: «Поиск кандидата», «Найм», «Кандидатов нет» (отдельной кнопки «Кандидат назначен» нет — назначение только через «Назначить»);
2. текущий статус потребности (из кэша `jira_need`) даёт этот переход по матрице ниже. Открытие списка не делает обращений к Jira.

Точные переходы и обязательные поля запрашиваются у Jira **при клике** на кнопку (`GET /needs/{key}/status-actions`, FR-026): диалог начинается с «Запрашиваем доступные действия в Jira…». Если Jira переход не отдала (права, нестандартный workflow) — диалог показывает «Действие недоступно: Jira не предлагает переход в «…» из статуса «…» (права или воркфлоу)», а отказ Jira при записи — текстом как есть (FR-029). Кнопка может быть показана, а переход не разрешён — это ожидаемо.
Если переходы запрашиваются часто, Dev вправе добавить короткий кэш переходов в backend (TTL ≈ 5 мин, ключ «потребность + статус», сброс при записи) — только при необходимости.

Остальные переходы (интервью, закреплён, на проекте, отложено, неактуально и др.) ведут клиентская служба и автор потребности; в приложении их нет. Для статусов без наших действий (включая «Отказ по кандидату») под чипом ничего не выводится: ни кнопок, ни пояснительного текста.

## Матрица (исходное состояние → кнопки)
| Статус потребности | Кнопки в столбце «Статус» | Назначение кандидата |
|---|---|---|
| Требуется кандидат | **Поиск**, **Найм**, **Кандидатов нет** | нет (сначала «Поиск») |
| Поиск кандидата | **Найм**, **Кандидатов нет** | «Назначить» у кандидата → статус «Кандидат назначен» меняет Jira |
| Кандидатов нет | **Поиск**, **Найм** | по запросу Jira (если отдаёт переход) |
| Найм | **Поиск**, **Кандидатов нет** | по запросу Jira |
| Кандидат назначен | **Поиск**, **Найм**, **Кандидатов нет** | повторное «Назначить» заменяет назначение (FR-010) |
| Отказ по кандидату | нет кнопок статуса | «Назначить» у кандидата из «Сопоставить» → Jira переводит в «Кандидат назначен» |
| Прочие (Интервью…, Закреплён, На проекте, Отложено, Неактуально, …) | нет, текста нет | нет |

Подписи кнопок — как целевые статусы Jira, кроме «Поиск» (переход в «Поиск кандидата»). Матрица — стартовая; окончательно переход подтверждает Jira при клике (см. выше), поэтому расхождения диаграммы и реальных переходов не ломают UI: кнопка покажет «Действие недоступно».

## Что происходит по кнопкам
- **Поиск** — перевод в «Поиск кандидата»: подтверждение одним кликом.
- **Найм** — перевод в «Найм» (переход «В найм», id 801): подтверждение с полями «Включает НДС» (20810), «Валюта» (20811), «Единица измерения» (20812) — обязательны в Jira, предзаполняются из потребности, при отсутствии значения выбираются из справочника Jira (до отправки — проверка обязательности). **Ставка («Планируемая ставка», 20809) здесь не вводится и не показывается как поле**: её вносят при назначении, в окне «Назначить» (FR-018 v3.0, FR-011 v1.3; CR-008). Диалог с полем ставки и ориентиром (CR-007, `design/KON-98/`) отменён.
- **Кандидатов нет** — диалог: «Причина отсутствия кандидата» (справочник Jira, обязательна) и «Комментарий» (обязателен, видимость «для всех»).
- «Назначить» у кандидата (в том числе для потребности в «Отказ по кандидату») — окно из варианта A; статус «Кандидат назначен» меняет Jira. Отдельной кнопки «Кандидат назначен» в столбце «Статус» нет: назначение делается только через сопоставление и «Назначить».
Отказ Jira — текст как есть, введённое сохранено, «Повторить». После успеха потребность перечитывается, чип и кнопки обновляются.

## Фильтры и настройки (замечания 1.1 и «Предложения 1»)
- **«Требуется кандидат» и «Поиск кандидата» уже входят в группу «Без кандидата» по умолчанию** (FR-035; миграция `V007__status_groups_seed.sql`, `status_groups/rules.py`). На скриншоте «Настроек» оба видны чипами группы «Без кандидата» (… «Найм», «Отказ по кандидату», «Поиск кандидата», «Требуется кандидат»). Выпадающий список «Выберите статус» показывает только статусы **вне групп**, поэтому этих двух там нет — это не пропуск. Менять нечего.
- Потребность в «Требуется кандидат» видна в приложении с первого опроса (JQL по типу «Аналитик», FR-028).
- Источник потребности создаёт автор в статусе «Требуется кандидат»; переход в «Поиск кандидата» — по регламенту направления из нашей системы кнопкой «Поиск» (новое по сравнению с FR-011).
