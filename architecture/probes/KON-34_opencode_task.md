# Задача для OpenCode: KON-34 (Pre.Dev-3) — jira_client: доработка, чтение и вход по паролю

Срок: 2026-10-12 (допущение). Приоритет высокий: от этой задачи зависят Pre.Dev-18 (KON-52, сессия Jira при входе в приложение) и Pre.Dev-4 (KON-35, синхронизация).

## Контекст

Репозиторий `re_web_presale`. Модуль `src/jira_client/` (Python, `httpx`) уже написан и проверен пробой KON-30: чтение 17 из 17, 258 тестов. Задача — **доработка и интеграция, а не написание с нуля**. Целевая Jira — Jira Server 8.13.0 (REST v2 и Agile API, PAT нет).

Способ доступа — сессионная cookie пользователя, без технической учётки и без Application Link. Логин и пароль Jira совпадают с корпоративным LDAP. Сессия Jira создаётся при входе в приложение одним вводом пароля: пароль живёт только в памяти запроса, не сохраняется и не логируется; хранится только сессионный токен, зашифрованно.

Читать: `src/jira_client/README.md`, `src/jira_client/auth.py`, `architecture/probes/KON-30_jira_probe_report.md`, `architecture/03_adr.md` (ADR-005). Тестовые ключи задач выдаёт Константин отдельно; секреты в репозиторий, фикстуры, логи и Linear не класть.

Область записи: только `src/jira_client/` и новый адаптер в `backend/app/integrations/jira/` (см. п. 6). Не менять `db/migrations/`, `docker-compose*.yml`, `output/`, остальной код `backend/`.

## Что сделать

1. **Включить обмен пароля на сессию.** `SessionLoginProvider` в `auth.py` сейчас отключён и бросает `PermissionError` (решение владельца 05.10 снимает запрет). Заменить флаг `enabled` на явную работающую реализацию:
   `login(username, password) -> SessionToken` — `POST /rest/auth/1/session` с плоским телом `{"username": ..., "password": ...}` (форма подтверждена пробой), возвращает имя cookie и значение токена. Обновить комментарии и README: убрать формулировки «выключен / запрещено UC-005 и NFR-006», описать, что пароль не сохраняется.
2. **Пароль не утекает.** Пароль не попадает в логи, `repr`, `last_call`, исключения, фикстуры и трассировки. Исключение `JiraError` на отказе входа не содержит тело запроса. Добавить тесты по аналогии с `tests/test_no_secrets.py` (в т.ч. на `login`).
3. **Классификация отказов входа** отдельными признаками: неверный логин/пароль (401, `x-seraph-loginreason: AUTHENTICATED_FAILED`), CAPTCHA/блокировка (`AUTHENTICATION_DENIED` — Jira требует ввод через браузер; отдать отдельным признаком `login_blocked`), Jira недоступна (сеть/TLS/таймаут) — не путать с «неверный пароль». HTML-ответ пользователю не показывать.
4. **Порт `JiraPort`** со всеми операциями чтения: `search_incremental` (по `updated`, только изменённые), `get_issue`, `get_epic_children` (Agile API, не JQL с `parent`), `get_epic`, `check_session` (`/rest/api/2/myself`), `login(username, password)`. Список полей настраивается. Поле эпика: `customfield_10101` + Agile API (канонический выбор между 10101 и 11032 — открытый вопрос владельцу процесса).
5. **`TokenVault`** (AES-256-GCM, ключ из env `JIRA_TOKEN_ENCRYPTION_KEY`) подключён: сессионный токен хранится и передаётся приложению только в зашифрованном виде.
6. **Адаптер для приложения.** `backend/app/integrations/jira/` — тонкий слой, который реализует `JiraPort` поверх `jira_client`. Приложение вызывает только его. Для Dev-18 нужен интерфейс:
   - `login(username, password)` → токен (запечатанный `TokenVault`) + время создания;
   - `check_session(token)` → `ok | needs_reauthorization | jira_unavailable`;
   - единая карта ошибок: `needs_reauthorization` (401 `login_required` / `invalid_cookie_or_expired`), `no_permission`, `auth_failed`, `login_blocked`, `jira_unavailable`.
   Различать «Jira недоступна» и «сессия истекла».
7. **Классификация 401 сохраняется:** `no_credentials`, `login_required`, `no_permission`, `auth_failed`, `invalid_cookie_or_expired`.

## Критерии приёмки

1. `login` с верными данными возвращает токен; затем `check_session` с ним даёт `ok`; с неверным паролем — `auth_failed`; при блокировке — `login_blocked`; при недоступной Jira — `jira_unavailable`, а не «неверный пароль».
2. Инкрементальная выборка по `updated` возвращает только изменённые задачи.
3. Дети эпика читаются через Agile API; список полей настраивается.
4. Ни пароль, ни токен, ни cookie не попадают в логи, `repr`, исключения и фикстуры (тесты на это в CI остаются и расширены на `login`).
5. Повторы запросов выключены, лимит 10 с на вызов (NFR-009).
6. Все тесты зелёные без сети (`httpx.MockTransport`); живая проверка `login` + `check_session` + чтение одной задачи — на тестовых ключах, результат (без секретов) записан в `architecture/probes/KON-34_report.md`.
