# KON-115 (Pre.UX-7) — Редактор заметки сотрудника в «Резюме»: решение

**Статус: approved** · дата: 21.10.2026 · утвердил: Константин (владелец, явное решение в чате) · автор: UX

Единственный вход для Dev по задаче KON-114 (Dev, фронтенд). Отклонение от решения — только через возврат к UX. Бриф и сравнение вариантов — `brief.md`, `README.md`; варианты A и C — архив, не реализуются.

## 1. Выбрано
**Вариант B — модальное окно.** Прототип: `design/KON-115/variant_b.html` (после правки по ответу владельца; открыть двойным кликом, «Изменить» в любой строке). Снимки: `variant_b_<состояние>_<dark|light>_1280.png`, для `edit`, `error`, `long`, `over` также `_1024`. Состояния: `edit`, `empty`, `long`, `limit` (1962 из 2000), `over` (превышение), `clear` (поле очищено, «Очистить заметку»), `saving`, `error`, `saved` и `cleared` (таблица после закрытия окна: новый текст / «нет заметки», без пометок).

Требования не менялись (FR-033, Could, CR-004; FR-005 — учёт заметки при сопоставлении). Backend готов: `PUT /cv/employees/{employee_key}/note`, тело `{"note": "..."}`, ответ `note`, `note_author`, `note_updated_at` (KON-94). Новых токенов и зависимостей нет.

## 2. Ответы владельца
1. **Автор и дата НЕ показываются в таблице «Резюме».** В ячейке «Заметка» — только текст заметки (как в KON-78, п. 7). Автор (`note_author`, логин как отдаёт API) и дата (`note_updated_at`) показываются **только в модальном окне** (подзаголовок).
2. Подсказка «Учитывается при сопоставлении с потребностью» — остаётся.
3. Превышение 2000 знаков блокируется на клиенте: счётчик и рамка `--err`, «Сохранить» disabled, текст «Сократите текст на N знаков» — принято.
4. Кнопка при пустой заметке остаётся «Изменить» — принято.
5. Принято как допущения (с поправкой п. 6): двухшаговая очистка без диалога подтверждения; Ctrl+Enter — сохранить, Esc — отмена.
6. Пометка «Сохранено» / «Заметка очищена» в ячейке таблицы **убрана** (следствие п. 1). Обратная связь о сохранении — закрытие окна и обновлённый текст в строке (решение UX, см. п. 5.3).

**Владелец не менял:** состав состояний, раскладку окна (заголовок / тело / футер), тексты (кроме удалённых), лимит 2000, формат даты, порядок фокуса.

## 3. Раскладка окна
Окно `role="dialog" aria-modal="true" aria-labelledby`, ширина `min(560px, 100%)`, паттерн существующих окон (`Modal.tsx`: шапка и футер не прокручиваются, прокручивается тело; подложка `rgba(0,0,0,.6)`; Esc и × закрывают). Переиспользовать `Modal`/стили `.modal.pm`; компонент — `NoteDialog`.

- **Шапка:** `h2` «Заметка: <ФИО>» (18px, переносится), под ним строка 13px `--muted`: «Изменена: <логин>, <дд.мм.гг, чч:мм>» или «Заметки пока нет», если заметки нет (`note` пуст). Кнопка × (32×32, `aria-label="Закрыть"`).
- **Тело:** метка «Заметка» (`<label for>`, 600), `textarea` на 10 строк (min-height 220px, `resize: vertical`, фон `--panel-2`, рамка `--border`, радиус 4, фокус — кольцо `--accent` 2px); плейсхолдер «Например: ограничения по проектам или командировкам»; под полем строка: слева подсказка «Учитывается при сопоставлении с потребностью» (13px `--muted`), справа счётчик «N / 2000»; ниже блок ошибки.
- **Футер:** слева «Очистить» (текстовая кнопка, `--muted`); справа «Отмена» (вторичная), «Сохранить» (primary), левее них статус «Сохраняем…».
- **Таблица:** ячейка «Заметка» = текст (`white-space: pre-wrap`) или «нет заметки» (`--muted`), под ним `.act` «Изменить» (`aria-label="Изменить заметку: <ФИО>"`), кнопка больше не disabled. Строки с автором, датой и «Сохранено» в ячейке нет.

| Где | Текст |
|---|---|
| Кнопка в строке | «Изменить» (и при пустой заметке) |
| Заголовок | «Заметка: <ФИО>» |
| Подзаголовок | «Изменена: <логин>, <дд.мм.гг, чч:мм>» / «Заметки пока нет» |
| Метка поля | «Заметка» |
| Плейсхолдер | «Например: ограничения по проектам или командировкам» |
| Подсказка | «Учитывается при сопоставлении с потребностью» |
| Счётчик | «N / 2000» |
| Превышение (вместо подсказки) | «Сократите текст на N знак / знака / знаков» (1 — знак; 2–4 — знака; 5–20, 0 — знаков; 21 — знак; 11–14 — знаков) |
| Кнопки | «Сохранить», «Отмена», «Очистить», «Очистить заметку», «Закрыть» (×, aria) |

| Озвучка успеха (скрыто визуально) | «Сохранено» / «Заметка очищена» |
| Ошибка | текст `detail` ответа как есть (404 «Сотрудник не найден», 503 и др.) |

## 5. Состояния и поведение
1. **Открытие:** фокус в поле, курсор в конец текста; «Изменить» остальных строк недоступны (окно модальное). Поле = текущая `note` (пусто, если нет).
2. **Редактирование:** «Сохранить» активна только если текст отличается от сохранённого и длина ≤ 2000. Счётчик `aria-live="polite"`; от 1900 знаков — жирный `--text`; свыше 2000 — `--err`, жирный, рамка поля `--err`, подсказка заменяется на «Сократите текст на N знаков» (`--err`), «Сохранить» disabled. Жёсткого `maxlength` нет. Лимит считать как на сервере (по символам); поведение на эмодзи проверить при разработке (допущение).
3. **Сохранение и обратная связь:** по «Сохранить» / Ctrl+Enter — PUT; поле только для чтения, «Сохранить», «Отмена», «Очистить» и × disabled, «Сохраняем…». **Успех:** окно закрывается, фокус возвращается на «Изменить» этой строки, в ячейке — новый текст (из ответа API); визуальной пометки «Сохранено» нет — закрытие окна и новый текст и есть подтверждение; для скринридеров скрытый `role="status"` озвучивает «Сохранено» / «Заметка очищена» (≈4 с, затем очищается).
4. **Очистка (двухшаговая):** «Очистить» стирает текст в поле (ничего не отправляет), фокус в поле; если сохранённая заметка непуста, главная кнопка становится «Очистить заметку» (текст `--err`, не primary) — по ней уходит PUT с `""`. «Очистить» disabled, пока поле пустое. Диалога подтверждения нет. После успеха в ячейке «нет заметки».
5. **Ошибка:** блок `role="alert"`, `--err`, 13px, текст ответа как есть; введённый текст сохраняется; кнопки снова активны; фокус возвращается в поле. Для 422 по длине клиент отправку не допускает (п. 5.2); при истёкшей сессии — штатная обработка приложения.
6. **Закрытие:** «Отмена», ×, Esc — закрывают без сохранения (во время сохранения не работают); щелчок по подложке — только если текст не менялся и сохранения нет. Диалога «отбросить изменения» нет.
7. **Клавиатура:** Ctrl+Enter (Cmd+Enter) — сохранить (если доступно), Esc — закрыть; Tab циклически внутри окна (фокус-ловушка `Modal`).
8. **Длинная заметка (до 2000 знаков):** в окне поле прокручивается/растягивается вручную, в таблице ячейка растёт по высоте (`overflow-wrap: anywhere`).

## 6. Токены
Только существующие (`design/tokens.md`, `design/KON-78/decision.md`, раздел 3): `--panel`, `--panel-2`, `--border`, `--text`, `--muted`, `--accent`, `--err`, `--primary`, `--primary-hover`. Новых нет. Предупреждение у счётчика сделано жирным `--text`, а не `--warn` (контраст `--warn` в светлой теме ниже 4.5:1).

## 7. Ориентиры в коде (по состоянию на 21.10.2026; фронтенд читался без правок)
- Таблица «Резюме» и кнопка «Изменить» — `frontend/src/pages/ResumesPage.tsx` (столбец «Заметка»; кнопка сейчас disabled, KON-78 п. 7).
- Окно — `frontend/src/components/Modal.tsx`; образцы — `AssignDialog.tsx`, `resumes/UploadDialog.tsx`; новый компонент `NoteDialog` рядом.
- Типы — `frontend/src/api/types.ts` (`note`, `note_author`, `note_updated_at` уже есть); новый вызов API `PUT /cv/employees/{employee_key}/note`.

## 8. Критерии приёмки для QA
Проверять обе темы (тёмная, светлая), 1280 и 1024 — ключевые состояния против PNG.
1. Кнопка «Изменить» в каждой строке «Резюме» активна, подпись «Изменить» и при пустой заметке; `aria-label="Изменить заметку: <ФИО>"`.
2. Окно: заголовок «Заметка: <ФИО>», подзаголовок «Изменена: <логин>, <дата>» либо «Заметки пока нет»; шапка и футер не прокручиваются при длинной заметке; Esc и × закрывают; при открытии фокус в поле, курсор в конце; после закрытия фокус на «Изменить» строки.
3. **В ячейке таблицы нет автора, даты и пометок «Сохранено» / «Заметка очищена» — ни до, ни после сохранения** (только текст или «нет заметки»); автор и дата видны только в окне.
4. Подсказка «Учитывается при сопоставлении с потребностью» есть в обычном состоянии и заменяется «Сократите текст на N знаков» при превышении.
5. Счётчик «N / 2000» всегда виден; от 1900 жирный; при 2001+ красный (`--err`), рамка поля красная, «Сохранить» disabled, склонение «знак/знака/знаков» верное (проверить превышение на 1, 2, 5, 11, 21); при ровно 2000 сохранить можно.
6. «Сохранить» disabled, пока текст не изменён; при изменении активна; Ctrl+Enter срабатывает только когда «Сохранить» активна.
7. Успех: PUT с введённым текстом, окно закрывается, в строке новый текст с сохранением переносов строк; повторное открытие показывает автора и дату из ответа.
8. Очистка: «Очистить» стирает поле без запроса; кнопка становится «Очистить заметку» (красный текст); по ней PUT с пустой строкой, в ячейке «нет заметки», при повторном открытии «Заметки пока нет». Диалога подтверждения нет. «Очистить» disabled при пустом поле.
9. Сохранение: поле только для чтения, кнопки и × disabled, «Сохраняем…» со спиннером; Esc и подложка не закрывают.
10. Ошибка (404, 503, прочие): текст ответа как есть в блоке `role="alert"` красным; введённый текст сохранён; кнопки доступны, повтор возможен; окно не закрывается.
11. Щелчок по подложке закрывает только при неизменённом тексте и вне сохранения.
12. Скрытый `role="status"` озвучивает «Сохранено» / «Заметка очищена»; визуальной пометки нет.
13. Обе темы, 1280 и 1024: нет горизонтальной прокрутки окна, тексты не обрезаны, контраст текста и кнопок ≥ 4.5:1, кольцо фокуса видно на всех интерактивных элементах.
14. Регрессия: тесты, ожидавшие disabled-кнопку «Изменить» в «Резюме», обновлены; прочие окна не затронуты.

## 9. Не входит в объём
Автор/дата в таблице; редактирование заметки вне «Резюме»; история заметок; ФИО автора вместо логина (серверное сопоставление); обрезка пробелов сервером (не проверялась); варианты A и C.

## 10. Допущения
1. Автор выводится логином как приходит в `note_author` (в KON-78 был «Иванова А.»; ФИО — серверное сопоставление, вне задачи).
2. Тело 422 у FastAPI — массив, `errorText` даст общий «Проверьте введённые данные»; поэтому превышение блокируется на клиенте.
3. Тексты ошибок в прототипе — образцы; на проде выводится `detail`.
4. Шапка в прототипе упрощена, данные вымышлены, столбец «Файлы» упрощён.
