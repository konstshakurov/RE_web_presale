# Заявка в Support: виртуальная машина для внутреннего приложения (KON-49)

Черновик текста заявки. Значения в «ЗАПОЛНИТЬ» известны только заявителю; размеры ресурсов — оценка DevOps/Arch (допущения, см. внизу).

---

**Тема:** Виртуальная машина Linux для внутреннего веб-приложения подбора аналитиков (проект RE_web_presale)

**Заказчик / владелец сервиса:** Константин Шакуров, направление Аналитики. Контакт: ЗАПОЛНИТЬ.

**Назначение.** Внутреннее приложение для руководителей направления Аналитики и Presale-менеджеров (до 4 пользователей): список потребностей из Jira, резюме сотрудников, подбор кандидатов, запись назначения в Jira от имени пользователя. Только внутренняя сеть, без публикации наружу. Приложение работает в Docker Compose (nginx, веб-сервер, API, фоновый воркер, PostgreSQL 16); Docker и всё остальное ПО на ВМ устанавливаем и настраиваем сами.

## 1. Виртуальная машина
| Параметр | Значение |
|---|---|
| ОС | Linux, Ubuntu Server 22.04 LTS или 24.04 LTS (допустимо другое дистрибутив из поддерживаемых в компании; нужна поддержка Docker Engine и Compose v2) |
| vCPU | 4 |
| RAM | 8 ГБ |
| Диск | 100 ГБ SSD (система + БД + файлы CV; бэкапы — см. п. 4) |
| Количество | 1 ВМ (prod). Отдельная ВМ под тест не требуется |
| Имя / DNS | внутреннее DNS-имя вида `ЗАПОЛНИТЬ.simbirsoft.com` |
| IP | статический во внутренней сети |
| Время | синхронизация NTP, часовой пояс — местный |

## 2. Доступ к ВМ
- SSH-доступ по ключу для Константина Шакурова (ЗАПОЛНИТЬ: логин/ключ) и права `sudo` (нужно для установки Docker Engine и настройки сервисов), либо Docker Engine + Compose v2 предустановлены и пользователь в группе `docker`.
- Исходящий доступ к репозиторию пакетов ОС и Docker registry (или внутренний зеркальный репозиторий; укажите, как поставить Docker).

## 3. Сеть и доступы
**Входящие** (только из внутренней сети компании, не из интернета):
- TCP 443 (HTTPS приложения);
- TCP 22 (SSH) — только из подсети администраторов.

**Исходящие** с ВМ:
| Куда | Порт | Зачем |
|---|---|---|
| `jira.simbirsoft.com` (Jira 8.13.0) | 443 | чтение потребностей и запись назначений от имени пользователя |
| `freeipa01.simbirsoft` (LDAP, FreeIPA) | 389 (ldap://, без TLS) | вход пользователей: прямой bind под учётными данными пользователя, служебная учётка не нужна (ответ Support от 09.10) |
| `ollama-gpu.simbirsoft.com` | 3000 | внутренняя LLM (Qwen) |
| Внешние провайдеры LLM (список адресов ЗАПОЛНИТЬ при подключении; только HTTPS, в них уходит только обезличенный текст) | 443 | по отдельному решению администратора приложения |
| Репозиторий пакетов, Docker registry | 443 | установка и обновление |
| Корпоративный GitLab (опционально) | 443/22 | получение кода |

## 4. Хранение и резервное копирование
- Данные приложения нужно хранить **5 лет** без автоудаления.
- Бэкапы делаем сами (ежедневный `pg_dump` обеих БД, 30 суток + ежемесячные 5 лет). Просим подтвердить:
  1) входит ли ВМ в корпоративное резервное копирование (снапшоты/бэкап ВМ) и с какой глубиной;
  2) возможность выделить отдельный том или сетевое хранилище под бэкапы (оценка ~50 ГБ на 5 лет) вне диска ВМ — либо расширить диск ВМ до 150 ГБ.

## 5. Безопасность
- TLS: просим выпустить сертификат для DNS-имени ВМ (внутренний УЦ) и передать ключ и сертификат; либо указать порядок получения.
- Секреты (ключи шифрования, пароли БД) хранятся только на ВМ в env/secret-файлах, в репозиторий не попадают.
- Данные сотрудников и CV не покидают внутренний контур; во внешнюю LLM уходит только обезличенный текст.
- Логи JSON без секретов; мониторинг доступности `/health` раз в минуту, отчёт 9:00–18:00 по будням — своими средствами. Если в компании есть единая система мониторинга — просим указать, куда подключить.

## 6. Что просим предоставить в ответ
1. Адрес/DNS-имя ВМ, сетевые параметры и подтверждение открытых правил (п. 3).
2. Учётные данные доступа (SSH) и способ установки Docker.
3. Подтверждение п. 4 (бэкап ВМ, место под бэкапы).
4. Сертификат TLS и порядок обновления.
5. Подтверждение, что с ВМ доступны `freeipa01.simbirsoft:389` и `jira.simbirsoft.com:443`.
6. Ориентировочный срок выдачи ВМ.

**Срок.** Желательно до 2026-11-12 (ЗАПОЛНИТЬ при необходимости; выкладка идёт после локального тестирования MVP, не критично по дням).

## Допущения и заметки (не вставлять в заявку)
- Ресурсы выбраны с запасом: до 4 пользователей, 10–100 новых потребностей в неделю, файлы CV до 10 МБ, LLM-вызовы идут по сети (GPU на ВМ не нужен), PostgreSQL 16 в контейнере. При жёсткой квоте в компании минимально допустимо 2 vCPU / 4 ГБ RAM / 60 ГБ.
- Параметры LDAP уже получены от Support (09.10): сервер `ldap://freeipa01.simbirsoft:389/`, base DN `cn=users,cn=accounts,dc=simbirsoft,dc=dev`, шаблон bind `uid={login},cn=users,cn=accounts,dc=simbirsoft,dc=dev` (`.env.example`); в заявке повторно не запрашиваются. TLS для LDAP не используется (`ldap://`, не `ldaps://`; `LDAP_USE_TLS=false`) — в заявке не запрашивается.
- Источник требований: `architecture/05_deployment_security.md`, ADR-010, NFR-001/003/004/006/007, допущения A2/A6.
