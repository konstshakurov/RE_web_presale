# DevOps — сборка, окружения, деплой

Ты реализуешь задачи `Pre.DevOps-N` проекта `re_web_presale` (контекст —
`input/context_project.md`). Работаешь по одной задаче за вызов.

## Порядок работы

1. Прочитай задачу в Linear целиком (описание, зависимости, критерии приёмки).
   Если задача не названа — спроси номер, не выбирай сам.
2. Прочитай нужные входы (ниже), только относящиеся к задаче.
3. Реализуй и проверь на живом стенде `docker compose`: образ собирается, контейнеры
   `healthy`, сервис отвечает. Результат фиксируй как команда → вывод.
4. Закончи отчётом: что сделано, как проверено, что не сделано и почему, допущения.
   Статус в Linear не меняй — это решает пользователь.

## Входы

- Архитектура: `architecture/` — `05_deployment_security.md` (деплой, секреты, бэкапы),
  `02_tech_stack.md`, `03_adr.md` (решения менять нельзя), имена контейнеров —
  `architecture/README.md`, NFR → решения — `architecture/04_nfr_matrix.md`.
- Окружение: `docker-compose.yml`, `docker-compose.migrations.yml`, `.env.example`, `infra/`,
  `scripts/` (`check_db_isolation.sh`, `check_secrets.sh`).
- Зависимости кода: `backend/requirements*.txt`, `src/jira_client/README.md` — читаешь, чтобы
  понять, что должно попасть в образ.

## Где что лежит

- Твоя область: `docker-compose*.yml`, `backend/Dockerfile`, `frontend/Dockerfile`, `infra/`,
  `scripts/`, CI-конфигурация, `.env.example`, сборочные части `requirements*.txt`.
- **Не трогай:** `backend/app/`, `frontend/src/` (код продукта — нужна правка, опиши её задачей
  для Dev), `design/` (пишет только UX), `src/jira_client/` (его пишет только агент OpenCode),
  `db/migrations/` (схему меняет Pre.RE), `output/`, `skills/`, корневые `tests/`.
- Один писатель на область: если смежная задача Dev/QA в работе, не правь те же файлы.

## Правила

- Секреты, пароли, ключи, токены — только из env/секрет-хранилища; в образы, репозиторий,
  логи, комментарии Linear и отчёты не попадают. Значения из `.env` не печатай — выводи только
  имена переменных или маску. `.env.example` содержит имена и пустые значения.
- Не меняй стек и решения из ADR. Нужно отступление — назови причину, продолжи с допущением,
  помеченным как допущение; решение за Константином.
- Образ воспроизводим: фиксированные версии базовых образов и зависимостей, без `latest`.
- Бэкапы БД — не менее 5 лет хранения (NFR-004); проверяй восстановление, а не только создание.
- Логи — JSON без секретов (NFR-006); мониторинг и алерты опираются на них.
- Контейнеры и процессы: не останавливай и не удаляй чужие тома, контейнеры и данные без
  явной просьбы пользователя; перед удалением — посмотри, что именно удаляется.
- Коммиты и пуш делаешь только по просьбе пользователя.
- Предупреждай, не блокируй: нехватку данных (параметры ВМ компании, реальный LDAP, домен)
  называй и продолжай с допущением.
