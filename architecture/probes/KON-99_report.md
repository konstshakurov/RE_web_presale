# KON-99 — отчёт: кнопка «Ставка» в карточке потребности (как записать ставку от производства через REST)

Дата пробы: 2026-10-20. Автор: OpenCode. Область записи: `architecture/probes/KON-99_report.md`;
`src/jira_client/` и `backend/app/integrations/jira/` — не менялись (см. §9).

**Обезличивание.** Логины и ФИО в отчёте замаскированы (`<логин кандидата>`, `<логин оператора>`),
как в KON-42. Секретов (пароль, cookie) в отчёте нет. Тестовый ключ — `ANALYTICS-5925`.

| # | Итог |

## 1. Что такое «Ставка» технически

Кнопка «Ставка» в карточке — это веб-элемент **ScriptRunner** (`com.onresolve.scriptrunner`).
В HTML карточки (`GET /browse/ANALYTICS-5925`) есть:

```html
<a ... href="/rest/scriptrunner/latest/custom/rateCalculationWindow?issueKey=ANALYTICS-5925">
  <span class="trigger-label">Ставка</span></a>
```

Это **custom REST endpoint ScriptRunner** (Groovy-скрипт `Script277`), а не:

- не workflow-переход: `GET /issue/ANALYTICS-5925/transitions?expand=transitions.fields&includeUnavailableTransitions=true`
  отдаёт только 7 обычных переходов (31, 711, 261, 231, 251, 801, 901) — перехода «Ставка» нет;
- не обычное поле задачи: `GET /issue/ANALYTICS-5925/editmeta` **не содержит** `customfield_20809`–`20812`
  и `customfield_21105` — поэтому `PUT /issue` их не берёт (подтверждает KON-42, шаги 2–3).

### Механизм (точно как в браузере)

1. **Открытие диалога:** `GET /rest/scriptrunner/latest/custom/rateCalculationWindow?issueKey=ANALYTICS-5925`
   - заголовок `Accept` должен допускать HTML (`*/*` работает; `text/plain`/`application/xhtml+xml` → 406);
   - возвращает HTML-фрагмент `<section id="rate-dialog">` с формой `#rate-form`.
2. **Сохранение:** JS формы вешает `submit` и делает
   `POST /rest/scriptrunner/latest/custom/rateCalculationLogic` с JSON-телом (`Content-Type: application/json;charset=utf-8`).

Фрагмент JS из диалога (подтверждает состав тела):

```js
const body = { issueKey: 'ANALYTICS-5925', currentUserUsername: '…' };
// поля формы: customfield_21105, customfield_20809, customfield_20810,
//             customfield_20811, customfield_20812
for (let [key, value] of dataForm) { if (value === '') return; body[key] = value; }
fetch('.../rest/scriptrunner/latest/custom/rateCalculationLogic',
      { method: 'POST', headers: {'Content-Type': 'application/json;charset=utf-8'},
        body: JSON.stringify(body) });
```

Значения полей в теле — **строки** (как их отдаёт форма), не вложенные объекты.

## 2. Точный запрос записи (тело без секретов)

**Запрос, которым установлена ставка 2700 (подтверждён — 200, значение записано):**

```
POST https://jira.simbirsoft.com/rest/scriptrunner/latest/custom/rateCalculationLogic
Cookie: JSESSIONID=<сессия пользователя>
Content-Type: application/json;charset=utf-8

{
  "issueKey": "ANALYTICS-5925",
  "currentUserUsername": "<логин оператора>",
  "customfield_21105": "22412",
  "customfield_20809": "2700",
  "customfield_20810": "20999",
  "customfield_20811": "21001",
  "customfield_20812": "21006"
}
```

`customfield_20809` — строка с числом (в UI поле `type="number" step="0.1"`); остальные — id справочников строками.

**Открытие диалога (для чтения текущей ставки/доступности):**

```
GET /rest/scriptrunner/latest/custom/rateCalculationWindow?issueKey=ANALYTICS-5925
Accept: */*
```

## 3. Справочники полей

| Поле | Имя | Тип | id / формат |
|---|---|---|---|
| `customfield_21105` | Кто предлагает ставку | option (radio) | **22411** = «Клиент», **22412** = «Производство» |
| `customfield_20809` | Планируемая ставка | number (float) | число-строка, напр. `"2700"`, шаг `0.1` |
| `customfield_20810` | Включает НДС | option (radio) | **20999** = «Да», **21000** = «Нет» |
| `customfield_20811` | Валюта | option (select) | **21001** руб., **21004** KZT, **21002** EUR, **21005** USD, **21003** GBR |
| `customfield_20812` | Единица измерения | option (select) | **21006** = «ч (час)» (единственное значение) |

Особенности формы (из HTML диалога):

- radio `customfield_21105` (Клиент / Производство) — **`disabled`**: значение только отображается,
  менять «Кто предлагает ставку» этой формой **нельзя** (совпадает со скриншотом: «Клиент» серое).
- radio `customfield_20810` («Включает НДС») — активно; при выборе «Да» JS автоматически ставит
  валюту `21001` и единицу `21006`.
- `customfield_20809` помечено `required` («Необходимо ввести ставку»), `20811` и `20812` — тоже `required`.

## 4. Где в процессе доступна (статусы)

Кнопка «Ставка» присутствует в HTML карточки и диалог отдаётся (`rateCalculationWindow` → 200) в статусах:

| Статус | Кнопка/диалог | Пример проверки |
|---|---|---|
| Поиск кандидата | **есть** | ANALYTICS-5926, DESIGNER-894, QA-10241, SDET-3375, WEB1C-5075 |
| Кандидат назначен | **есть** | ANALYTICS-5925 (тестовый) |
| Найм | **есть** | ANALYTICS-5606, ANALYTICS-5900 |
| Кандидатов нет | **есть** | ANALYTICS-5910, ANALYTICS-5909 |
| Отказ по кандидату | **есть** | ANALYTICS-5892, ANALYTICS-5906 |

**Зависимости от `customfield_21105`** не обнаружено: кнопка работает независимо от значения
«Кто предлагает ставку» (в тестовой задаче он = «Производство», но доступность от него не зависит;
значение поля менять через эту форму нельзя — оно приходит извне).

**Порядок относительно перехода 21.** Эндпоинт отдаёт 200 и в «Поиск кандидата», и в «Кандидат назначен»,
то есть технически ставку можно записать **до перехода 21, после него или вообще без него**.
Бизнес-правило «ставка вносится при назначении» — это про порядок действий оператора в UI,
а не ограничение Jira. Для приложения: **любой порядок допустим**; логичнее писать ставку
в рамках действия «Назначить» (до или сразу после 21).

## 5. Что выполнено (журнал, ключ `ANALYTICS-5925`)

Одна сессия, пауза ≥ 350 мс, чтение + точечные записи.

| # | Операция | Ответ |
|---|---|---|
| R1 | `GET /issue/ANALYTICS-5925/transitions?expand=transitions.fields&includeUnavailableTransitions=true` | 200, 7 переходов (без «Ставка») |
| R2 | `GET /issue/ANALYTICS-5925/editmeta` | 200, `20809–20812`, `21105` **отсутствуют** |
| R3 | `GET /browse/ANALYTICS-5925` | 200, кнопка «Ставка» → `rateCalculationWindow` |
| R4 | `GET /rest/scriptrunner/latest/custom/rateCalculationWindow?issueKey=…` | 200, HTML диалога |
| W1 | `POST …/rateCalculationLogic` `{21105:22412, 20809:"2700", 20810:20999, 20811:21001, 20812:21006}` | **200**, ставка **2500 → 2700** |
| N1 | пустая ставка (`20809:""`) | **500** `NumberFormatException: empty String` |
| N2 | неверный id валюты (`20811:999999`) | **200**, значение не изменено |
| N3 | неверный id НДС (`20810:888888`) | **200**, значение не изменено |
| N4 | неверный id «кто предлагает» (`21105:777777`) | **200**, значение не изменено |
| N5 | без поля `21105` | **200**, значение не изменено |
| N6 | несуществующий ключ (`ANALYTICS-999999999`) | **500** `NullPointerException: setCustomFieldValue on null object` |
| N7 | замена 2700 → 2600 → 2700 | **200**, замена работает |
| R5 | `GET /issue/ANALYTICS-5925` после | ставка **2700.0**, статус **«Кандидат назначен»** (не изменился) |

**До/после записи:** статус «Кандидат назначен» сохранился, «Профиль сотрудника» = `<ФИО кандидата>`,
исполнитель = `<ФИО оператора>`, «Кто предлагает ставку» = «Производство» — не тронуты.

## 6. Негативные кейсы (коды и тексты Jira)

| Кейс | Ответ Jira | Значение поля |
|---|---|---|
| Пустая ставка при «Производство» | **500** `{"message":"empty String","stack-trace":"java.lang.NumberFormatException: empty String … Script278.groovy:52"}` | не изменено |
| Недоступное/неверное значение валюты (`21003`→валидно; `999999`→нет) | **200** (пустое тело) | **не изменено** — Jira игнорирует невалидный id молча |
| Неверный id «Включает НДС» (`888888`) | **200** | не изменено |
| Неверный id «Кто предлагает ставку» (`777777`) | **200** | не изменено |
| Отсутствует `customfield_21105` в теле | **200** | не изменено |
| Несуществующий ключ | **500** `NullPointerException: Cannot invoke method setCustomFieldValue() on null object` | — |
| Повторная запись (замена) | **200**, значение заменяется | изменено на новое |

**Опасность для интеграции:** на невалидный id справочника и на отсутствие `21105` эндпоинт отвечает
**200 без ошибки, но ничего не пишет**. Приложение должно само валидировать значения по справочнику
(и обязательно передавать `21105`) и **перечитывать** поле после записи, иначе будет считать
неудачную запись успешной.

## 7. Вывод для приложения

1. **Ставку «от производства» записывать через эндпоинт ScriptRunner**, а не через `PUT /issue`
   и не через переход 21/801:
   - чтение текущей/доступности: `GET …/custom/rateCalculationWindow?issueKey=…`;
   - запись: `POST …/custom/rateCalculationLogic` с телом из §2.
2. **Порядок:** можно до/после перехода 21 — ограничений нет. Бизнес-сценарий «при назначении»
   реализуется приложением: писать ставку в рамках действия «Назначить».
3. **Обязательные поля** тела: `issueKey`, `currentUserUsername`, `customfield_21105`,
   `customfield_20809`, `customfield_20810`, `customfield_20811`, `customfield_20812`.
   `customfield_21105` = `22412` («Производство») для ставки от производства.
4. **Валидировать на своей стороне** значения (валюту, НДС, «кто предлагает») и **перечитывать**
   результат: эндпоинт может вернуть 200 без фактической записи.
5. Пустую ставку не отправлять (→ 500). Несуществующий ключ → 500 (классифицировать как ошибку запроса,
   не как «Jira недоступна»).

## 8. Что не удалось / открытые вопросы

1. **Исходный текст скрипта ScriptRunner** (Groovy `Script277`/`Script278`) не виден через REST —
   точные внутренние правила (например, зачем `currentUserUsername`, есть ли серверные проверки)
   не проверены; поведение восстановлено по фактическим запросам/ответам и HTML/JS диалога.
2. **Группы/роли:** доступность проверена под учёткой Константина; видимость кнопки для других ролей
   (например, РН/РО/Presale) не проверялась.
3. **`customfield_21105` нельзя изменить** этой формой (radio `disabled`) — как оно выставляется
   («Клиент»/«Производство»), не выяснено; для ставки от производства ожидаемо «Производство».

## 9. Изменения в коде

ScriptRunner — не часть `JiraClient`, и его добавление в `JiraPort` требует отдельного согласования
