## Что реализовать

### Фильтр статусов (мультивыбор)
- Ряд чипов `.filter` сохраняется: «Все N» + 9 статусов (без «Уволен», он остаётся тумблером). Каждый чип — `button` с `aria-pressed`; нажатие переключает статус независимо от остальных.
- Выбранный чип: заливка `--primary`, белый текст, перед подписью галочка «✓» (выбор не только цветом).
- «Все N» нажат (`aria-pressed=true`), когда не выбран ни один статус; нажатие «Все» снимает все выбранные статусы. Выбор последнего оставшегося чипа снимает выбор, «Все» становится нажатым.
- Снять один или несколько — повторным нажатием на них. Крестиков нет.
- Логика: статусы между собой ИЛИ; статусы, РО, поиск и «Уволенные» — вместе И.
- `nav aria-label="Статусы сотрудников (можно выбрать несколько)"`.
- Состояние фильтров в URL не сохраняется (вне объёма).

### Фильтр «РО»
- Панель `.toolbar` (порядок): «Поиск» -> «РО» -> тумблер «Уволенные». Метки полей видимы над полями (13 px, `--muted`), высота полей 36 px.
- «РО» — `select` шириной 230 px (`max-width:100%`), первое значение «Все» (по умолчанию), затем отображаемые имена из Jira по алфавиту, последним «Без РО» (сотрудники, у которых поле «Руководитель отдела» пусто). «Без РО» показывается всегда, пока список РО загружен; в строке итогов — «РО: Без РО». Длинное имя обрезается многоточием, полное — в `title` поля.
- Выбор другого РО сразу применяет фильтр; возврат к «Все» снимает его.
- Панель при нехватке ширины переносится (`flex-wrap`).

### Строка итогов и сброс
- Под панелью всегда строка: «Показано **N** из M» (M — число сотрудников с учётом «Уволенные», без остальных фильтров; `aria-live="polite"`).
- Если задан хотя бы один фильтр, в той же строке: «статус: **…** · РО: **…** · поиск: **«…»** · **включая уволенных** (все условия сразу)» и ссылка-кнопка «Сбросить фильтры». Сброс: все статусы сняты («Все»), РО «Все», поиск пуст, «Уволенные» выключено.
- Без заданных фильтров видна только «Показано N из M».

### Состояния
- Загрузка списка: «Загрузка…» (`role="status"`, спиннер как в проекте); фильтры доступны.
- Ошибка списка: «Не удалось загрузить сотрудников. Проверьте соединение и обновите страницу.» (`role="alert"`, `--err`).
- Пусто при заданных фильтрах: панель `.empty`: «По выбранным фильтрам сотрудников нет.» + кнопка «Сбросить фильтры». Пусто без фильтров: «Нет данных» (как сейчас).
- РО загружаются: поле отключено, значение «Загрузка…», под панелью «Загружаем список РО…» (`role="status"`).
- Ошибка списка РО: поле отключено, значение «Список недоступен», под панелью красным «Не удалось загрузить список РО. Остальные фильтры работают.» + ссылка «Повторить» (`role="alert"`); остальные фильтры работают.
- Нет РО ни у одного сотрудника: поле отключено, значение «Нет данных», подсказка «В карточках сотрудников не указан руководитель отдела — фильтр недоступен.»
- Длинные имена: ФИО в карточке переносится (`overflow-wrap:anywhere`), имя РО в поле — многоточие; чипы статусов переносятся на следующую строку.

### Клавиатура и доступность
Tab: поиск -> РО -> тумблер -> «Сбросить фильтры»; чипы — перед панелью. Чипы переключаются Enter/Space. Фокус видимый: рамка `--accent` 2 px, смещение 2 px. Контраст — токены проекта, цвет не единственный носитель выбора (галочка).

## Токены и стили
Новых токенов нет: `--primary`, `--accent`, `--panel`, `--panel-2`, `--border`, `--text`, `--muted`, `--err`. Новое — только правило `.filter__item[aria-pressed=true]::before { content:"\2713\00a0" }` и стили строки итогов и подсказок под РО (в прототипе — `.fsum`, `.rohint`).

## Данные и API
- Поле Jira «Руководитель отдела» (customfield_14401, пользователь; в интерфейсе — отображаемое имя): синхронизация, колонка, параметр API и список РО — Arch/Dev по CR-012.
- Фильтрация в прототипе клиентская по загруженному списку; если Dev оставит серверную — результат должен совпасть с правилами выше. Счётчики статусов (подтверждено) считаются по загруженному списку.

## Критерии приёмки UI
1. Можно выбрать несколько статусов; список показывает сотрудников любого из выбранных; повторное нажатие снимает выбор; при нуле выбранных «Все» нажат.
2. «РО» по умолчанию «Все»; выбор имени оставляет сотрудников этого РО; в сочетании со статусами, поиском и «Уволенные» результат — пересечение (И).
3. «Сбросить фильтры» возвращает все четыре фильтра в исходное состояние; ссылка видна только при заданном фильтре.
4. Строка «Показано N из M» совпадает с числом карточек; перечень условий перечисляет только заданные.
5. «Без РО» — последний пункт списка; выбор показывает сотрудников с пустым РО; сочетается с остальными фильтрами по И.
6. Состояния из раздела «Состояния» показаны с указанными текстами; при ошибке списка РО остальные фильтры работают.
7. На 1280 и 1024 фильтры помещаются без наложений и горизонтальной прокрутки (чипы переносятся); обе темы.
8. Очень длинное имя РО не ломает панель (многоточие, полное в `title`).
9. Выбранный чип отличим без цвета (галочка); Tab/Enter/Space работают; фокус виден.

### Что реализовать
- **Чипы статусов — полоса под заголовком страницы, над блоком фильтров**, как на «Сотрудниках»: `.filter` / `.filter__item`, «Все N» + 9 статусов, мультивыбор, галочка у выбранных, `nav aria-label="Статусы сотрудников (можно выбрать несколько)"`. Выпадающий «Статус сотрудника» из блока удаляется.
- **«РО» — выпадающий список на месте бывшего «Статус сотрудника»**: «Все» (по умолчанию), имена РО по алфавиту, последним «Без РО». Сетка блока прежняя (5 колонок на 1280, 3 на 1024).
- **Все фильтры работают мгновенно** (чипы статусов, «Поиск», «РО», «Технологии», «Уволенные»), по аналогии с «Сотрудниками»; для поиска и технологий — по вводу (поиск — с задержкой на усмотрение Dev, около 300 мс). **Кнопка «Применить» убирается.**
- **«Сбросить»** — единственная кнопка блока, на месте бывших «Применить»+«Сбросить» (последняя колонка). Два состояния:
  - **активна**, если применён хотя бы один фильтр блока: «Поиск» не пуст, «РО» не «Все», выбрана хотя бы одна технология, «Уволенные» включено;
  - **неактивна** (`disabled`, непрозрачность 0,5, курсор по умолчанию), если ни один из этих фильтров не применён, а также сразу после нажатия (когда всё сброшено).
  - Hover (активна): рамка `--accent`, фон `--panel`; focus-visible: контур `--accent` 2 px со смещением 2 px (`resumes_filters_reset_hover_*`, `_focus_*`). После нажатия фокус переходит на поле «Поиск» (кнопка стала неактивной).
- **«Сбросить» сбрасывает:** «Поиск» (пусто), «РО» («Все»), «Технологии» (пусто), «Уволенные» (выключено). **Чипы статусов НЕ сбрасываются**, и выбор чипов не делает «Сбросить» активной (кнопка относится только к фильтрам блока).
- Логика: статусы между собой ИЛИ; чипы, поиск, РО, технологии, «Уволенные» — вместе И. Счётчики статусов — с учётом РО и «Уволенные» (как на «Сотрудниках»).

### Блок «Поиск по смыслу (LLM)»: одна строка (подтверждено владельцем, прежнее решение KON-78 п. 7 сохраняется)
- **Поле — одна строка:** `<input type="text">` высотой 36 px (не `textarea`), 3–500 знаков, длинный текст прокручивается внутри поля, placeholder — «Например: аналитик с опытом интеграций 1С и REST, работал в банковской сфере».
- **На одной строке** (`.sa__row`, ряд 36 px, зазор 8 px): поле (занимает всё свободное) -> выпадающий список LLM (провайдер, 240 px; на 1024 при необходимости 200 px) -> кнопка «Найти» (`primary`); после выполненного поиска в том же ряду справа добавляется «Пересчитать». На 1024 ряд остаётся одним (перенос не допускается; сжимается только поле).
- Подпись «Поиск по смыслу (LLM)» с кнопкой «i» над рядом; под рядом мелким серым: слева подсказка/область поиска (может переноситься на вторую строку), справа счётчик «N / 500».
- **Правило области:** область поиска ограничена **всеми** фильтрами выше: чипы статусов, «Поиск», «РО», «Технологии», «Уволенные». Фильтры меняют область **сразу**; сам смысловой поиск запускается отдельным действием («Найти»). В подсказке под рядом выводится текущая область: «Область поиска — все фильтры выше: статусы: … · РО: … · поиск: … · технологии: … Меняется сразу; поиск запускается кнопкой «Найти». Во внешнюю LLM уходит только обезличенный текст». Моя трактовка: смена фильтров не перезапускает LLM-запрос автоматически (иначе лишние вызовы внешней модели); если нужно иначе — вернуться к UX.
- Для Dev/аналитика: параметры области (статусы — список, РО, поиск, технологии, уволенные) передаются в запрос при нажатии «Найти»; уже выведенный результат при смене фильтров остаётся до нового запуска.
- **Расхождение с моим предыдущим макетом (версии 3–4):** там поле было двухстрочным (`textarea` 56 px) с отдельным столбцом справа (список LLM над «Найти»). Это ошибка макета, а не реализации: текущий код (`frontend/src/components/matching/SemanticSearch.tsx`, `styles.css`, `.sa__row`) и решение KON-78 п. 7 (KON-89) уже однострочные, в одном ряду; версия 5 приведена в соответствие. Изменение кода для самого поля не требуется, кроме текста подсказки (область поиска теперь включает «РО», чипы статусов и «Уволенные», слово «Статус сотрудника» заменено на «статусы»).

### Состояния
- РО загружаются: поле отключено («Загрузка…»), «Загружаем список РО…» (`role="status"`).
- Ошибка списка РО: поле отключено («Список недоступен»), «Не удалось загрузить список РО. Остальные фильтры работают.» + «Повторить» (`role="alert"`).
- Нет РО ни у одного сотрудника: поле отключено («Нет данных»), «В карточках сотрудников не указан руководитель отдела — фильтр недоступен.»
- **Пустой результат:** панель `.empty`: «По выбранным фильтрам резюме нет.» + «Измените фильтры, нажмите «Сбросить» (статусы не сбрасываются) или выберите «Все» в статусах.» + кнопка «Все статусы» (подтверждено владельцем; быстрый сброс чипов, так как «Сбросить» их не трогает).
- Длинное имя РО — многоточие в поле, полное в `title`; чипы статусов переносятся.

### Критерии приёмки «Резюме»
1. Полоса чипов между заголовком страницы и блоком фильтров; в блоке нет списка статусов; кнопки «Применить» нет.
2. Каждое изменение чипов, поиска, РО, технологий, «Уволенных» меняет результат сразу, без нажатия кнопки; сочетание — по И (статусы внутри — ИЛИ).
3. «РО»: «Все», имена по алфавиту, «Без РО»; по умолчанию «Все».
4. «Сбросить» неактивна без применённых фильтров блока и после своего нажатия; активна при любом из: поиск, РО, технологии, «Уволенные». Выбор чипов её не активирует.
5. Нажатие «Сбросить» очищает поиск, РО, технологии и «Уволенные»; выбранные чипы статусов остаются выбранными.
6. Поле «Поиск по смыслу» — одна строка 36 px; поле, список LLM и «Найти» (и «Пересчитать» после поиска) расположены в одном ряду на 1280 и 1024 без переноса и горизонтальной прокрутки. Область поиска отражает все фильтры и меняется сразу; поиск запускается только «Найти».
7. Пустой результат — с текстом и действием; состояния РО — с указанными текстами; при ошибке РО остальные фильтры работают.
8. Hover и focus-visible у «Сбросить» видны в обеих темах; 1280 и 1024 — без наложений и горизонтальной прокрутки; обе темы.

### Данные и API (для аналитика/Arch; вне CR-012)
- Backend «Резюме»: параметр статуса станет списком (сейчас одно значение), добавится параметр РО (значение или «Без РО»); то же для области поиска по смыслу.
- Dev не реализует «Резюме» до оформления изменения аналитиком (CR) и появления задач.
