# YouGile-трекер: автоматическое передвижение задач по колонкам

Правило владельца (Константин, 05.11.2026): **агент обязан сам передвигать задачу
в YouGile по колонкам доски «Задачи» проекта REW по мере работы.** Ручное передвижение
владельцем не предусмотрено; задача, «зависшая» не в той колонке, — сбой агента.

> Это платформо-независимый слой правил (`.agents/rules/`): его читают агенты,
> начинающие работу в любом харнессе — OpenCode, Codex и другие. Харнесс-специфичные
> копии/ссылки: `.agents/rules/tasktracker.md` (Claude Code), раздел в корневом
> `AGENTS.md` до программ OpenCode.

## Доска и колонки (project REW, board dd90e28c-b1a4-4b9e-ae81-e6d004de5f62)

| Колонка | columnId | Когда |
|---|---|---|
| Backlog | `fba67ebd-ac85-4c82-8501-6c1e797a1856` | задача в плане, работа не началась |
| In Progress | `e913a187-ed9d-4f92-b0fd-e2c27f982eb3` | работа реально началась |
| In Review | `5e807ed1-4d08-4062-9a8a-9d56e78b20b1` | реализация завершена, ждёт проверки |
| Done | `9fccad5f-1d07-417d-983b-a14371fc0755` | критерии приёмки выполнены и приняты |

## Когда в какую колонку

1. **In Progress** — в момент, когда агент взял задачу и начал хоть что-то делать
   (первое чтение проблемы, планов, кода). Вызов MCP `yougile.manage_tasks` с
   существующим `id` задачи и `columnId` целевой колонки; `color: "primary"`
   (перечень цветов обязателен даже при простом переносе).
2. **In Review** — код готов, локальный QA-гейт прошёл (backend: ruff + pytest;
   frontend: eslint + vitest + build; check_secrets), описание задачи обновлено
   (что сделано / что осталось). Это сигнал QA-агенту.
3. **Done** — только после Pass от QA (или приёмки владельцем для задач без QA).
   Не переносить в Done самовольно, если критерии приёмки не выполнены.
4. Заблокировано извне — вернуть обратно в Backlog с короткой причиной в
   комментарии задачи (`yougile.send_chat_message`).

## Ограничения

- Одновременно **не более одной** задачи в In Progress на одного агента: владелец
  всегда должен видеть, что «сейчас в работе».
- В In Review не копить больше 5; выросшую очередь разобрать (QA/принятие) и
  вернуть реальное состояние.
- На смене In Progress → In Review обновлять описание задачи ( что сделано /
  что осталось) — трекер должен отражать реальность.
- Стикеры/приоритет не менять без поручения владельца.

## Как (MCP yougile)

- Прочитать: `tools.yougile.get_task_data({ id: "REW-N", cursor: "" })`.
- Перенести/обновить: `tools.yougile.manage_tasks({ tasks: [{ id, title: null,
  columnId, description: null, color: "primary", complete: null, archived: null }] })`.
- Не блокирующие уточнения — комментарий в задаче, не чат владельцу.
