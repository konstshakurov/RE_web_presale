### FR-011: Статусы «Кандидатов нет» и «Найм»
**Тип:** functional | **Версия:** 1.3 | Приоритет: Should  
**Owner:** Руководитель направления Аналитики  

Система ДОЛЖНА позволять перевести потребность в статусы «Поиск кандидата», «Найм» и «Кандидатов нет» из столбца «Статус» раздела «Потребности». Вместо кнопок отдельных статусов — кнопка «Изменить ⌄», открывающая выпадающее меню только доступных переходов (FR-026): «Требуется кандидат» → Поиск / Найм / Кандидатов нет; «Поиск кандидата» → Найм / Кандидатов нет; «Кандидатов нет» → Поиск / Найм; «Найм» → Поиск / Кандидатов нет; «Кандидат назначен» → Поиск / Найм / Кандидатов нет. У каждого пункта меню — иконка статуса (эталон — референс владельца 24.11.2026, скрин 4). Для прочих статусов (включая «Отказ по кандидату») кнопки «Изменить» нет; «Кандидат назначен» выставляется только при назначении (FR-008). Меню доступно с клавиатуры: видимый фокус, aria-expanded, открытие/закрытие и выбор пункта без мыши.

При переходе «Кандидатов нет» ДОЛЖНЫ запрашиваться обязательные поля Jira: «Причина отсутствия кандидата» (значения справочника Jira: Нет специалистов данного уровня, но есть слабее; …конкретного набора стека; …нужной отраслевой экспертизой; …нужным специфичным стеком (стек в комментарии); Низкая ставка; Увольнение/декрет кандидата; Требуется очное присутствие; Есть прямой запрос) и «Комментарий» (видимость «для всех»). Для «Поиск кандидата» — подтверждение одним кликом. Для «Найм» (переход «В найм») Jira требует ставку целиком — «Включает НДС», «Валюта», «Единица измерения» (customfield_20810–20812): значения предзаполняются из потребности, при отсутствии запрашиваются; проверка обязательности — до отправки (проба KON-30). Саму ставку («Планируемая ставка», 20809) при найме не вводят: она вносится при назначении (FR-018); значения справочников передаются по id, полученным у Jira. Значения справочника и обязательные поля ДОЛЖНЫ запрашиваться у Jira, а не храниться в приложении (см. FR-026).

**Критерии приёмки:** 1. Для статусов с доступными переходами показывается кнопка «Изменить ⌄»; для статусов без переходов (включая «Отказ по кандидату») кнопки нет.
2. Меню показывает только переходы, которые Jira отдаёт для текущего статуса (FR-026); у каждого пункта — иконка статуса.
3. Выбор пункта ведёт к прежнему поведению: «Кандидатов нет» — обязательные поля Jira; «Поиск кандидата» — подтверждение одним кликом; «Найм» — предзаполнение «Включает НДС»/«Валюта»/«Единица измерения» из потребности.
4. Меню управляется клавиатурой (открытие/закрытие/выбор), aria-expanded корректен, фокус видим.

**CR-история:** CR-005 (approved/Approved); CR-007 (approved_modified/Approved_with_Modification); CR-008 (approved_modified/Approved_with_Modification); CR-022 (approved/Approved)


### FR-034: Таблица потребностей и кнопка синхронизации
**Тип:** functional | **Версия:** 1.0 | Приоритет: Must  
**Owner:** Руководитель направления Аналитики  

Раздел «Потребности» ДОЛЖЕН показывать таблицу со столбцами: «Запрос» (клиент/эпик, название со ссылкой в Jira, ставка, статус, автор, предупреждение о возможном дубле FR-014, раскрываемые комментарии Jira), «Исполнитель», «Требования» (технологии и навыки из поля «Требования к кандидату» и описания; кнопка «Сопоставить ⌄» FR-036), «Кандидаты».

Над таблицей ДОЛЖЕН быть блок фильтров: (1) поиск по ключу и названию с очисткой (X); (2) фильтр дата-диапазона по дате создания потребности — поля «дд.мм.гггг — дд.мм.гггг» с календарём, быстрые кнопки «Сегодня», «7 дней», «30 дней» и «Сбросить даты»; (3) кнопка «Обновить» с иконкой обновления рядом с текстом — принудительная синхронизация, не дожидаясь периодической (FR-028); (4) текст используемого JQL-запроса (только чтение, редактируется в «Настройках»). Дата-фильтр комбинируется с фильтром групп статусов (FR-035) и поиском по И; «Сбросить даты» очищает диапазон и снимает ограничение. Фильтрация выполняется по дате создания потребности в кэше, на стороне API/кэша.

Система ДОЛЖНА показывать время последней синхронизации и количество потребностей. В столбце «Ставка» значение вида «2 240 RUB» показывается в одну строку без переноса, уменьшенным шрифтом (токены — FR-038 v1.3); при отсутствии значения — «—» (вместо «не указана»). Технологии и навыки выделяются из требований при синхронизации (кэш), показывается и исходный текст. Добавление комментария к потребности из приложения — этап 2.

Примечание (CR-022): кнопку принудительной синхронизации в реализации уже ведут как «Обновить»; формулировка v1.0 называла её «Синхронизировать» — приведено в соответствие.

**Критерии приёмки:** 1. Дата-диапазон фильтрует таблицу по дате создания потребности; «Сегодня»/«7 дней»/«30 дней» заполняют диапазон; «Сбросить даты» очищает поля и снимает ограничение.
2. Дата-фильтр комбинируется с группой статусов (FR-035) и поиском по И.
3. Поле поиска очищается крестиком (X).
4. В столбце «Ставка» значение в одну строку («2 240 RUB» без переноса, уменьшенный шрифт); при отсутствии — «—».
5. «Обновить» с иконкой обновления запускает принудительную синхронизацию; штамп времени последней синхронизации и счётчик потребностей сохраняются.

**CR-история:** CR-022 (approved/Approved)


### FR-035: Фильтр потребностей по группам статусов
**Тип:** functional | **Версия:** 1.0 | Приоритет: Must  
**Owner:** Руководитель направления Аналитики  

Раздел «Потребности» ДОЛЖЕН предоставлять фильтр по группам статусов в один клик (чипы над таблицей, у каждой — счётчик потребностей). Группы по умолчанию (статусы workflow Jira типа «Аналитик»): «Без кандидата» — Требуется кандидат, Поиск кандидата, Найм, Отказ по кандидату, Интервью не пройдено; «Кандидат назначен» — Кандидат назначен; «Интервью» — Подготовка к интервью, Интервью состоялось, Интервью пройдено, Интервью не пройдено; «Закреплён» — Закреплен за проектом. Статус может входить в несколько групп («Интервью не пройдено» входит в две). Статусы вне перечисленных групп (Кандидатов нет, Поиск партнерки, Партнерка, На проекте, Скоро освобождается, Работа завершена, Не на проекте, Неактуально, Отложено) доступны через группу «Прочие» и режим «Все статусы». Стартовая группа — «Без кандидата». Состав групп хранится в «Настройках» и меняется администратором без правки кода; выбор фильтра запоминается для пользователя. Названия статусов берутся из Jira как есть.

Чипы групп ДОЛЖНЫ отображаться в стиле референса владельца (24.11.2026, пункт 3.1): цвета пилюль ярче текущих (токены — FR-038 v1.3, design/KON-166); смысл не передаётся только цветом, подписи чипов сохраняются. Если в составе групп есть группа «Субподряд», её чип ДОЛЖЕН отображаться сокращённо «Суб»; название группы в «Настройках» не меняется.

**Критерии приёмки:** 1. Клик по чипу группы сразу оставляет в таблице потребности только с её статусами.
2. Счётчик группы равен числу потребностей в ней.
3. Чипы отображаются цветами по референсу (ярче); подписи сохраняются, смысл не передаётся только цветом.
4. Чип группы «Субподряд» показан как «Суб»; название группы в «Настройках» остаётся «Субподряд».
5. Стартовая группа «Без кандидата», запоминание выбора и «Прочие»/«Все статусы» — как в v1.0.

**CR-история:** CR-022 (approved/Approved)


### FR-036: Сопоставление потребности с кандидатами (статус кандидата цветным чипом)
**Тип:** functional | **Версия:** 1.2 | Приоритет: Must  
**Owner:** Руководитель направления Аналитики  

По кнопке «Сопоставить ⌄» в столбце «Требования» система ДОЛЖНА запустить сопоставление (FR-005) и показать в столбце «Кандидаты» список подходящих сотрудников, отсортированный по убыванию % совпадения. Кнопка отображается с шевроном ⌄ на одной линии с текстом; в активном (раскрытом) состоянии шеврон меняется на ⌃ (пункты 3.7–3.8 референса владельца 24.11.2026). Раскрывающееся поведение кнопки и состав элементов столбца «Кандидаты» — по решению UI design/KON-166; логика сопоставления, кэш результата и правила объективности не меняются.

Для каждого кандидата показываются: ФИО, статус сотрудника, % совпадения (цветовая шкала), значок заметки (FR-033), кнопки «Резюме» (открыть Основное CV, FR-037) и «Назначить» (FR-008). Первоначально показываются 10 лучших, остальные — по «Показать ещё». Подсказка с обоснованием оценки показывается по клику на %. Повторное открытие потребности показывает сохранённый результат с датой расчёта и кнопкой «Пересчитать». Если подходящих нет — сообщение; пользователь может перейти к смене статуса «Кандидатов нет» (FR-011).

### Правила объективности вывода (v1.1, CR-019)

1. **Только по требованиям потребности:** критерии и формулировки — из текста потребности (описание, требования, поля Jira) и заметки о сотруднике (FR-033). Модель НЕ привносит собственные пороги и знания о грейдах (уровни «Senior» и прочее); требование не сформулировано явно в потребности — не учитывается ни в проценте, ни в обосновании, ни в «чего не хватает».
2. **Формулировка нехватки — «в CV не указан/не упомянут X»:** «нет опыта X», «отсутствует опыт X», «нет упоминания X» — запрещены (не-упоминание в CV ≠ отсутствие опыта).
3. **Согласованность вывода:** percent < 100 ⟺ в gaps перечислены причины; каждый пункт gaps — причина снижения процента; формулировки вида «полностью закрывает требования» при percent < 100 — запрещены.
4. **Без модальностей домысла:** «может считаться», «может не соответствовать», «ожидаемый уровень» — запрещены.
5. **Пост-обработка (защитный слой):** нормализация формулировок (п. 2–3) и отсечение модальностей (п. 4) реализуются в коде приложения и покрыты unit-тестами.
6. **Golden-кейсы:** фиксированные пары «CV + потребность» — для регрессии при смене промптов/моделей (правила от смены модели не меняются).

**Критерии приёмки:** 1. Кнопка сопоставления отображается «Сопоставить ⌄»; шеврон и текст на одной линии.
2. В активном (раскрытом) состоянии шеврон — ⌃.
3. Запуск сопоставления (FR-005), сортировка по %, «Показать ещё», кэш результата с датой расчёта и правила объективности v1.1 — без изменений.

**CR-история:** CR-014 (approved/Approved); CR-022 (approved/Approved)


### FR-038: Логотип и фирменный вид интерфейса (светлая тема А2, цветные статус-чипы)
**Тип:** functional | **Версия:** 1.2 | Приоритет: Could  
**Owner:** Руководитель направления Аналитики  

Система ДОЛЖНА показывать логотип «regoose» (исходник design/KON-78/logo/logo_B_CandaraLight.png; в шапке — два ассета logo_head.svg и logo_wordmark.svg по design/KON-135; фавикон favicon_dark_256.png) в шапке каждой страницы и на странице входа; на форме входа логотип не меняется. Общий вид и расположение элементов ДОЛЖНЫ ориентироваться на референсы из input/Референсы (тёмная верхняя панель с разделами, таблицы со столбцами и кнопками действий, модальные окна).

Светлая тема ДОЛЖНА использовать палитру А2 по design/KON-149/decision.md (утверждена 29.10.2026; заменяет вариант 4 KON-142 и палитру CR-015): токены --bg, --accent, --primary, --nav и производные; значения — в решении KON-149. Статусы сотрудников и кандидатов ДОЛЖНЫ показываться цветными пастельными чипами: карта «статус → тип» (ok/info/err/warn/neu) в frontend/src/lib/statusTone.ts; наведённая и выбранная строки таблиц ДОЛЖНЫ заливаться (--row-hover, --row-sel) с левой полосой 3 px; вторичные кнопки — в новый акцент. Тёмная тема НЕ ДОЛЖНА меняться.

Раздел «Потребности» (CR-022, референсы владельца 24.11.2026): радиусы всех кнопок, тип, уменьшенный размер и цвета шрифтов, цвета пилюль (чипов) — ярче нынешних — в точности по референсу; у кнопки «Обновить» — иконка обновления рядом с текстом; радиусы углов контейнера таблицы по референсу; высота строки заголовков таблицы уменьшена на 20% относительно текущей; ссылки-действия отображаются с шевронами на одной линии с текстом — «Правила ⌄» (FR-015), «N кандидатов ⌄», «Сопоставить ⌄» (FR-036); активное состояние шеврона — ⌃; подпись «Субподряд» — «Суб» (FR-035). Кебаб-меню из референса НЕ реализуется (решение владельца, пункт 3.11). Значения новых токенов — design/KON-166/decision.md после апрува владельца.

**Критерии приёмки:** 1. В шапке каждой страницы — логотип из двух ассетов; на странице входа — логотип без меню; фавикон установлен.
2. Светлая тема использует токены палитры А2 из design/KON-149 (фон, акценты, навигация).
3. Статусы отображаются цветными чипами по карте statusTone.ts; выбор не передаётся только цветом (текст сохраняется).
4. Наведённая и выбранная строки таблиц заливаются с левой полосой 3 px.
5. Вторичные кнопки выполнены в новом акценте.
6. Тёмная тема не изменилась; переключение тем работает внизу страниц.
7. Кнопки и чипы раздела «Потребности» соответствуют референсу по радиусам, шрифтам и цветам (ярче нынешних).
8. «Обновить» — с иконкой обновления рядом с текстом; строка заголовков таблицы ниже на 20% относительно текущей; контейнер таблицы со скруглением по референсу.
9. «Правила ⌄», «N кандидатов ⌄», «Сопоставить ⌄» — шеврон на одной линии с текстом; активное состояние — ⌃. Кебаб-меню отсутствует.
