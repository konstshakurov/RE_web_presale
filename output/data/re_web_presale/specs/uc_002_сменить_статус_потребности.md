## Общая информация

| Атрибут | Значение |
|---------|----------|
| Актор (primary) | РН / РО / Presale-менеджер |
| Акторы (secondary) | Jira |
| Предусловие | Пользователь авторизован в Jira; потребность открыта. |
| Постусловие | Статус потребности в Jira изменён; в кэше приложения обновлён. |
| Триггер | Пользователь нажимает кнопку статуса («Поиск», «Найм», «Кандидатов нет») в столбце «Статус». |

## Основной сценарий (Happy Path)

1. Система показывает в столбце «Статус» кнопки «Поиск», «Найм», «Кандидатов нет» по текущему статусу потребности и переходам, которые отдаёт Jira (FR-026, FR-011).
2. Пользователь нажимает кнопку.
3. Для «Поиск» система запрашивает подтверждение; для «Найм» — подтверждение и поля ставки (Включает НДС, Валюта, Единица), предзаполненные из потребности и обязательные по Jira.
4. Система отправляет переход в Jira от имени пользователя.
5. Система перечитывает потребность и обновляет статус и кнопки.

## Альтернативные сценарии

3а. Для «Кандидатов нет» пользователь выбирает причину из справочника Jira и вводит комментарий (обязательны, FR-011).

## Сценарии исключений

4а. Jira отказала (403 и др.) — система показывает причину как есть, введённые данные сохраняются.
4б. Сессия Jira истекла — повторный ввод пароля в том же окне, данные сохраняются (UC-005).

## Бизнес-правила и ограничения

BR-001, BR-008.
