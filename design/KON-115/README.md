# KON-115 (Pre.UX-7) — редактор заметки: варианты и рекомендация

Статус: **approved, вариант B (21.10.2026) — см. `decision.md`**; ниже — исходное сравнение (архив). Бриф, допущения и общее поведение — `brief.md`.

Прототипы (двойным кликом, без внешних загрузок; переключатели темы и ответа сервера — в чёрной панели сверху):
`variant_a.html`, `variant_b.html`, `variant_c.html`. Нажмите «Изменить» в любой строке; в панели можно выбрать «ошибка 503 / 404 / без ответа». Строки: с короткой заметкой, пустая (две), с длинной (~700 знаков).

## Варианты

| | A. На месте, в ячейке | B. Модальное окно | C. Боковая панель |
|---|---|---|---|
| Суть | Заметка в ячейке превращается в поле с кнопками; строка растёт | Окно по центру 560 px: заголовок «Заметка: ФИО», поле на 10 строк, футер с кнопками | Панель справа 420 px: ФИО, статус, описание, дата последнего изменения + поле; таблица остаётся видна |
| Поле | ~228 px на 1024, 6 строк | ~510 px, 10 строк | ~370 px, тянется на высоту панели |
| Счётчик/ошибка | под полем, в узкой колонке переносятся | под полем, в одну строку | под полем |
| Контекст | вся таблица на виду, видна строка | таблица затемнена, ФИО в заголовке, автор/дата в подзаголовке | таблица видна слева, в панели ФИО, статус, описание |
| Очистка | «Очистить» над кнопками -> «Очистить заметку» | «Очистить» слева в футере -> «Очистить заметку» | то же, что B |
| Прочие «Изменить» | disabled, пока одна строка редактируется | недоступны (окно модальное) | недоступны (панель модальная) |

Скриншоты: `variant_<a|b|c>_<состояние>_<dark|light>_1280.png`, для `edit`, `over`, `error`, `long` также `_1024`.
Состояния: `edit` (редактирование), `empty` (пусто), `long` (длинная заметка ~700 знаков), `limit` (1962 из 2000), `over` (2134 — превышение), `clear` (поле очищено, кнопка «Очистить заметку»), `saving` (сохранение), `error` (ошибка сохранения, введённое на месте), `saved` (после сохранения: автор, дата, «Сохранено»), `cleared` («Заметка очищена», «нет заметки»).

### A. На месте
- Плюсы: самый короткий путь (без перекрытия экрана), сохраняет контекст строки (файлы, описание рядом).
- Минусы: поле ~228 px на 1024 — 2000 знаков это ~45 строк, читать и править неудобно (резиновый `textarea` с прокруткой); строка прыгает по высоте, соседние строки уезжают; подсказка о сопоставлении не помещается (убрана); кнопки в узкой колонке в два ряда; нужен контроль «одна строка редактируется одновременно».
- Цена для Dev: низкая-средняя — нет нового контейнера, но состояние «строка в режиме правки» в таблице, управление disabled у остальных, перерисовка высоты.

### B. Модальное окно
- Плюсы: комфортное поле при любой ширине и любой длине заметки; единая раскладка заголовок / тело / футер, уже есть в приложении (окно просмотра CV, `.modal.pm`) — паттерн знаком; естественные места для автора/даты, счётчика и ошибки; фокус и Esc привычны.
- Минусы: перекрывает таблицу (нельзя подглядеть в соседние данные пока пишешь — для заметки это редко нужно); на 1–2 слова «Изменить» открывает окно — на один шаг тяжелее, чем A.
- Цена для Dev: низкая — переиспользует существующие стили/фокус-ловушку окна; один компонент `NoteDialog`.

### C. Боковая панель
- Плюсы: контекст сотрудника рядом (описание, статус, автор/дата), таблица остаётся видна; просторное поле.
- Минусы: **в приложении нет такого компонента** — новая механика (анимация/фокус-ловушка/закрытие), другого такого места нет, для единственной формы избыточно; панель 420 px закрывает столбцы «Описание/Заметка» на 1024 — «таблица рядом» работает хуже, чем кажется.
- Цена для Dev: средняя-высокая — новый компонент панели, стили, тесты поведения.

## Рекомендация: B (модальное окно)
Причины: заметка до 2000 знаков — это текст, ему нужна широкая область (в A на 1024 всего 228 px); окно уже знакомо пользователям и разработке (CV, «Наим»), не добавляет нового паттерна и токенов; все состояния (счётчик, ошибка «как есть», сохранение, автор/дата) естественно укладываются. A остаётся запасным, если владельцу важнее скорость правки коротких заметок («Готов к командировкам») — тогда стоит принять, что длинные правятся тесно. C не рекомендую: цена выше, а выгода (контекст сотрудника) для этой задачи мала.

## Решения, которые понадобятся от владельца (кроме выбора варианта)
1. Автор показывается логином (`ivanova`), как отдаёт API, — принять? Альтернатива — ФИО, но это сопоставление на сервере (вне UX-задачи).
2. Подсказка «Учитывается при сопоставлении с потребностью» — оставить (по FR-005) или убрать.
3. Очистка двухшаговая (стереть -> «Очистить заметку») без диалога подтверждения — достаточно?
4. Подпись кнопки для пустой заметки остаётся «Изменить» (как в утверждённом KON-78) — не менять на «Добавить».

## Тексты интерфейса (общие)
Заголовок окна/панели: «Заметка: <ФИО>» (B), «<ФИО>» (C); метка поля «Заметка»; плейсхолдер «Например: ограничения по проектам или командировкам»; подсказка «Учитывается при сопоставлении с потребностью»; счётчик «N / 2000»; превышение «Сократите текст на N знак/знака/знаков»; кнопки «Сохранить», «Отмена», «Очистить», «Очистить заметку»; процесс «Сохраняем…»; успех «Сохранено», «Заметка очищена»; подпись «Изменена: <логин>, <дата>» (B); ошибки — текст ответа сервера как есть.

## Доступность и проверки
- Поле с `<label>` (B, C) или `aria-label="Заметка: <ФИО>"` (A); счётчик `aria-live="polite"`; ошибка `role="alert"`; «Сохраняем…» `role="status"`; окно/панель `role="dialog" aria-modal="true"` с `aria-labelledby`; фокус при открытии — в поле (курсор в конец), при закрытии — на «Изменить» строки.
- Закрытие щелчком по подложке — только если текст не менялся и сохранения нет.
- Контрасты: используются утверждённые токены; предупреждение у счётчика (от 1900 знаков) сделано жирным `--text`, а не `--warn`, чтобы не опираться на цвет с контрастом ниже 4.5:1 в светлой теме. Фактические контрасты проверить Dev по `design/KON-78/decision.md`, раздел 3.
- Прототип использует упрощённую шапку и вымышленные данные.
