## Общая информация

| Атрибут | Значение |
|---------|----------|
| Актор (primary) | РН / РО / Presale-менеджер |
| Акторы (secondary) | LDAP, Jira |
| Предусловие | Учётная запись пользователя добавлена администратором в список доступа. |
| Постусловие | Создана сессия приложения; в системе есть зашифрованный сессионный токен Jira пользователя (при отказе Jira — статус отказа, запись в Jira заблокирована). |
| Триггер | Пользователь открывает приложение. |

## Основной сценарий (Happy Path)

1. Пользователь вводит корпоративный логин и пароль.
2. Система проверяет их в LDAP и наличие в списке доступа.
3. Система создаёт сессию приложения.
4. Тем же вводом пароля система создаёт сессию Jira (пароль живёт только в памяти запроса и не сохраняется).
5. Система сохраняет зашифрованный сессионный токен Jira.

## Альтернативные сценарии

4а. Пользователь уже входил ранее — при каждом входе сессия Jira создаётся заново, прежний токен заменяется.

## Сценарии исключений

2а. Пользователя нет в списке — вход отклонён, даже если LDAP-вход успешен.
4б. Jira отказала при верных данных LDAP (неверный пароль в Jira, блокировка входа, недоступность) — вход в приложение выполнен, чтение кэша доступно, запись в Jira заблокирована с текстом отказа; при недоступности Jira прежний токен сохраняется.
5а. Сессия Jira истекла во время работы (401) — система запрашивает пароль повторно, введённые данные не теряются; после ввода пароля прерванная операция продолжается с невыполненных шагов.
