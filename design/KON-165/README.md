# KON-165 — сравнение вариантов (FR-014, предупреждение о дубле)

Задача: [BF-10] Pre.UX-15 (REW-39) · Бриф: `brief.md` · Дата: 24.11.2026

| | **A — значок + раскрытие в строке** (`variant_a_row_disclosure.html`) | **B — значок + модальное окно** (`variant_b_modal.html`) |
|---|---|---|
| Идея | Предупреждение — значок ⚠ с числом дублей у названия; клик раскрывает список дублей блоком под строкой таблицы | Тот же значок; клик открывает модальное окно со списком дублей |
| Плюсы | Контекст не теряется: дули видны рядом со строкой; согласовано с раскрытием строки (ClientRules, кандидаты); клавиатура — кнопка в ячейке, `aria-expanded` | Много места для длинных названий и 5+ дублей (скролл внутри окна); строка таблицы не растёт; паттерн уже есть (Modal, AssignDialog, RosDialog) |
| Минусы | Длинные списки удлиняют таблицу; при раскрытой строке (правила клиента) два блока подряд — больше прокрутки | Перекрывает таблицу — сравнивать «дубль vs оригинал» приходится по памяти; лишний слой поверх раскрытой строки |
| Цена для Dev | Небольшая: список `duplicates` в `NeedOut` + блок-раскрытие; переиспользует `.pct`/`statusTone` | Небольшая: те же данные + существующий `Modal.tsx`; состояние фокуса в модалке (trap) |
| Кому подходит | Кто работает с таблицей как с доск: раскрыл — посмотрел — сравнил в одном экране | Кто держит таблицу компактной и не любит «прыгающие» высоты строк |

## Рекомендация: **вариант A**

Дубли нужно **сравнивать с оригиналом** — раскрытие показывает их рядом со строкой, без
перекрытия таблицы, и согласовано с существующим взаимодействием строки (правила клиента,
кандидаты уже раскрываются там же). Модалка B — запасной вариант, если список дублей станет
богаче (фильтры, сортировка) — сейчас этого в требовании нет.

## Открытые вопросы
1. Данные: отдаём дубли полем `duplicates` в `GET /sync/needs` (допущение брифа) или отдельным
   эндпоинтом `GET /sync/needs/{key}/duplicates` по клику — решит Dev на постановке.
2. Хронология: в списке дублей нужна ли дата создания потребности-дубля (сейчас: ключ, название,
   статус, %)?
3. Порог 15% и окно 2 недели — код/конфигурация, в UI не выносятся (вне объёма).
