# KON-98 (Pre.UX-5) — «Назначить» без ставки, ставка в диалоге «Найм»: варианты

Прототипы (состояния переключаются ссылками в чёрной полосе; тема — `?t=dark|light`): `variant_a.html`, `variant_b.html`, `variant_c.html`.
PNG: `variant_<a|b|c>_<состояние>_<dark|light>_1280.png`; ключевые состояния (`assign`, `confirm`, `hire`, `hire_req`, `hire_refused`, B: `done`) — ещё `_1024`.

## Общее для всех вариантов (решение не зависит от выбора)
- **Окно «Назначить»:** поле ставки убрано; остаются «Резюме», «Комментарий», «Файлы», «CV по шаблону клиента…». Под контекстной строкой — одна подсказка (`.note`, синяя полоса слева): «Ставка здесь не вводится: её указывают при переводе в «Найм»…»; для потребностей «от производства» добавлено «при найме она будет обязательной». Подтверждение: строка «Ставка» убрана, добавлен блок «Ставка не передаётся». Прогресс: шаг «Профиль сотрудника, исполнитель» (без «ставка»).
- **Диалог «Найм»:** состояния «Запрашиваем доступные действия в Jira…» → форма → «Переводим…» → успех (окно закрывается, список перечитывается); «Действие недоступно» (KON-96); отказ Jira как есть, введённое сохранено, «Повторить»; истёкшая сессия — пароль в том же окне.
- **Поля:** «Планируемая ставка» (число; `*` и ошибка «Укажите планируемую ставку…» при «от производства», иначе необязательно); «Валюта», «Единица измерения», «Включает НДС» (все обязательны в Jira, предзаполнены из потребности; без предзаполнения — «Выберите…» и ошибка до отправки).
- **Ориентир** следует за выбранными валютой и единицей, подписан «только справка», не подставляется в поле и не блокирует перевод; состояния: загрузка, ошибка с «Повторить», «ориентира нет», «появится после выбора валюты и единицы».

## Рекомендация UX: вариант A
Назначение и найм — разные моменты процесса (Jira даёт ставку только на «В найм», который идёт после согласования с клиентом), поэтому навязывать «Найм» сразу после назначения (B) — лишний экран на частом действии. Вариант C полезен, но выбор периода — расширение и для API, и для Dev; единственная строка ориентира в A закрывает FR-018. Оси независимы: A можно усилить позднее — добавить экран «Назначено» (B) или справку (C) отдельным небольшим изменением, не переделывая остальное.

Что я взял из B: подсказка в «Назначить» ведёт к ссылке «Найм» (по месту, без нового экрана).

## Вопросы владельцу
1. Подтверждаете A (рекомендация)? Или нужна кнопка «Перейти к найму…» после назначения (B)?
2. Поля «Валюта», «Включает НДС» — редактируемые списки (допущение, согласно FR-011) или зафиксировать «рубли, с НДС» по FR-018? Это противоречие в требованиях; при выборе «зафиксировать» — CR к аналитику.
3. Планируемая ставка при «от клиента» — необязательна (по FR-018); оставляем без подсказки о ставке клиента как предзаполнении?
4. KON-95 («Ориентир ставки в окне „Назначить“») — перепривязать к диалогу «Найм» и добавить параметры валюта/единица (задача для Arch)?
5. Состояния обхода CR-006 («Назначить», ошибка возврата «Нужно предоставить CV») — спроектировать отдельным пунктом?
