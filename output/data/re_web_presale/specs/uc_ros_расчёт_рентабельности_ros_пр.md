## Основной сценарий (Happy Path)

Пользователь нажимает «ROS» в строке потребности.
Система открывает модальное окно «ROS специалиста» (потребность - клиент - ставка).
Ставка для расчёта: задана клиентом - read-only из потребности; иначе - поле ввода (руб. с НДС за час).
ЗП кандидата, гросс - ввод вручную.
Автопересчёт при вводе (до 0,3 с): выручка (165 ч x ставка), взносы (до/после лимита ФОТ), НДС, налог на прибыль, ROS.
Показ двух значений ROS: до лимита ФОТ (крупнее) и после лимита; месяц перехода по лимиту ЗП (22/23-й при 130 000); таблица промежуточных расчётов (выручка, взносы, прямые расходы, косвенные, налог, прибыль).
Закрытие (Отмена/x/Esc) - данные не сохраняются.

## Альтернативные сценарии

4а. Ставка потребности задана в валюте/единице, отличной от руб. с НДС за час, - окно показывает её справочно и активирует ручной ввод ставки (приведение как в 4.3 не выполняется автоматически).

## Сценарии исключений

5а. Введено ЗП <= 0 или не число - сообщение «Введите ЗП числом больше нуля», пересчёт заблокирован.
5б. Ставка <= 0 в поле ручного ввода - «Введите ставку числом больше нуля».
5в. Ставка > 1 000 000 - «Ставка не может превышать 1 000 000» (как у поля ставки при назначении).

## Бизнес-правила и ограничения

Модель ROS: input/ROS/ROS_model_v2.xlsx (лист v2, 165 billable-часов). «Лист1» (145 ч) — устаревшее, не используется.
Ввод ЗП и результат не сохраняются и не пишутся в логи (конфиденциальные данные, политика FR-017).
Кнопка «ROS» видна только в статусах матрицы status_actions, где доступно действие кандидата (FR-039 п. 3).
