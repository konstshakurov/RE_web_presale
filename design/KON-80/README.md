## Сравнение

| Критерий | A — «Мастер из 2 шагов» | B — «Одно окно» |
|---|---|---|
| Генерация без подтверждения невозможна | да: чекбоксы + кнопка «Сгенерировать» на шаге 1 | да, но чекбоксы на длинной форме — легче промахнуться |
| Внимание к повтору по паре | предупреждение прямо над подтверждением (первый экран) | предупреждение сверху длинного окна — проще проскроллить |
| Читаемость результата | отдельный экран: CV слева, рекомендации + письмо справа; скролл только внутри колонок | тот же макет, но ниже длинной формы; общий скролл |
| Согласованность с окном «Назначить» | то же окно `--wide`, футер с основным действием | то же окно |
| Скорость | +1 клик («Сгенерировать» на 1-м шаге) | кнопка одна |
| Состояния (прогресс/ошибка LLM) | отдельный шаг — статус «шаг 2 из 3» виден, Esc/закрытие закта нет | состояния вставляются в ту же форму — заметнее, но длиннее |

(закрытие окна во время отправки недоступно в обоих вариантах.)

## Рекомендация

**Вариант A (мастер из 2 шагов).** Причины: повтор по паре (BR-007) и подтверждение
двух файлов — главный риск задачи (критерий «без подтверждения генерация не стартует»);
в A они собраны на первом экране компактно, а результат получает собственный экран,
не конкурируя с формой. «Лишний клик» — минимальная цена.

После апрува:
1. `decision.md` (points для Dev: состав окон, текста, поведение чекбоксов и кнопки
   публикации, состояния повтор/ошибка/прогресс; API: KON-43/Dev-14).
2. Dev: `frontend` (диалог в окне «Назначить»), QA — по критериям из `brief.md`
   (обе темы, 1280/1024, высота окна 400px, Tab/Esc — закрытие запрещено только во время генерации).
