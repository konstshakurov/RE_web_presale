# KON-79 «Назначить» и смена статуса — решение по UI

Статус: **proposed (ждёт апрува владельца)** | дата: 15.10.2026 | утвердил: —
Предложенный вариант: **A — одно окно «Назначить» + диалог смены статуса** (рекомендация UX, см. `README.md`).

> Dev (KON-44) не стартует до статуса `approved` и комментария в Linear (`.claude/rules/ui_workflow.md`). После выбора владельца этот файл обновляется: статус, выбранный вариант, поправки, ответы на открытые вопросы.

## Что реализовать (в рамке варианта A; уточняется после апрува)
- Чип статуса потребности — кнопка «<статус> ▾», открывает диалог «Сменить статус потребности».
- Окно «Назначить кандидата» (`Modal wide`): контекстная строка, «Резюме» (select), «Ставка, руб. с НДС» (обязательна при «от производства»), «Комментарий», «Файлы» (чекбоксы), «CV по шаблону клиента…» (secondary). Основное действие «Назначить…» → экран подтверждения (сводка) → «Подтвердить и отправить в Jira».
- Прогресс отправки по этапам; отказ Jira (текст как есть, введённое сохранено, «Повторить»); истёкшая сессия (пароль Jira в окне, данные сохранены).
- Диалог смены статуса: переходы из Jira; обязательные поля перехода (для «Кандидатов нет» — «Причина отсутствия кандидата», «Комментарий»); отказ Jira как есть.

## Токены и стили
Существующие токены; secondary — `--secondary`, основная кнопка `--primary`; новых токенов нет.

## Данные и API (KON-43)
Назначение; допустимые переходы с полями; повторная авторизация Jira. Нет метода — состояние показывает «недоступно» (допущение).

## Критерии приёмки UI
Будут зафиксированы после выбора варианта (проверяемые «при …, на экране …» для Dev и QA; обе темы, 1280/1024, высота 400px; состояния — список в `README.md`).

## Вне объёма
CV по шаблону (KON-80), закрепление баннера Jira, массовое назначение.
