## Общая информация

| Атрибут | Значение |
|---------|----------|
| Актор (primary) | РН / РО / Presale-менеджер |
| Акторы (secondary) | LDAP, Jira |
| Предусловие | Учётная запись пользователя добавлена администратором в список доступа. |
| Постусловие | Создана сессия; в системе есть зашифрованный access token пользователя в Jira. |
| Триггер | Пользователь открывает приложение. |

## Основной сценарий (Happy Path)

1. Пользователь вводит корпоративный логин и пароль.
2. Система проверяет их в LDAP и наличие в списке доступа.
3. Система создаёт сессию (пароль не сохраняется).
4. При первом входе система перенаправляет пользователя в Jira для разрешения доступа (OAuth 1.0a).
5. Пользователь разрешает доступ.
6. Система сохраняет зашифрованный токен.

## Альтернативные сценарии

4а. Токен уже есть — шаги 4–6 пропускаются.

## Сценарии исключений

2а. Пользователя нет в списке — вход отклонён, даже если LDAP-вход успешен.
5а. Пользователь отказал в доступе — разделы чтения доступны, запись в Jira недоступна.
6а. Токен отозван (401) — система повторно запрашивает авторизацию.
