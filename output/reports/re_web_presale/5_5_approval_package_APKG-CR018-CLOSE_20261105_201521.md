### FR-041: Расчёт рентабельности (ROS) при подключении кандидата на потребность
**Тип:** functional | **Версия:** 1.0 | Приоритет: Low
**Owner:** Константин Шакуров (РН Аналитики)
**Источник:** output/reports/re_web_presale/4_3_confirmed_result_20261001_115657.md; input/ROS/ROS_model_v2.xlsx; YouGile REW-10 (KON-121)

Система ДОЛЖНА в списке «Потребности» в столбце «Кандидаты» отображать кнопку «ROS» (контурная, под кнопкой «Сопоставить», placement — input/screenshots/ros_button_placement.png) и по клику открывать модальное окно «ROS специалиста»: ввод уровня ЗП кандидата в гросс (ФОТ с НДФЛ); рентабельность пересчитывается автоматически при вводе (без кнопки «Рассчитать», отклик ≤ 0,3 с). Ставка для расчёта: задана клиентом — read-only из потребности; не задана / «от производства» — поле ввода (руб. с НДС за час, > 0, ≤ 1 000 000); валюта/единица не руб./час — ручной ввод, значение потребности справочно; «без НДС» приводится к «с НДС» автоматически (× НДС-параметр из Настроек). Модель (ROS_model_v2, лист v2, 165 billable-часов; «Лист1» 145 ч — устаревший): НДС 22% (доход = выручка/122×22), взносы 15,2% до лимита / 7,8% после лимита ФОТ 2 979 000, косвенные 53 000 на человека, налог на прибыль 5% только с прибыли > 0. ROS = Прибыль / Выручка × 100%. Показываются ДВА значения ROS («до лимита» — основное, крупнее), месяц перехода N = ОКРУГЛВНИЗ(Лимит ФОТ / ЗП, 0) — «после» с N+1-го. Параметры модели — в «Настройках» (роль Админ). Введённая ЗП и результат НЕ сохраняются (БД, Jira, логи).

**CR-история:** CR-018 (approved — решение владельца «апрув», 05.11.2026)

### UC-ROS: Расчёт рентабельности (ROS) при подключении кандидата
**Тип:** use case | **Версия:** 1.0 | Приоритет: Low
**Owner:** Константин Шакуров (РН Аналитики)
**Источник:** YouGile REW-10; input/screenshots/ros_button_placement.png; FR-041

Актор (primary): РН/РО/Presale-менеджер. Предусловие: пользователь на странице «Потребности», потребность в статусе, где доступны действия кандидата (матрица status_actions, BR-002). Постусловие: ROS показана в модальном окне; ничего не сохраняется (БД/Jira/логи). Триггер: клик по контурной кнопке «ROS» (под «Сопоставить»). Основной сценарий: открыть окно → показать/подставить ставку → ввести ЗП → автопересчёт ≤ 0,3 с → два значения ROS (до/после лимита) + месяц перехода → закрытие (Отмена/×/Esc). Альтернатива 4а: валюта/единица не руб./час — ручной ввод, значение справочно. Исключения: 5а ЗП ≤ 0 или не число — «Введите ЗП числом больше нуля»; 5б ставка ≤ 0 — «Введите ставку числом больше нуля»; 5в ставка > 1 000 000 — «Ставка не может превышать 1 000 000».

**CR-история:** CR-018 (approved — решение владельца «апрув», 05.11.2026)
