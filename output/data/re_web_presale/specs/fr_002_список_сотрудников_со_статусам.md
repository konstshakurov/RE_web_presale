## Формулировка

> _Формулировка: «Система ДОЛЖНА [действие]...»_

Система ДОЛЖНА отображать список сотрудников (карточки Jira типа Epic) с фильтром по статусу из 10 статусов Jira: Выход новичка, Программа обучения, Внутренний проект, Свободен, Коммерческий проект, Ожидает подключения, Скоро освобождается, Недоступен для подключения, Уволен, Декрет. Для каждой карточки ДОЛЖНЫ показываться описание, отпуска и переход к CV. Для назначения на потребность ДОЛЖНЫ быть доступны сотрудники в статусах: Выход новичка, Программа обучения, Внутренний проект, Свободен, Ожидает подключения, Скоро освобождается. Сотрудники в статусах Коммерческий проект, Недоступен для подключения, Уволен, Декрет НЕ ДОЛЖНЫ назначаться.

Фильтр статусов ДОЛЖЕН быть мультивыбором: ряд чипов «Все N» и девяти статусов, кроме «Уволен» — он остаётся отдельным тумблером «Уволенные». Статусы между собой ДОЛЖНЫ сочетаться по ИЛИ; статусы, РО, поиск и «Уволенные» — по И. Повторное нажатие чипа ДОЛЖНО снимать выбор; при нуле выбранных нажат чип «Все N». Выбранный чип ДОЛЖЕН быть отличим без цвета (галочка перед подписью).

Система ДОЛЖНА предоставлять фильтр «РО»: список «Все» (по умолчанию), отображаемые имена руководителей отдела из Jira по алфавиту, последним «Без РО». Данные — поле Jira «Руководитель отдела» (customfield_14401, отображаемое имя). Значение-заглушка «Не назначен» ДОЛЖНО трактоваться как отсутствие РО («Без РО»); неактивные и скрытые настройкой окружения РО в списке НЕ ДОЛЖНЫ показываться. РО в карточке сотрудника НЕ ДОЛЖЕН показываться.

Под панелью ДОЛЖНА быть строка «Показано N из M»: M — число сотрудников с учётом «Уволенные», без остальных фильтров; счётчики статусов и «Все» ДОЛЖНЫ считаться с учётом РО и «Уволенные», без учёта поиска. При заданном хотя бы одном фильтре в строке ДОЛЖНЫ перечисляться только заданные условия и быть ссылка «Сбросить фильтры», возвращающая все фильтры в исходное состояние. Фильтр по технологии на «Сотрудниках» НЕ ДОЛЖЕН добавляться.

## Обоснование

РО и коллеги запросили ускоренный отбор сотрудников: выбор нескольких статусов одновременно и фильтр по руководителю отдела вместо ручного просмотра списка.

## Ограничения и допущения

Статусы сотрудника — workflow типа Epic (БП-8), отдельный от workflow потребности. Список сотрудников обновляется раз в час и по кнопке (FR-028). Поле РО синхронизируется по FR-028 (customfield_14401; заглушка «Не назначен» = NULL). Состояние фильтров в URL не сохраняется. UI-решение — design/KON-134/decision.md v5 (approved): порядок панели «Поиск → РО → Уволенные», состояния загрузки/ошибки, клавиатура и доступность (Tab/Enter/Space, видимый фокус, aria-pressed).

## Acceptance Criteria

1. Можно выбрать несколько статусов; список показывает сотрудников любого из выбранных (ИЛИ); повторное нажатие снимает выбор; при нуле выбранных нажат «Все N».
2. «РО» по умолчанию «Все»; выбор имени оставляет сотрудников этого РО; в сочетании со статусами, поиском и «Уволенные» результат — пересечение (И).
3. «Сбросить фильтры» возвращает все фильтры в исходное состояние; ссылка видна только при заданном фильтре.
4. Строка «Показано N из M» совпадает с числом карточек; перечень условий называет только заданные.
5. «Без РО» — последний пункт списка; выбор показывает сотрудников с пустым РО («Не назначен» в Jira трактуется как пустое); сочетается с остальными фильтрами по И.
6. Неактивные и скрытые настройкой окружения РО в списке фильтра не показываются; РО в карточке сотрудника не выводится.
7. Счётчики статусов и «Все» считаются с учётом РО и «Уволенные», без учёта поиска.
8. Состояния (загрузка, ошибка списка, ошибка списка РО с работающими остальными фильтрами, пустой результат) показаны текстами решения KON-134 v5.
9. На 1280 и 1024 в обеих темах фильтры помещаются без наложений и горизонтальной прокрутки; выбранный чип отличим без цвета (галочка); Tab/Enter/Space работают, фокус виден.
10. Правила назначения по статусам из первой части требования не изменены.
