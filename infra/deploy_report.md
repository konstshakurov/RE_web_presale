## 1. Боевой оверлей `docker-compose.prod.yml`

Создан `/opt/re_web_presale/docker-compose.prod.yml` (и копия в репозитории `docker-compose.prod.yml`).

- **proxy (nginx):** публикует **только 443** (`0.0.0.0:443->443`). Порт 80 **не публикуется** (закрыт ufw).
- **db, api:** порты не публикуются наружу (`ports: []`); Docker открывает их только внутри сети `internal`.
- `restart: unless-stopped` унаследован из базового compose.
- Healthchecks: db (pg_isready), api (urllib /health), web (wget), worker (heartbeat), proxy (wget https с `--no-check-certificate`).
- Лимиты ресурсов (старт по `infra/vm_setup.md` п. 5.2):

| Сервис | Память | CPU | Обоснование |
|---|---|---|---|
| db | 2 ГБ | 1.5 | PostgreSQL + init-роли, запас под рост данных |
| api | 1 ГБ | 1.0 | uvicorn + FastAPI, sync Jira/LLM |
| worker | 1 ГБ | 1.0 | фоновые задачи, LLM-шлюз |
| web | 256 МБ | 0.5 | статика nginx (unprivileged) |
| proxy | 256 МБ | 0.5 | nginx TLS-терминатор |

Оценка адекватности: ВМ 8 ГБ RAM / 8 vCPU; сумма лимитов ~4.5 ГБ, оставляет запас ОС/Docker. Лимиты не менялись.

- Логи: `json-file` 10m × 5 (как в `daemon.json`).
- `env_file: /opt/re_web_presale/.env` (через `--env-file` при запуске).
- Тома: именованный `pgdata` (БД), каталог `/opt/re_web_presale` для кода; CV-файлы хранятся в БД (bytea) + локальные пути внутри контейнера api. Решение: именованный том `pgdata` для БД (проще бэкап через `pg_dump`), каталог на хосте для кода/конфигов. Обоснование: будущие бэкапы (отдельная задача) смогут делать `pg_dump` из контейнера db без доступа к файловой системе хоста; том `pgdata` изолирован от кода.

Скрипт `scripts/gen_selfsigned_cert.sh` создан, проверен на ВМ: запуск без `--force` выдаёт `CERT_EXISTS (не перезаписан)`, отпечаток SHA256 `71:B5:FE:F0:4F:78:89:0E:E2:94:35:FE:8F:F1:5E:95:12:05:48:FB:43:25:6B:27:AE:4E:3E:31:C1:25:5B:79` совпадает. Сертификат создан идемпотентно (не затирает существующий).

Параметры:
- Алгоритм: RSA 2048, SHA-256.
- Срок: 825 дней (до 23.01.2029).
- SAN: `DNS:vm-re.simbirsoft`, `DNS:vm-re`, `IP:10.73.11.110`.
- Права: каталог `tls` 700, cert 644, key 600 (user:user).

**Отпечаток SHA256:** `71:B5:FE:F0:4F:78:89:0E:E2:94:35:FE:8F:F1:5E:95:12:05:48:FB:43:25:6B:27:AE:4E:3E:31:C1:25:5B:79`

**Обоснование «самоподписанный vs локальный УЦ»:** выбран самоподписанный, потому что (а) сертификат выдаётся без обращения к Support (решение владельца), (б) SAN включает IP и короткое имя, (в) срок 825 дней — стандартный для самоподписанных. Локальный УЦ Simbirsoft предпочтительнее для продакшена (доверие без ручного импорта), но требует заявки в Support и времени. Инструкция по переходу на УЦ — в `infra/deploy.md` §5–6.

**HSTS не включён:** при самоподписанном сертификате включение HSTS заблокирует доступ при ошибке доверия (браузер не даст обойти предупреждение). Включить после перехода на сертификат внутреннего УЦ.

## 7. Проблемы продукта (для Dev)

1. **Healthcheck proxy в базовом compose** обращается к `http://127.0.0.1/health`, а в боевом оверлее nginx слушает только 443. Исправлено в оверлее (`wget --no-check-certificate https://127.0.0.1/health`). Рекомендуется обновить и базовый `docker-compose.yml` (healthcheck proxy) для единообразия.
2. **Сервис `ldap-test`** объявляет `TEST_LDAP_DOMAIN` и `TEST_LDAP_ADMIN_PASSWORD` как обязательные (`:?`), из-за чего `docker compose config` падает, если они пусты. В `.env` на ВМ значения заполнены (тестовые, не боевые; в отчёте не приводятся) только для прохождения валидации. Рекомендуется сделать их необязательными (`:-`) или убрать сервис из базового compose (он нужен только для разработки).
3. **`scripts/gen_selfsigned_cert.sh`** создан, идемпотентен, проверен на ВМ: `CERT_EXISTS (не перезаписан)`, отпечаток `71:B5:...:5B:79` совпадает. Рекомендуется использовать для повторяемости.
4. **Worker heartbeat-файл** имеет размер 0 байт (`/tmp/worker.heartbeat`) — healthcheck проверяет mtime, что работает, но содержимое пустое. Не критично.
5. **Сообщение «сбой цикла LLM: AdminShutdown»** в логах worker — возникло при перезапуске proxy (остановка контейнера), не ошибка продукта. Worker восстановился и healthy.
