## Описание CR

**Название:** Модель доступа к Jira: сессионная cookie вместо OAuth 1.0a (FR-025, UC-005, NFR-006, DD-001)  
**Тип:** change_existing | **Инициатор:** Аналитик (по итогам документирования интеграции Jira, KON-126)  
**Открыт:** 2026-10-26  
**Регуляторный:** Нет  

Утверждённые FR-025 v1.0 и UC-005 v1.0 описывают OAuth 1.0a (Application Link, RSA-ключ, перенаправление пользователя в Jira для разрешения доступа, access token). Реализовано иначе (проба KON-30, ADR-005, решение владельца 05.10.2026; KON-52, KON-42): логин и пароль Jira совпадают с LDAP; при входе один ввод пароля используется для LDAP bind и для POST /rest/auth/1/session; пароль не сохраняется; хранится зашифрованный сессионный токен (cookie JSESSIONID, AES-256-GCM); при 401 пароль запрашивается повторно без потери введённых данных; Application Link — запасной вариант, не используется. Нужно: переписать FR-025 (название и формулировка), UC-005 (шаги 3-6, постусловие, исключения 5а/6а), поправить термин «OAuth-токен» в NFR-006 и DD-001 на «сессионный токен Jira»; закрыть ISS-001/RK-001 (заявка в Support на Application Link более не блокирует). Основание и диаграммы: product_docs/02_system_components/jira_integration/ (README, SEQ-1, SEQ-6). Реализация уже в проде MVP; CR приводит спецификацию в соответствие.
