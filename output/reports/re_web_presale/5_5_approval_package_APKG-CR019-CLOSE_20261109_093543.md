### FR-005: Рекомендация кандидата с % соответствия и обоснованием
**Тип:** functional | **Версия:** 1.1 | Приоритет: High
**Owner:** Руководитель направления Аналитики

Система ДОЛЖНА по запросу пользователя («Сопоставить», FR-036) оценивать соответствие сотрудников выбранной потребности: процент и краткое текстовое обоснование, рассчитанные LLM по Основному CV (FR-027) и требованиям потребности — опыт в годах, отрасли, инструменты, опыт в системах, профессия. В оценку ДОЛЖНА учитываться свободная заметка о сотруднике (FR-033, например «не подключать в ЛеманаПРО»). Оцениваются только сотрудники в статусах, допустимых для назначения (FR-002) и имеющие Основное CV. Результат — рекомендация; решение принимает пользователь. Для снижения нагрузки на LLM система ДОЛЖНА сначала отобрать сотрудников детерминированно (по технологиям, статусу), а LLM оценивать только отобранных; результат кэшируется по связке «потребность + Основное CV + модель» и пересчитывается при изменении потребности или CV.

**Правила объективности вывода (добавлено, CR-019):**
1. Только по требованиям потребности; собственные пороги и знания о грейдах модели запрещены. Требование не сказано явно в потребности — не учитывается ни в проценте, ни в обосновании, ни в gaps.
2. Формулировки нехватки — «в CV не указан/не упомянут X»; «нет опыта» / «отсутствует опыт» запрещены.
3. Согласованность: percent < 100 ⟺ причины перечислены в gaps; «полностью закрывает» при percent < 100 запрещено.
4. Без модальностей домысла («может считаться», «может не соответствовать», «ожидаемый уровень»).
5. Пост-обработка правил 2–4 реализуется в коде и покрыта unit-тестами.
6. Golden-кейсы (пары CV+потребность) — регрессия при смене промптов/моделей.

**CR-история:** CR-019 (approved — решение владельца «B/C», 09.11.2026)

### FR-036: Сопоставление потребности с кандидатами
**Тип:** functional | **Версия:** 1.2 | Приоритет: High
**Owner:** Руководитель направления Аналитики

По кнопке «Сопоставить» в столбце «Требования» система ДОЛЖНА запустить сопоставление (FR-005) и показать в столбце «Кандидаты» список подходящих сотрудников, отсортированный по убыванию % совпадения. Для каждого кандидата показываются: ФИО, статус сотрудника, % совпадения (цветовая шкала), значок заметки (FR-033), кнопки «Резюме» (открыть Основное CV, FR-037) и «Назначить» (FR-008). Первоначально показываются 10 лучших, остальные — по «Показать ещё». Подсказка с обоснованием оценки показывается по клику на %. Повторное открытие потребности показывает сохранённый результат с датой расчёта и кнопкой «Пересчитать». Если подходящих нет — сообщение; пользователь может перейти к смене статуса «Кандидатов нет» (FR-011).

**Правила объективности** — см. FR-005 v1.1 (те же правила распространяются на вывод сопоставления и подсказку обоснования; применима и пост-обработка).
