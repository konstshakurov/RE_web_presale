# KON-134 (Pre.UX-8) + часть «Сотрудники» из KON-124 — варианты и рекомендация

Статус: **на согласовании у владельца**. Бриф, допущения и пробел в требованиях — `brief.md`.

Прототипы (двойным кликом, без внешних загрузок, рабочие фильтры на вымышленных данных; чёрная панель сверху: тема, состояние списка, состояние списка РО, готовые примеры):
`variant_a.html`, `variant_b.html`, `kon124_cards.html` (кнопки карточки в одну строку, стресс-проверка).

## Правила фильтров (одинаковы в обоих вариантах)
- Статусы: можно выбрать несколько; снять — повторным нажатием или крестиком; внутри статусов ИЛИ.
- Статусы, РО, поиск и «Уволенные» действуют одновременно: **И**. Над списком всегда строка «Показано N из M · статус … · РО … · поиск … (все условия сразу)» и ссылка «Сбросить фильтры» (видна, только если что-то задано; возвращает «Все статусы», РО «Все», пустой поиск, «Уволенные» выключено).
- РО по умолчанию «Все»; в списке отображаемые имена из Jira; длинное имя обрезается многоточием, полное — в подсказке `title`.
- Счётчики статусов считаются с учётом РО и «Уволенные» (допущение 2).

## Варианты

| | A. Чипы-переключатели | B. Выпадающий мультивыбор |
|---|---|---|
| Суть | Текущий ряд чипов остаётся, но чипы переключаются независимо; «Все N» — когда ничего не выбрано; выбранные помечены галочкой и заливкой; РО — выпадающий список в панели рядом с поиском | Статусы сворачиваются в одно поле «Статус» (кнопка с выпадающим списком флажков и счётчиками); выбранные дублируются снимаемыми чипами «Свободен ×» под панелью; поле РО рядом |
| Высота блока фильтров | 1280: две строки чипов + панель; 1024: три строки + панель | одна строка панели (+ строка выбранных чипов только когда они есть) |
| Видимость выбора | все 10 статусов с счётчиками всегда на виду | выбранные видны чипами; полный список только в раскрытом поле |
| Снять один из выбранных | клик по чипу | крестик на чипе или флажок в списке |
| Снять все | клик «Все» или «Сбросить фильтры» | «Снять все» в списке или «Сбросить фильтры» |
| Клавиатура | чипы — обычные кнопки, Tab/Enter/Space, `aria-pressed` | кнопка с `aria-expanded`, флажки Tab/Space, Esc закрывает и возвращает фокус; клик вне закрывает |
| Новые компоненты | нет (правка существующих чипов, + `select` РО, + строка «Показано…») | да: выпадающий мультивыбор (поповер, закрытие по Esc/клику вне, фокус), снимаемые чипы |
| Цена для Dev | низкая: ~0,5 дня фронтенда на фильтры + параметры API | средняя: +компонент и тесты поведения, ~1,5 дня |

### A. Плюсы / минусы
- Плюсы: привычно (тот же ряд), все статусы и их счётчики видны сразу, ни одного нового паттерна; самая дешёвая.
- Минусы: ряд занимает 2–3 строки и отодвигает список вниз (на 1024 три строки); при добавлении новых статусов в Jira ряд растёт; нужна галочка у выбранных, чтобы выбор не опирался только на цвет.

### B. Плюсы / минусы
- Плюсы: все фильтры в одной панели, список выше на ~80–120 px; масштабируется на любое число статусов; выбранные видны чипами, снять — одно нажатие.
- Минусы: счётчики статусов видны только при раскрытии; два клика, чтобы выбрать первый статус; новый компонент и больше состояний (a11y, фокус).

## Состояния (оба варианта)
Скриншоты `variant_<a|b>_<состояние>_<dark|light>_<1280|1024>.png`:
- `default` — без фильтров; `filtered` — два статуса + РО; `open` (B) — раскрытое поле статусов; `longro` — очень длинное имя РО + пять статусов (A: чипы переносятся, B: «5 статуса» + ряд снимаемых чипов).
- `empty` — «По выбранным фильтрам сотрудников нет.» + кнопка «Сбросить фильтры» (без фильтров и без данных остаётся прежнее «Нет данных»).
- `loading` — «Загрузка…» (список) и «Загружаем список РО…» (РО, поле отключено); `error` — «Не удалось загрузить сотрудников. Проверьте соединение и обновите страницу.» (`role="alert"`).
- `rofail` — список РО не загрузился: поле отключено («Список недоступен»), красная строка «Не удалось загрузить список РО. Остальные фильтры работают.» + «Повторить»; фильтры по статусам, поиску, «Уволенные» работают.
- `nonero` — в карточках нет РО: поле отключено («Нет данных») и подсказка «В карточках сотрудников не указан руководитель отдела — фильтр недоступен.»
- Метки полей («Поиск», «Статус», «РО») видимы над полями; фокус — рамка `--accent` 2 px.

## KON-124, часть «Сотрудники»: три кнопки в одну строку
Один вариант + «как сейчас» (`kon124_cards.html`, скрины `kon124_cards_<dark|light>.png`, стресс при шрифте 20 px):
- `.card__actions`: `flex-wrap: nowrap`, `gap: 0`, `margin-left: -8px` (выравнивание текста по левому краю карточки, как в KON-78); `.act`: `white-space: nowrap`, `min-width: 0`.
- Нехватка ширины, пороги в `em` контейнера (карточка = `container-type: inline-size`): при внутренней ширине ≤ 20em уже отступы кнопок (6 px) и зазор иконки 4 px; при ≤ 17em иконки скрываются, остаются подписи. Подписи не переносятся и не обрезаются; у кнопок остаётся `aria-label` с ФИО. Горизонтальной прокрутки нет (карточка в сетке не уже 300 px).
- Пороги в `em` — чтобы работало при увеличении шрифта и масштаба 80–125 %. Контейнерные запросы поддерживаются актуальными Chrome/Edge/Firefox/Safari; без них остаётся `nowrap` с обычными отступами.

### KON-124, часть «Потребности» (текстовые правки, без прототипа)
Исходные правки из задачи, макета не требуют; прошу утвердить вместе:
1. Ссылка «Правила клиента» -> «**Правила**»; `title="Правила клиента"` и `aria-label="Правила клиента"` сохраняют ясность.
2. Колонка «Ставка»: «от производства» -> «**от произв.**», `white-space: nowrap`; перенос не допускается; многоточие не нужно (текст короче прежнего и умещается в колонке 1024 px — проверить при реализации).
3. Ссылка «Скрыть кандидатов» -> «**Скрыть**»; «N кандидатов» без изменений.
Эти три пункта можно реализовать независимо от выбора A/B.

## Рекомендация: A
Это правка существующего ряда без нового паттерна, самая дешёвая, и все статусы со счётчиками остаются на виду — для отбора «покажи Свободен и Скоро освобождается» это быстрее. B лучше, если владелец хочет компактную панель и ожидается рост числа статусов; тогда цена выше (~+1 день и тесты). Переход A -> B позже возможен без изменений API.
