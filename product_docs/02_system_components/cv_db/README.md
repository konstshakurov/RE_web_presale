# Файлы и CV (`cv_db`) — паспорт компонента (SRV)

Статус страницы: `implemented`. Актуально на 26.10.2026 по миграциям `db/migrations/cv_db/V001…V010`, ADR-003/007/009 и маршрутам `/cv`.

| Атрибут | Значение |
|---|---|
| Назначение | Хранение сотрудников и их файлов (основное и дополнительные CV, материалы), извлечённый текст, навыки, архив версий основного CV, заметка о сотруднике; кэш и прогоны сопоставления и смыслового поиска |
| Код | `backend/app/cv/` (`router.py`, `repo.py`, `extract.py`, `formats.py`, `limits.py`), `backend/app/matching/repo.py` |
| Данные | отдельная БД `cv_db` (PostgreSQL 16), схема `cv`, роль `cv_rw`, не видит `app_db`; доступ только через слой `cv_repo` |
| Бизнес-функции | BF-02, BF-03 |
| Требования | FR-002, 003, 004, 005, 022, 027, 032, 033, 036, 037, 039, 040; NFR-007; ERD-001, DD-001 |
| Архитектурное решение | ADR-003 (две БД, раздельные роли), ADR-009 (bytea, лимит 10 МБ, текст при загрузке, архив 3 версий) |
| Первоисточник схемы | миграции `db/migrations/cv_db/` |

## Эндпоинты (`/cv`)

| Метод и путь | Назначение |
|---|---|
| `GET /cv/limits`, `PUT /cv/limits` | лимиты файлов |
| `GET /cv/files`, `GET /cv/employees/{key}/files` | списки файлов |
| `POST /cv/employees/{key}/files` | загрузка файла сотрудника (413 — больше лимита, 415 — недопустимый формат) |
| `GET /cv/files/{id}/download`, `GET /cv/files/{id}/text` | скачивание, извлечённый текст |
| `GET /cv/employees/{key}/main-cv` | основное CV (источник компетенций, FR-027) |
| `PUT /cv/employees/{key}/note` | заметка о сотруднике (FR-033) |
| `DELETE /cv/files/{id}`, `POST /cv/files/{id}/restore` | удаление и восстановление из архива |

Маршруты сопоставления и поиска (`/needs/{key}/match`, `/resume/…`) — см. `../llm_gateway/README.md`.

## Правила
* Файлы в `cv_db` (bytea), лимит файла 10 МБ (допущение A5), тип файла обязателен.
* Основное CV — главный источник компетенций; замена сохраняет 3 последние версии в архиве (FR-039); навыки пересчитываются при замене файла.
* Сотрудники приходят из Jira (`issuetype = "Epic"`, раз в час); карточка связывается с потребностью по «Профилю сотрудника» (`jira_login`).
* Бэкапы: ежедневный дамп 30 дней + ежемесячные 5 лет (A6).
