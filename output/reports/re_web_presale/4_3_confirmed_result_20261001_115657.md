## Функциональные требования

**FR-001:** Система отображает в отдельном разделе новые потребности из Jira (проект ANALYTICS, тип задачи «Аналитик») со ставками.  
*Критерий приёмки: Новая потребность из Jira появляется в разделе; ставка показана вместе с валютой, признаком НДС и единицей измерения; пустая ставка допустима.*

**FR-002:** Система отображает список сотрудников (карточки Jira, тип Epic) с фильтром по статусу из 10 статусов Jira: Выход новичка, Программа обучения, Внутренний проект, Свободен, Коммерческий проект, Ожидает подключения, Скоро освобождается, Недоступен для подключения, Уволен, Декрет; с описанием, отпусками и доступом к CV. Для назначения на потребность доступны сотрудники во всех статусах, кроме: Коммерческий проект, Уволен, Декрет, Недоступен для подключения.  
*Критерий приёмки: Фильтр содержит все 10 статусов; сотрудник в статусе Коммерческий проект, Уволен, Декрет или Недоступен для подключения не может быть назначен; в остальных 6 статусах назначение разрешено; у карточки есть переход к CV.*

**FR-003:** Система показывает профиль сотрудника: краткий опыт из CV (отрасли, стек, проекты).  
*Критерий приёмки: Состав и объём краткого опыта согласуется на этапе спецификации 7.1; профиль содержит отрасли, стек, проекты.*

**FR-004:** Система хранит сотрудников, их CV и дополнительные сведения (в т.ч. поле Jira «Подробнее об опыте») в отдельной БД; у сотрудника может быть несколько CV (корпоративное и по шаблонам клиентов).  
*Критерий приёмки: К сотруднику привязывается несколько CV; у каждого CV есть метаданные «корпоративное (главное)» или «по шаблону клиента».*

**FR-005:** Система предлагает сотрудника и CV под потребность с рейтингом % соответствия, рассчитанным LLM по опыту в годах, отраслям, инструментам, опыту в системах и профессиях.  
*Критерий приёмки: Критерий приёмки — набор эталонных пар «потребность + CV» с ожидаемым результатом; задаётся при спецификации (открытая проблема ISS-006).*

**FR-006:** Система автоматически проверяет CV на противоречия с помощью LLM и показывает отчёт с рекомендациями.  
*Критерий приёмки: Перечень типов противоречий и эталонные CV задаются при спецификации (ISS-006).*

**FR-007:** Система предоставляет диалоговое окно с LLM для запросов по потребностям, CV и рекомендациям.  
*Критерий приёмки: Пользователь может задать запрос в контексте выбранной потребности или CV и получить ответ; во внешнюю LLM уходит только обезличенный текст.*

**FR-008:** Система позволяет назначить на потребность рекомендованного или выбранного вручную сотрудника с загрузкой CV и передаёт в Jira: сотрудника (поле «Профиль сотрудника»), CV (вложение), ставку (если она от производства), комментарий.  
*Критерий приёмки: После назначения в Jira у потребности заполнен профиль сотрудника, есть вложение CV и комментарий; действие выполнено от имени пользователя приложения.*

**FR-009:** Система автоматически устанавливает исполнителем потребности в Jira того РО или РН, кто провёл назначение.  
*Критерий приёмки: Исполнитель потребности в Jira совпадает с учётной записью Jira пользователя, выполнившего назначение.*

**FR-010:** Система позволяет повторно отправить назначение на уже назначенную потребность: предыдущее назначение меняется, если Jira допускает изменение в текущем статусе; побеждает последний отправивший.  
*Критерий приёмки: Если Jira отказывает, пользователь видит причину отказа без потери введённых данных.*

**FR-011:** Система позволяет выбрать статус «Кандидатов нет» с обязательной причиной из выпадающего справочника Jira и статус «Найм».  
*Критерий приёмки: Справочник причин и обязательные поля перехода берутся из Jira; конкретное поле причины уточняется у администратора Jira (ISS-010).*

**FR-012:** Система генерирует рекомендации по адаптации CV под потребность, версию CV для потребности и сопроводительное письмо; после апрува письмо прикрепляется комментарием к потребности в Jira.  
*Критерий приёмки: Письмо публикуется в Jira только после явного апрува пользователя.*

**FR-013:** Система отправляет в Jira комментарием результат скрининга сотрудника.  
*Критерий приёмки: Комментарий создан в потребности от имени пользователя.*

**FR-014:** Система выявляет дубли потребностей по описанию (не по названию) и показывает % совпадения; сравнение с потребностями на аналитиков за последние 2 недели во всех статусах. Дублем с очень высокой вероятностью считается совпадение 15% и более текста, описывающего требования к кандидату (опыт, компетенции, навыки, инструменты), полностью совпадающего в последовательном изложении (не вразброс).  
*Критерий приёмки: На эталонных примерах «Прямой контракт»/«Субподрядчик» пара с совпадением последовательного фрагмента требований от 15% помечается как вероятный дубль; для сравнения используется статус, а не резолюция.*

**FR-015:** Система показывает правила и условия клиента из эпика (комментарии в Активности, поле «Рекомендации», Описание, вкладка «Важные условия для производства» с её структурными полями) и только информирует при нарушении, не блокируя отправку.  
*Критерий приёмки: Перечень полей эпика и потребности (напр. «Рисовать опыт нельзя») определяется при спецификации (ISS-009); отправка не блокируется.*

**FR-016:** Система показывает историю отправок аналитика клиенту: в какие потребности отправляли, статус, ставку; только по потребностям направления Аналитики.  
*Критерий приёмки: История по сотруднику содержит потребность, статус и ставку.*

**FR-017:** Система создаёт из корпоративного CV CV по шаблону клиента и проверяет, не создавалось ли такое CV ранее.  
*Критерий приёмки: При повторном запросе для той же пары сотрудник/клиент система показывает ранее созданное CV.*

**FR-018:** Система при назначении запрашивает ставку, если она от производства; ввод свободный, без встроенной логики.  
*Критерий приёмки: Поле ставки обязательно только при признаке «ставка от производства».*

**FR-019:** Система выводит среднюю и медианную ставки по потребностям за период (например, 6 месяцев) по величинам ставок, без привязки к грейдам и ролям. Рублёвые ставки приводятся к единому виду, НДС принимается равным 22%. Ставки в других валютах считаются отдельно по каждой валюте и с рублями не складываются; расчёт ведётся в разрезе единицы измерения.  
*Критерий приёмки: На тестовом наборе рублёвых ставок с НДС и без НДС результат совпадает с ручным расчётом при НДС 22%; ставки USD и KZT не входят в рублёвую статистику. Целевой вид приведения (с НДС или без) и ставка НДС как настройка — уточняются при спецификации.*

**FR-020:** Система отображает текущий статус потребности из Jira для всех статусов workflow типа «Аналитик» (19 статусов).  
*Критерий приёмки: Статус потребности в приложении совпадает со статусом в Jira.*

**FR-021:** Администратор выдаёт и отзывает доступ к приложению выборочным LDAP-аккаунтам (РО и выбранные Presale-менеджеры).  
*Критерий приёмки: Пользователь вне списка не входит, даже если LDAP-вход успешен; отзыв доступа действует немедленно.*

**FR-022:** Система поддерживает первичную загрузку CV из папок по сотрудникам (около 80, форматы doc/docx), отсекая не работающих сотрудников по статусам карточки Jira (Уволен, Декрет).  
*Критерий приёмки: Ключ сопоставления папка–сотрудник уточняется при спецификации (ISS-008); CV уволенных сотрудников не загружаются.*

**FR-023:** Система обезличивает фрагменты потребностей и CV (компании, имена, названия проектов, локации, персональные данные) перед отправкой во внешнюю LLM.  
*Критерий приёмки: В запросе во внешнюю LLM нет перечисленных сущностей; перечень и методика проверки — при спецификации (ISS-006).*

**FR-024:** Вход в приложение выполняется по корпоративному LDAP; пароль не сохраняется; доступ только пользователям из списка администратора.  
*Критерий приёмки: Успешный LDAP-вход и наличие в списке — условия создания сессии.*

**FR-025:** Действия в Jira выполняются от имени конкретного пользователя через OAuth 1.0a (Application Link); при первом входе пользователь разрешает доступ в Jira; токен хранится зашифрованно, ключ шифрования в окружении; при отзыве доступа (401) авторизация запрашивается повторно.  
*Критерий приёмки: В истории Jira действия отображаются от имени пользователя; токен в БД в открытом виде отсутствует. Зависит от согласия администратора Jira (ISS-001).*

**FR-026:** Смена статуса потребности: приложение запрашивает у Jira допустимые переходы из текущего статуса (с обязательными полями) и показывает их пользователю; приложение не вводит собственных ограничений на операции, права определяются правами пользователя в Jira; отказы Jira показываются как есть.  
*Критерий приёмки: Список переходов совпадает с ответом Jira; при отказе (403 и др.) пользователь видит причину.*

**FR-027:** Корпоративное CV сотрудника отмечается флажком или метаданными. Если у сотрудника одно CV, оно автоматически помечается корпоративным (главным); если несколько, система предлагает указать основное корпоративное.  
*Критерий приёмки: При одном CV флаг выставлен автоматически; при нескольких без выбора флаг не проставляется и запрос повторяется до выбора.*

## Ограничения

- Web-приложение, on-premise на сервере компании.
- Jira — корпоративный Jira Server 8.13.0 (не облако), личных токенов (PAT) нет, обновить Jira пока нельзя.
- Вход в приложение — корпоративный LDAP плюс список пользователей, разрешённых администратором.
- LLM по умолчанию — корпоративная Qwen; внешняя LLM — только обезличенный текст; настройка через ввод API Key и URL; Claude — только через API-ключ.
- Разработка силами ИИ-агентов; весь объём — MVP.
- Права в Jira — права самого пользователя; приложение не ограничивает набор операций у себя.
- Дети эпика читаются только через Agile API; поля parent и priority Jira не возвращает; Epic Link хранится в customfield_10101.
- Полный граф workflow через REST недоступен: переходы только из текущего статуса задачи.

## Бизнес-правила

- БП-1: Что может менять пользователь в Jira, определяет Jira по правам пользователя; клиентская служба меняет остальные статусы по своим правам.
- БП-2: Ставку вносит аккаунт или сейлз с признаком «ставка от клиента» / «ставка от производства» (поле «Кто предлагает ставку»); поле может быть пустым; при ставке от производства наша ставка вносится вручную при назначении.
- БП-3: Ставка хранится вместе с валютой, признаком «Включает НДС» и единицей измерения; для рублей признак НДС обязателен, ставки в иных валютах всегда без НДС.
- БП-4: Валюта в основном рубли, редко доллары и тенге.
- БП-5: Потребности направления Аналитики имеют ключ с префиксом ANALYTICS; в потребности есть поле «Тип контракта» (Прямой контракт / Субподрядчик).
- БП-6: Правила клиентов задаются в эпике (свободный текст и структурные поля); нарушение только информирует.
- БП-7: Корпоративный формат CV: профиль, основной стек, отрасли, ключевые навыки, языки, образование, проекты.
- БП-8: Потребности и сотрудники — разные workflow Jira: 19 статусов у типа «Аналитик», 10 статусов у типа Epic (карточка сотрудника).
- БП-9: Для расчёта средней и медианной ставки НДС принимается равным 22%.
- БП-10: Для определения состояния потребности и эпика используется статус, а не резолюция.

## ⚠️ Открытые проблемы (known issues)

_Передаются в следующие задачи как явные риски._

**ISS-001:** Согласие администратора Jira на Application Link (OAuth 1.0a) не получено.  
- Риск: Без Application Link действия в Jira от имени пользователя на Jira 8.13.0 невозможны; потребуется другая схема доступа.  
- Владелец: Руководитель направления Аналитики / администратор Jira

**ISS-006:** Нет критериев приёмки для % соответствия (FR-005), проверки CV (FR-006), обезличивания (FR-023).  
- Риск: Невозможно принять LLM-функции; риск утечки данных во внешнюю LLM и недостаточного качества Qwen.  
- Владелец: Аналитик + Руководитель направления Аналитики

**ISS-008:** Не выбран ключ сопоставления папок CV и карточек сотрудников (ФИО, ID пользователя, ссылка на резюме).  
- Риск: Ошибочная привязка CV к сотруднику при первичной загрузке.  
- Владелец: Аналитик + Руководитель направления Аналитики

**ISS-009:** Не определён перечень полей эпика и потребности, показываемых как правила клиента.  
- Риск: Часть правил клиента не будет показана пользователю.  
- Владелец: Аналитик

**ISS-010:** Не определены поле причины для «Кандидатов нет» и обязательные поля переходов в Кандидат назначен / Кандидатов нет / Найм.  
- Риск: Смена статуса из приложения может отклоняться Jira.  
- Владелец: Администратор Jira

**ISS-011:** Нет НФТ по защите персональных данных (шифрование, резервное копирование, роли, согласование с ИБ).  
- Риск: Нарушение требований по ПДн при бессрочном хранении CV.  
- Владелец: Руководитель направления Аналитики / ИБ

**ISS-012:** Не определены способ получения изменений из Jira (опрос или вебхуки), период и НФТ по времени отклика.  
- Риск: Неактуальные данные и непредсказуемая производительность.  
- Владелец: Аналитик + разработка

**ISS-013:** Не описано поведение при отказах Jira, кроме общего принципа в FR-026.  
- Риск: Непонятные сообщения об ошибках у пользователя.  
- Владелец: Аналитик
