# Правила экспорта estimate.md в xlsx для CashMeter

Источник истины по правилам заполнения ячеек — лист «ПРАВИЛА ЗАПОЛНЕНИЯ» в
`assets/Шаблон для импорта.xlsx` (колонка C — «Правила заполнения шаблона для
скила analyst_estimate»). Этот файл — рабочая выжимка тех правил для скилла и
реализации `scripts/export_to_xlsx.py`; при расхождении приоритет у шаблона.

## Когда применять

Экспорт — опциональный шаг ПОСЛЕ того, как `estimate.md`/`estimate_pp.md`
полностью сохранён (см. Шаг 5 SKILL.md). Не предлагай его раньше и не запускай
автоматически без вопроса BA — см. Шаг 6 SKILL.md.

## Откуда берутся строки

В xlsx попадают только пронумерованные строки таблиц детализации (заголовок
H3 вида `### A. Название группы`, сразу за которым — markdown-таблица с
колонками № | Артефакт | Кол-во | Сложность | Норма | Итого | Описание).
Сводные/итоговые таблицы («Итого по группам работ», «Общий итог», строки
«Подитого») не переносятся — они не проходят проверку «№ — целое число».

## Маппинг колонок

| Колонка шаблона | Источник в estimate.md | Правило |
|---|---|---|
| A. Наименование Фазы | — | всегда `"Аналитика"` |
| B. Наименование Этапа | — | название модуля/MVP, если такое разделение есть в оценке; иначе `"Этап 1"` (значение по умолчанию, можно переопределить флагом `--stage`) |
| C. Наименование Задачи | заголовок группы (`### A. ...`) | префикс-нумератор убирается (`A. `, `2.1 ` и т.п.) |
| D. Наименование Подзадачи | колонка «Артефакт» | как есть |
| E. Количество задач | колонка «Кол-во» | ведущее целое число; если % или число не выделяется — подставляется `1` (по правилу шаблона B10/C9) |
| F. Роль | — | всегда `"Аналитик"` |
| G. Часы min | колонка «Норма» (или «Ставка (ч./ед.)» / «Ставка (ч.)») | число часов на единицу; если «Норма» не чистое число (формула, диапазон, «— (фикс.)», текстовое описание) — берётся значение колонки «Итого» вместо неё |
| H. Часы max | — | `round(Часы_min × 1.2, 2)` |
| I–O. Risk/UnitTest/QA/Bugs/PM/TL/Adm, % | — | всегда пусто |
| P. Комментарий | колонка «Описание» | как есть; если в источнике нет колонки «Описание» (более старый формат отчёта) — остаётся пустой |

## Известное ограничение по старым отчётам

Отчёты, сохранённые до появления колонки «Описание» в таблице детализации
(KON-6), не дают заполнить колонку P — построчных описаний в них попросту нет
(есть только общий текст комментариев под таблицей, не привязанный к
конкретной строке). Не пытайся сопоставлять этот текст со строками —
оставляй P пустой и создавай новые оценки уже в текущем формате Шага 5.

## Формат результата

- Один лист с именем **«Шаблон»** (не «АНАЛИТИКА» — см. правку KON-22).
- Стиль всех строк данных — единый плоский (Arial 8, без рамки/заливки),
  не наследуется из первой строки исходного листа «ШАБЛОН» (там обнаружено
  унаследованное форматирование, которого нет у остальных строк).
- Имя файла — то же, что у исходного md, с расширением `.xlsx`
  (`estimate.md` → `estimate.xlsx`), сохраняется рядом с исходником.
