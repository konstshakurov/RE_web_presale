# KON-80 «CV по шаблону клиента» — решение по UI

- Статус: **approved** | 02.11.2026 | утвердил: Константин (чат OpenCode;
  выбран вариант A — «Мастер из 2 шагов»).
- Прототипы: `variant_a.html` (принят), `variant_b.html` (не избран), PNG в этой папке.
- Входы: FR-017, FR-012, UC-004, FR-023, BR-007; KON-79 (диалог из окна «Назначить»),
  `design/tokens.md`, `brief.md`.

## Решения владельца, зафиксированные в чате 02.11.2026 (вход для Dev)

1. Начало процесса — единственная точка: кнопка secondary `«CV по шаблону клиента…»`
   в окне «Назначить кандидата» (KON-79). Отдельной кнопки вне контекста назначения нет.
2. Шаблон клиента берётся из файлов потребности (клиента) — заранее загруженный.
   В диалоге — подтверждение конкретного файла; при нескольких — выбор; при отсутствии —
   состояние «Шаблон клиента не найден. Прикрепите файл в Jira (в потребность)».
   Загрузка шаблона в диалоге не проектируется.
3. Просмотр результата: (а) предпросмотр текста прямо в окне результата — UX-решение
   принято; (б) после сохранения — файл в карточке сотрудника «Файлы» (тип
   «CV по шаблону клиента» + клиент) и в разделе «Резюме»; открытие — стандартной
   кнопкой «Скачать» (как у всех файлов, `/api/cv/files/{id}/download`).
   Встроенный docx-просмотрщик — вне MVP.
4. Повтор по паре «сотрудник + клиент»: предупреждение (BR-007/FR-023), не блокирует;
   текущий результат добавляется в историю, прежние сохраняются.

## Экранный сценарий (вариант A, реализует Dev)

**Шаг 1 — «Файлы и модель»** (входит из окна «Назначить»):
- предупреждение о повторе (если есть прежний результат по паре): `box--warn`,
  `role="alert"`: «Для пары «<сотрудник ФИО> + <клиент>» уже есть CV по шаблону от <дата>.
  Новый результат добавится в историю, прежний останется. Продолжить?» — кнопки
  `Продолжить` (закрывает баннер) / `Отмена`;
- две блока-строки файла (шаблон клиента с папки файлов потребности; Основной CV
  сотрудника): имя, метаданные, чекбоксы «Использую как шаблон» / «Подтверждаю вход»;
  кнопка «Сгенерировать» активна только при обеих подтверждённых галках
  (критерий Dev-14: без подтверждения генерация не стартует);
- при отсутствии шаблона: обе блока заменяются состоянием «пусто» с текстом выше;
- модель LLM: `select`, предзаполняется последней использованной (как в семантическом
  поиске, KON-38/шлюз LLM).

**Шаг 2 — «Генерация»** (то же окно, шаги: чтение шаблона → чтение CV → генерация):
спиннер + «шаг N из 3», закрытие окна/Escape недоступны до завершения
(согласовано с окном «Назначить»); таймаут шлюза 120 с — состояние ошибки.

**Шаг 3 — «Результат»**:
- слева: предпросмотр текста CV (скролл внутри колонки);
- справа: «Рекомендации по адаптации» (bullets, FR-012); «Сопроводительное письмо»
  (редактируемая textarea, предзаполнена черновиком LLM); чекбокс
  «Я проверил(а) письмо, публикую как есть»; кнопка
  `Опубликовать письмо в Jira` — **disabled до явного апрува** чекбокса
  (критерий Dev-14: публикация только после апрува);
- основной футер: «Сохранить CV» (primary) — сохраняет результат с типом
  «CV по шаблону клиента» и клиентом потребности; «Отмена».
- Ошибка шлюза: `box` (`--err`, `role="alert"`) — текст ошибки шлюза как есть, выбор
  сохранён, «Повторить» (шаг генерации перезапускается с теми же вводными).

## Пост-поведение

- После «Сохранить CV»: файл появляется в списке файлов сотрудника (перечитывание),
  окно возвращается в окно «Назначить» (или закрывается — деталь реализации: закрытие
  и визуальный отклик в «Назначить»: файл появляется в «Файлы» диалога).
- После «Опубликовать письмо в Jira»: комментарий виден в Jira; повторная публикация
  того же письма — блокируется вторым нажатием (disabled после отправки).

## Токены и стили

Существующие токены (модал `--wide`, `--primary-btn`, `--panel-2`, `--warn`, `--err`);
новых токенов нет. Кнопка публикации — primary, но меньше (`padding: 5px 10px`).

## Критерии приёмки для QA (обе темы, 1280/1024, окно 400px)

1. Диалог открывается из «Назначить» кнопкой «CV по шаблону клиента…»; заголовок и
   контекстная строка (потребность · клиент · сотрудник) заполнены.
2. Без двух подтверждённых чекбоксов «Сгенерировать» disabled; с ними — активна.
3. Повтор: баннер показывает дату прежнего результата; «Продолжить» — идём дальше,
   «Отмена» — без генерации; прежний результат остаётся в файлах.
4. Нет шаблона в потребности: состояние «пусто» с текстом подсказки; генерации нет.
5. Прогресс: шаги 1–3, закрытие/Esc недоступны.
6. Ошибка шлюза: текст как есть, выбор сохранён, «Повторить».
7. Результат: предпросмотр; чекбокс письма отдельно; «Опубликовать письмо в Jira»
   disabled до апрува, после — комментарий уходит; второе нажатие блокировано.
8. «Сохранить CV»: файл с типом «CV по шаблону клиента» и клиентом появляется в
   файлах сотрудника; «Скачать» работает.
9. Tab-порядок и видимый фокус; высота окна 400px: шапка и футер на месте, тело скроллится.

## Данные и API (в постановке Dev-14 / KON-43)

- старт генерации: `POST` — inputs (id файла шаблона, id основного CV, модель) → задача.
- статус/результат: поллинг или задача-результат шлюза (правила KON-53/43).
- сохранение результата: файл сотрудника, тип «CV по шаблону клиента», клиент потребности.
- публикация письма: комментарий Jira по потребности (после явного апрува).

## Вне объёма

Встроенный рендерер docx; редактирование CV перед сохранением (только предпросмотр);
массовая генерация по нескольким парам.
