## Расхождения/вопросы к аналитику (не баги, решение за владельцем)
1. В `decision.md` область поиска по смыслу включает «Уволенные»; backend (решение владельца 28.10.2026) никогда не включает «Уволен», параметр `include_dismissed` принимается и игнорируется. Включённый тумблер «Уволенные» на «Резюме» таблицу меняет, а область смыслового поиска — нет, и подсказка об этом не говорит. Кандидат в уточнение decision/CR.
2. При пустых чипах («Все») область смыслового поиска по FR-002 исключает статусы «Коммерческий проект», «Декрет», «Недоступен для подключения» и «Уволен», хотя таблица ниже их показывает; подсказка «все фильтры выше» это не раскрывает. Поведение прежнее (FR-002), но формулировка подсказки может вводить в заблуждение.
3. В `ResumesPage` статус в строке таблицы по-прежнему нейтральный `.status` (не `statusClass`), как и до KON-150; решение KON-149 про чипы относилось к Потребностям/Сотрудникам.

## API (KON-143, по диффу и unit-тестам)
- `GET /resume/employees`: `status` повторяемый (ИЛИ), `dept_head` (логин или `__none__`), `include_dismissed`, ответ содержит `statuses` — счётчики с учётом РО и «Уволенные», без поиска и технологий; все условия по И — код соответствует.
- Смысловой поиск (POST и GET): `statuses`, `dept_head`, `include_dismissed`; одиночный `status` совместимо складывается со списком; «Уволен» вне области всегда; пустая область — без вызова LLM; текст запроса в лог не пишется. Прогоны, сохранённые до CR-014, читаются (`from_dict`).
- Фронтенд фильтрует таблицу на клиенте по загруженному списку сотрудников, технологии — запросом к `/resume/employees`; параметры статусов/РО backend списка UI не использует (допустимо по decision.md).
- Во внешнюю LLM только обезличенный текст: путь не менялся (шлюз обезличивания, FR-023); дифф KON-143 его не затрагивает; на живом шлюзе не проверялся.
- pytest: `tests/unit` выборка sync/dept/employee/cv/matching — 184 passed, 35 skipped (БД-тесты; без `TEST_*_DB_URL`). DB-тесты `test_matching_db.py::test_resume_dept_head_statuses_dismissed_and_counts` и др. на QA-БД упали из-за отсутствия миграций V011/V012 (не дефект кода); счётчики и фильтры на реальной БД **не проверены**.
