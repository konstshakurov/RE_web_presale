## Формулировка

> _Формулировка: «Система ДОЛЖНА [действие]...»_

Раздел «Резюме» ДОЛЖЕН содержать таблицу сотрудников со столбцами: Сотрудник (ФИО, ключ Jira, статус), Файлы (FR-022), Содержание/статус извлечения (FR-027), Описание (технологии из Основного CV), Заметка (FR-033). Фильтры:
(1) «Поиск» — по ФИО, ключу, имени файла и тексту внутри CV; работает без LLM.
(2) «Статус сотрудника» — чипы-мультивыбор полосой под заголовком страницы (выпадающий список удалён); в пустом результате — кнопка «Все статусы»; текстовый поиск и фильтры работают без LLM.
(3) «Технология» — выбор нескольких (подсказки из выделенных технологий).
(4) «Поиск по смыслу (LLM)» — запрос на естественном языке; запуск отдельной кнопкой «Найти», поле в одну строку в одном ряду с выбором LLM; область поиска ограничена всеми применёнными фильтрами; по решению владельца 28.10.2026 поиск по смыслу НИКОГДА не охватывает сотрудников в статусе «Уволен».
(5) «РО» — выпадающий список: «Все» (по умолчанию), имена по алфавиту, «Без РО»; данные — customfield_14401 (правила показа — как в FR-002).
Все фильтры (чипы, поиск, РО, технологии, «Уволенные») ДОЛЖНЫ применяться мгновенно; кнопка «Применить» удалена. Кнопка «Сбросить» ДОЛЖНА очищать поиск, РО, технологии и «Уволенные», но не чипы статусов. Backend: статус передаётся списком, добавлен параметр РО.

## Обоснование

Ускорить работу с разделом «Резюме»: мгновенные фильтры, мультивыбор статусов и фильтр по РО, осмысленный поиск по сотрудникам.

## Ограничения и допущения

Запрос во внешнюю LLM — только обезличенный (FR-023); скоуп смыслового поиска зафиксирован CR-014 (семантика — без учёта фильтров статуса/РО в ранжировании, область — пересечение фильтров). UI — design/KON-134/decision.md v5, раздел «Резюме» (approved). Правила РО — CR-012/CR-014, решения владельца 28.10.2026. Реализовано KON-143/145; приёмка Pre.QA-12 (KON-147) — Pass, замечания исправлены (KON-156/157/158).

## Acceptance Criteria

1. Статус выбирается чипами-мультивыбором; в пустом результате доступна кнопка «Все статусы».
2. Фильтр «РО»: «Все» по умолчанию, имена по алфавиту, «Без РО» последним; сочетается с остальными по И.
3. Все фильтры применяются мгновенно (без кнопки «Применить»); «Сбросить» очищает поиск, РО, технологии, «Уволенные» и не трогает чипы статусов.
4. Поиск по смыслу запускается кнопкой «Найти»; поле в одну строку рядом с выбором LLM; область ограничена применёнными фильтрами.
5. Поиск по смыслу никогда не возвращает сотрудников в статусе «Уволен».
6. Текстовый поиск и фильтры работают без LLM.
7. Состояния (загрузка, ошибка, пустой результат с фильтрами и без) показаны текстами решения KON-134 v5.
8. Замечания KON-156/157/158 исправлены и не воспроизводятся.
