## Окно «ROS специалиста» (вариант A, утверждён)

1. **Раскрывающийся блок «Детали расчёта» удалён** (п. 1.1): окно показывает только поля
   ввода и итоговые значения.
2. **Ставка из потребности подставляется автоматически** (п. 1.2): read-only;
   «задана клиентом» → значение из потребности; «не задана»/«от производства» → пустое поле ввода.
3. **Приведение ставки к «с НДС»** (п. 1.3): если в потребности ставка без НДС
   (без НДС: 3 000 руб.), система автоматически вписывает ставку **с НДС** =
   ставка × 1,22 (по НДС 22% из параметров ROS): 3 000 × 1,22 = 3 660.
   Под подписью поля — строка-подсказка: «ставка без НДС приведена к „с НДС“ (× 1,22)».”
4. **Ставка не в рублях или в иной единице** (п. 1.4): поле остаётся **пустым для
   ручного ввода**, значение потребности показывается справочно.
5. **ROS до/после лимита**: как утверждено — оба значения; «до лимита» — крупнее
   (акцентная рамка), «после лимита» справа; под значениями — прибыль и строка
   перехода (месяц перехода вычисляется от ЗП, см. пункт 6).
6. Месяц перехода вычисляется от введённой ЗП: **N = ОКРУГЛВНИЗ(Лимит ФОТ / ЗП, 0)** —
   «до лимита» — N месяцев, «после» — с N+1-го. При ЗП 130 000: N = 22
   (2979000/130000 = 22,9). Значения из отчёта не фиксируются: считаются при каждом
   вводе ЗП.

## Вкладка «ROS» в Настройках (п. 1.4 — owner)

- Вкладка после «Лимит файла»: **ROS**. Поля (все редактируемы любым админом,
  красные рамки, значения по умолчанию = эталонная модель ROS_model_v2):
  - Billable часов в месяц (165);
  - Косвенные расходы на человека (53 000);
  - Ставка налога на прибыль (5%);
  - Ставка НДС (22%);
  - Страховые взносы до лимита (15,2%); после лимита (7,8%);
  - Лимит ФОТ (2 979 000).
- «Сохранить» — значения становятся общими для всех пользователей; при следующем
  открытии окна ROS расчёт идёт с ними (кэш не нужен: читается при каждом открытии).
- НДС из вкладки используется и для авто-приведения «без НДС → с НДС» (п. 1.3).

## Критерии приёмки QA (обе темы, 1280/1024)

1. Окно: ставка read-only при «задана клиентом», автозаполнение; ввод ЗП; пересчёт
   при вводе ≤ 0,3 с; оба значения ROS; строка перехода.
2. Приведение: ставка потребности 3 000 «без НДС» → в поле показывается 3 660 «с НДС».
3. Ставка в валюте/единице — поле пустое, ручной ввод.
4. Блок «Детали расчёта» отсутствует.
5. Настройки: вкладка ROS с 7 полями по умолчанию, «Сохранить» меняет параметры;
   окно ROS считает с изменёнными значениями (например НДС 20% → приведение × 1,20).
6. Расчёт не сохраняется, не пишется в логи/БД/Jira.

## Реализация (Arch → Dev)

- Frontend: окно ROS (единый опрос параметров из Настроек, расчёт на клиенте).
- Backend: API параметров ROS (Настройки, роль Админ: GET/PUT — отдельный CR по 5.4
  добавит требования к этому API, поставляется в спецификации текущей).
- QA: контрольный пример FR-039 (130 000 × 2 200 → 24,80%/27,32%, переход на 23-й месяц).
