# Задача для OpenCode: KON-101 — живая проверка записи ставки (KON-100, CR-008) на ANALYTICS-5925

Срок: по готовности. Условие: **корпоративный VPN** (без него Jira отвечает 403 HTML-страницей — так и было при попытке QA-агента), тестовая учётка Jira у Константина, **запись только в тестовый ключ ANALYTICS-5925**. Предыдущая попытка QA (`qa/KON-100_acceptance.md`, раздел 4) упёрлась именно в 403 без VPN; повторять вход по паролю из `.env` вне VPN не нужно.

## Зачем

KON-100 реализует запись ставки при назначении через ScriptRunner-эндпоинт «Ставка» (проба `architecture/probes/KON-99_report.md`, CR-008). Автотесты и UI-приёмка пройдены на моках; на живой Jira не проверено. Нужно закрыть остаточные риски приёмки и дать QA основание перевести KON-100 в Done.

## Что прочитать

`architecture/probes/KON-99_report.md` (формат тела запроса, справочники, поведение «200 без записи»), `backend/app/integrations/jira/adapter.py` (`JiraAdapter.login`, `get_issue`, `set_rate`), `qa/KON-100_acceptance.md` (разделы 2, 4, 5).

## Что проверить (только ANALYTICS-5925, пауза ≥ 350 мс между запросами)

Использовать **боевой код** `JiraAdapter` из `backend/` (не писать свой клиент), чтобы проверялся именно путь приложения. Вход — `JiraAdapter.login` с логином/паролем из переменных окружения процесса (`JIRA_USERNAME`, `JIRA_PASSWORD`), либо уже запечатанная сессия Константина, если он даст.

1. **«До».** Прочитать поля потребности: `customfield_21105`, 20809, 20810, 20811, 20812, статус, исполнитель. Ожидаемо по пробе: ставка 2700, статус «Кандидат назначен». Если значения другие — зафиксировать и спросить Константина, прежде чем писать.
2. **Запись.** `set_rate(amount=2750, vat=20999, currency=21001, unit=21006, proposer=<производство>, username=<логин Jira>)`. Ожидаемо: успех, перечитывание даёт 2750. Зафиксировать: есть ли `id` у 20810–20812 в перечитанном ответе (от этого зависит, сверяются ли справочники при проверке «200 без записи»), выставился ли 21105, не изменился ли статус и исполнитель.
3. **Возврат.** `set_rate(amount=2700, …)` — вернуть исходное значение. Перечитать и подтвердить 2700.
4. **`currentUserUsername`.** Выполнить вызов с `username=<логин LDAP из приложения>`, если он отличается от логина Jira, — зафиксировать, принимает ли Jira такое значение (риск (б) из приёмки KON-101).
5. **Негатив (по одному запросу, только если Константин разрешил запись неверных значений; иначе пропустить и записать «не выполнено»):** неверный id валюты, пустая сумма — убедиться, что защита адаптера не пускает запрос до Jira (ожидаемо `jira_error` без обращения), а при обходе проверки Jira даёт 200 без записи/500.
6. **Переход 801 без ставки (риск (а)).** **Не выполнять** на ANALYTICS-5925 без прямого разрешения Константина (смена статуса необратима). Если разрешение есть и статус позволяет — только `GET …/transitions?expand=transitions.fields` и проверить, требуются ли для 801 поля 20809–20812; сам переход не делать. Результат — в отчёт.

## Чего НЕ делать

- Не менять код продукта, тесты, `design/`; правок в репозитории нет, кроме файла отчёта.
- Не писать в другие ключи Jira, не менять статус, исполнителя, вложения, комментарии.
- Не печатать и не логировать пароль, cookie, токен, содержимое `.env`; в отчёте логины и ФИО маскировать.
- Не повторять неудачный вход по паролю больше одного раза подряд (риск блокировки учётной записи). При 403 — остановиться и сообщить Константину (VPN? подтверждение входа в браузере? устаревший пароль?).
- Если запись прошла, а возврат на 2700 — нет: немедленно остановиться и сообщить Константину, не пробовать «чинить» другими вызовами.

## Область записи

Только `qa/KON-101_live_report.md`. Временные скрипты — вне репозитория (например, `%TEMP%\opencode\`).

## Как запустить (Константину)

Включить VPN, затем в окне, где запускается OpenCode (значения не копировать в чат и файлы):

```powershell
$env:JIRA_USERNAME = "<логин Jira>"
$env:JIRA_PASSWORD = "<пароль Jira>"
```

После завершения: `Remove-Item Env:JIRA_USERNAME, Env:JIRA_PASSWORD`.

## Что вернуть

`qa/KON-101_live_report.md`: список операций (ключ, операция, код ответа, пауза), состояние «до» и «после» по полям (21105, 20809–20812, статус, исполнитель), подтверждение возврата на 2700, формат 20810–20812 в перечитанном ответе, результат по `username`, результат п. 5–6 или причина пропуска, вывод: Pass / замечания / Fail для приёмки KON-100, что не удалось и почему.
