## Что сделано

| Файл | Назначение |
|---|---|
| `scripts/deploy.ps1` | Локальный оркестратор: проверки до выкладки (чистое дерево, HEAD запушен, ветка `main`, backend unit-тесты, сборка frontend, `check_secrets.sh` — красная проверка отменяет деплой ДО отправки) → `git archive HEAD` (список путей как в `infra/deploy.md` §1) → scp архива и `deploy.sh` → запуск деплоя на ВМ → сверка `DEPLOYED_VERSION` |
| `scripts/deploy.sh` | ВМ-скрипт (ядро всех вариантов): flock (параллельный запуск отклоняется), короткое замыкание при повторе того же коммита, CRLF-проверка архива, `app.prev.<время>` с ретеншеном (3 копии), миграции **только** при изменении `db/migrations/` (перед ними дамп через механизм KON-49 `scripts/backup_db.sh`), `docker compose build/up` боевого оверлея, ожидание `/health == {"status":"ok"}` + healthy всех 5 сервисов (300 с), авто-откат на `app.prev` при любой красной проверке (без `down -v`), журнал `/opt/re_web_presale/deploy.log`, `DEPLOYED_VERSION` |
| `.gitattributes` | `*.sh`, `*.py`, `*.yml`, `*.conf`, `Dockerfile*` → `eol=lf` — закрывает риск CRLF в арх |

## Проверено локально (02.11.2026)

- `bash -n scripts/deploy.sh` — синтаксис чистый;
- файлы в LF (проверено по байтам; `.gitattributes` выт еол-правило);
- `scripts/check_secrets.sh` — секретов не найдено;
- в скриптах нет значений и путей секретов; `.env` на ВМ не читается и не печатается;
- запрещённые операции (`down -v`, `prune --volumes`) в скриптах отсутствуют.

## Чего не сделано (нужны решения владельца)

1. **Вариант 1 (runner на ВМ) или 2 (pull-таймер):** по постановке деплой «по пушу» требует либо
   self-hosted GitHub Actions runner на ВМ, либо systemd-таймер с deploy-key. Оба пункта ждут
   решений из постановки (runner и политика Support; репо приватный?). Ядро на ВМ (`deploy.sh`)
   для обоих вариантов уже готово и переиспользуется без изменений.
2. **Первый боевой прогон `deploy.ps1`** запускает владелец (интерактивная парольная фраза ключа).
   Рекомендуемый первый прогон — с `-SkipFrontendBuild -SkipBackendTests` на уже развёрнутой версии:
   проверит короткое замыкание («same version — ничего не делает», критерий ид ампотентности).

## Отправка-критерии и как проверено (после прогона владельцем)

| Критерий | Проверка |
|---|---|
| Пуш в main → версия на ВМ обновлена, DEPLOYED_VERSION = хеш | прогон после пуша; надпись «=== деплой ок ===» |
| Красная проверка — отмена/откат | `deploy.ps1` отменяет до scp (тесты/сборка/секреты); `deploy.sh` откатывает при health/миграциях (ручной тест сломанным коммитом на тест. ветке делаем после прогона) |
| Повтор того же коммита безопасен | короткое замыкание в deploy.sh («SKIP версия … уже на стенде») |
| Нет секретов в скриптах | check_secrets.sh + просмонтр |
| Параллельный запуск | flock -n → REJECT, код 3 |
| Журнал и откат | `deploy.log`, §2 infra/deploy.md |
