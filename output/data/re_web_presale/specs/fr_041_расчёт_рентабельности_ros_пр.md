## Формулировка

> _Формулировка: «Система ДОЛЖНА [действие]...»_

Система ДОЛЖНА в списке «Потребности» в столбце «Кандидаты» отображать кнопку «ROS» (контурная, под кнопкой «Сопоставить», placement — input/screenshots/ros_button_placement.png) и по клику открывать модальное окно «ROS специалиста»: ввод уровня ЗП кандидата в гросс (ФОТ с НДФЛ); рентабельность пересчитывается автоматически при вводе (без кнопки «Рассчитать», отклик ≤ 0,3 с, NFR-002-подобный).
Ставка для расчёта: а) задана клиентом — берётся из столбца «Ставка» потребности, второго поля ввода нет; б) не задана или «от производства» — в окне второе поле ввода ставки (руб. с НДС за час, валидация как у поля «Ставка» при назначении: >0, ≤ 1 000 000); валюта/единица, отличные от руб./час, — ручной ввод, значение потребности справочно.
Модель расчёта (источник: input/ROS/ROS_model_v2.xlsx, лист «ROS специалиста_v2», 165 billable-часов; лист «Лист1» с 145 ч признан устаревшим):
• Billable-часов в месяц = 165 (параметр);
• НДС = 22% (доход = выручка/122×22);
• страховые взносы «до лимита» 15,2% (15% + 0,2%), «после лимита» 7,8% (7,6% + 0,2%); лимит ФОТ = 2 979 000;
• косвенные расходы на человека = 53 000;
• налог на прибыль 5%, только если прибыль до налога > 0.
Формулы: Выручка = часы × ставка; Прямые расходы = ЗП + Взносы + НДС; Прибыль до налога = Выручка − Прямые − Косвенные; Налог = max(Прибыль до налога, 0) × 5%; ROS = Прибыль / Выручка × 100%.
Расчёт даёт ДВА значения: «до лимита» и «после лимита» ФОТ; месяц перехода вычисляется от ЗП: N = ОКРУГЛВНИЗ(Лимит ФОТ / ЗП, 0) — до лимита N месяцев, после — с N+1-го (при ЗП 130 000: 2979000/130000 = 22,9 → 22 месяца «до», «после» с 23-го).
Контрольный пример (критерий приёмки): ЗП 130 000, ставка 2 200 с НДС → выручка 363 000; ROS «до лимита» = 24,80% (прибыль 90 041,93), «после лимита» = 27,32% (прибыль 99 180,93); переход на 23-й месяц.
Решения владельца по вопросам спецификации (см. UC-ROS): 1) показываются ОБА значения (до/после лимита); «до лимита» — основное (крупнее); 2) параметры модели (часы, налоги, косвенные, лимит) хранятся в «Настройках» (роль Админ), editable; 3) кнопка ROS видна для потребностей в статусах, где доступны действия кандидата (матрица status_actions); для «Кандидат назначен» и далее — скрыта; 4) ставка клиента приводится к руб. с НДС за час (как в 4.3); валюта/единица, отличные от руб./час, — в окне поле ввода ставки вручную; 5) ЗП не предзаполняется из карточки (в Jira/БД поля нет) — ввод вручную, ничего не запоминается.
Введённая ЗП и результат НЕ сохраняются (БД, Jira, логи) — конфиденциальные данные; расчёт только при открытом окне; запись в Jira не затрагивается.

## Обоснование

РН быстро оценивает рентабельность кандидата при текущей/уточнённой ставке без внешних таблиц; решения по ставке (принять/торговаться) принимаются сразу в момент подбора.

## Ограничения и допущения

Вне MVP (Версия 2). Ввод ЗП и результат не сохраняются и не пишутся в логи (ПДн). Параметры модели в «Настройках» (CR по 5.4 — внесение в baseline). Замечание: прежний spec-файл fr_039_расчёт_рентабельности_(ros)_пр.md ошибочно использовал занятый ID FR-039 — требование перенумеровано в FR-041, дубль.id устранён.
