# KON-79 (Pre.UX-2) — «Назначить» и смена статуса. Бриф

## Кто и зачем
Руководитель направления / Presale-менеджер (до 4 человек). Назначение кандидата и смена статуса — основное действие раздела «Потребности»: 10–100 потребностей в неделю, каждое назначение — запись в Jira от имени пользователя. Цена ошибки высокая (запись в чужой Jira, вложения, комментарий), поэтому нужны подтверждение, видимый прогресс и понятный отказ.

## Требования (что обязано быть на экране)
- FR-008: окно «Назначить» — «Резюме» (по умолчанию Основное CV, можно заменить), «Ставка, руб. с НДС», «Комментарий», «Файлы» (Доп. CV и Материалы), кнопка «CV по шаблону» (FR-017); после подтверждения — запись в Jira (сотрудник, файлы, комментарий, ставка, исполнитель = пользователь, FR-009).
- FR-018: поле ставки обязательно, если «Кто предлагает ставку» = «от производства»; рядом ставка из потребности и средняя/медианная как ориентир.
- FR-010: повторное назначение заменяет прежнее; при отказе Jira — текст причины, введённое не теряется.
- FR-011, FR-026: смена статуса — допустимые переходы и обязательные поля запрашиваются у Jira; «Кандидатов нет» — причина и комментарий; отказы Jira как есть.
- FR-013, FR-029, UC-005: комментарий скрининга; при 401 повторная авторизация без потери данных.

## Контекст
Пользователь приходит из «Потребности» → «Сопоставить» → список кандидатов с кнопкой «Назначить» (сейчас заглушка). Статус потребности виден чипом в списке (KON-78). Токены и компоненты — `Modal` (шапка/тело/футер, Esc, ×), `.btn-secondary`, поля `.field`, `HintButton`; новых зависимостей нет.

## Ограничения
Стек React + текущие стили; обе темы; 1280 и 1024; высота окна ≥ 400px (тело модалки прокручивается, шапка и футер на месте). API назначения/переходов — KON-43 (Dev-12), поля обязательных переходов Jira заранее неизвестны (ISS-010) — форма переходов строится из ответа Jira.

## Допущения
- Список переходов и обязательные поля берутся у Jira при открытии диалога; причины «Кандидатов нет» — справочник Jira.
- Назначение — одна транзакция с точки зрения пользователя; прогресс показывает этапы (перечитывание потребности → профиль → вложения → комментарий/ставка/исполнитель).
- Пароль Jira при истёкшей сессии вводится в том же окне, нигде не сохраняется.
