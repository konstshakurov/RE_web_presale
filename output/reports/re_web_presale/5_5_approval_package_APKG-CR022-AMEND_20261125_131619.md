### FR-011: Статусы «Кандидатов нет» и «Найм»
**Тип:** functional | **Версия:** 1.5 | Приоритет: Should  
**Owner:** Руководитель направления Аналитики  

Система ДОЛЖНА позволять перевести потребность в статусы «Поиск кандидата», «Найм» и «Кандидатов нет» из столбца «Статус» раздела «Потребности». Статус отображается цветным облачком (чипом) без шеврона; под ним — кнопка «Изменить ⌄», открывающая выпадающее меню только доступных переходов (FR-026): «Требуется кандидат» → Поиск / Найм / Кандидатов нет; «Поиск кандидата» → Найм / Кандидатов нет; «Кандидатов нет» → Поиск / Найм; «Найм» → Поиск / Кандидатов нет; «Кандидат назначен» → Поиск / Найм / Кандидатов нет. У каждого пункта меню — иконка статуса (эталон — референс владельца 24.11.2026, скрин 4; эталон задаёт вид пунктов, а не состав меню). Для прочих статусов (включая «Отказ по кандидату») кнопки «Изменить» нет; «Кандидат назначен» выставляется только при назначении (FR-008). Меню доступно с клавиатуры: видимый фокус, aria-expanded, открытие/закрытие и выбор пункта без мыши. Облачко статуса: шрифт среднее начертание (500); цвета фона и текста — прежние (пастельный фон, цветной текст; FR-038 v1.5).

При переходе «Кандидатов нет» ДОЛЖНЫ запрашиваться обязательные поля Jira: «Причина отсутствия кандидата» (значения справочника Jira: Нет специалистов данного уровня, но есть слабее; …конкретного набора стека; …нужной отраслевой экспертизой; …нужным специфичным стеком (стек в комментарии); Низкая ставка; Увольнение/декрет кандидата; Требуется очное присутствие; Есть прямой запрос) и «Комментарий» (видимость «для всех»). Для «Поиск кандидата» — подтверждение одним кликом. Для «Найм» (переход «В найм») Jira требует ставку целиком — «Включает НДС», «Валюта», «Единица измерения» (customfield_20810–20812): значения предзаполняются из потребности, при отсутствии запрашиваются; проверка обязательности — до отправки (проба KON-30). Саму ставку («Планируемая ставка», 20809) при найме не вводят: она вносится при назначении (FR-018); значения справочников передаются по id, полученным у Jira. Значения справочника и обязательные поля ДОЛЖНЫ запрашиваться у Jira, а не храниться в приложении (см. FR-026).

**Критерии приёмки:** 1. Для статусов с доступными переходами показывается облачок статуса (без шеврона) и кнопка «Изменить ⌄»; для статусов без переходов (включая «Отказ по кандидату») кнопки нет.
2. Меню показывает только переходы, которые Jira отдаёт для текущего статуса (FR-026); у каждого пункта — иконка статуса.
3. Выбор пункта ведёт к прежнему поведению: «Кандидатов нет» — обязательные поля Jira; «Поиск кандидата» — подтверждение одним кликом; «Найм» — предзаполнение «Включает НДС»/«Валюта»/«Единица измерения» из потребности.
4. Облачко статуса — прежние цвета фона и текста, шрифт 500.
5. Меню управляется клавиатурой (открытие/закрытие/выбор), aria-expanded корректен, фокус видим.

**CR-история:** CR-005 (approved/Approved); CR-007 (approved_modified/Approved_with_Modification); CR-008 (approved_modified/Approved_with_Modification); CR-022 (approved/Approved)


### FR-034: Таблица потребностей и кнопка синхронизации
**Тип:** functional | **Версия:** 1.3 | Приоритет: Must  
**Owner:** Руководитель направления Аналитики  

Раздел «Потребности» ДОЛЖЕН показывать таблицу потребностей из кэша Jira. Состав и названия столбцов — по факту реализации (решение владельца 24.11.2026, скрин 2): «Ключ», «Автор», «Название» (со ссылкой в Jira; предупреждение о возможном дубле FR-014 и раскрываемые комментарии Jira), «Статус» (цветной чип + «Изменить ⌄» FR-011), «Клиент» (со ссылкой «Правила ⌄» FR-015), «Контракт» (Прямой контракт / Суб — «Субподряд» отображается сокращённо «Суб»), «Ставка», «Кандидаты» («Сопоставить ⌄» FR-036; счётчик «N кандидатов ⌄»; «ROS» — рентабельность по ставке, FR-041/BF-12), «Создана» (дата создания потребности, сортировка). Отдельные столбцы «Исполнитель» и «Требования» из v1.0 в реализации отсутствуют; «Сопоставить ⌄» размещается в столбце «Кандидаты».

Над таблицей ДОЛЖЕН быть блок фильтров: (1) поиск по ключу и названию с очисткой (X); (2) фильтр дата-диапазона по дате создания потребности (столбец «Создана») — поля «дд.мм.гггг — дд.мм.гггг» с календарём, быстрые кнопки «Сегодня», «7 дней», «30 дней» и «Сбросить даты»; (3) кнопка «Обновить» без иконки внутри кнопки — принудительная синхронизация, не дожидаясь периодической (FR-028); иконка обновления — перед текстом штампа «актуально на…»; (4) текст используемого JQL-запроса (только чтение, редактируется в «Настройках»). Дата-фильтр комбинируется с фильтром групп статусов (FR-035) и поиском по И; «Сбросить даты» очищает диапазон и снимает ограничение. Фильтрация выполняется на стороне API/кэша.

Система ДОЛЖНА показывать время последней синхронизации и количество потребностей. В столбце «Ставка» значение вида «2 240 RUB» показывается в одну строку без переноса, шрифтом строки (решение владельца 25.11.2026: отдельный уменьшенный шрифт ставки отменён); при отсутствии значения — «—» (вместо «не указана»). Технологии и навыки выделяются из требований при синхронизации (кэш), показывается и исходный текст. Добавление комментария к потребности из приложения — этап 2.

Примечание (CR-022): кнопку принудительной синхронизации в реализации ведут как «Обновить»; формулировка v1.0 называла её «Синхронизировать» — приведено в соответствие.

**Критерии приёмки:** 1. Состав и названия столбцов соответствуют скрину 2 (текущая реализация): Ключ, Автор, Название, Статус, Клиент, Контракт, Ставка, Кандидаты, Создана.
2. Дата-диапазон фильтрует таблицу по дате создания (столбец «Создана»); «Сегодня»/«7 дней»/«30 дней» заполняют диапазон; «Сбросить даты» очищает поля и снимает ограничение.
3. Дата-фильтр комбинируется с группой статусов (FR-035) и поиском по И; поле поиска очищается крестиком (X).
4. В столбце «Ставка» значение в одну строку («2 240 RUB» без переноса), шрифт — как во всей строке таблицы; при отсутствии — «—».
5. Кнопка «Обновить» — без иконки внутри кнопки; запускает принудительную синхронизацию; штамп «актуально на…» с иконкой обновления перед текстом и счётчик потребностей сохраняются.

**CR-история:** CR-022 (approved/Approved)


### FR-035: Фильтр потребностей по группам статусов
**Тип:** functional | **Версия:** 1.2 | Приоритет: Must  
**Owner:** Руководитель направления Аналитики  

Раздел «Потребности» ДОЛЖЕН предоставлять фильтр по группам статусов в один клик (чипы над таблицей, у каждой — счётчик потребностей). Группы по умолчанию (статусы workflow Jira типа «Аналитик»): «Без кандидата» — Требуется кандидат, Поиск кандидата, Найм, Отказ по кандидату, Интервью не пройдено; «Кандидат назначен» — Кандидат назначен; «Интервью» — Подготовка к интервью, Интервью состоялось, Интервью пройдено, Интервью не пройдено; «Закреплён» — Закреплен за проектом. Статус может входить в несколько групп («Интервью не пройдено» входит в две). Статусы вне перечисленных групп (Кандидатов нет, Поиск партнерки, Партнерка, На проекте, Скоро освобождается, Работа завершена, Не на проекте, Неактуально, Отложено) доступны через группу «Прочие» и режим «Все статусы». Стартовая группа — «Без кандидата». Состав групп хранится в «Настройках» и меняется администратором без правки кода; выбор фильтра запоминается для пользователя. Названия статусов берутся из Jira как есть.

Чипы групп ДОЛЖНЫ отображаться по цветовое решению design/KON-166 (предложение UX, принято владельцем 25.11.2026): синий и яркие пилюли; шрифт чипов — среднее начертание (500), не жирный; смысл не передаётся только цветом, подписи чипов сохраняются. Если в составе групп есть группа «Субподряд», её чип ДОЛЖЕН отображаться сокращённо «Суб»; название группы в «Настройках» не меняется.

**Критерии приёмки:** 1. Клик по чипу группы сразу оставляет в таблице потребности только с её статусами.
2. Счётчик группы равен числу потребностей в ней.
3. Чипы отображаются в цветах по design/KON-166 (синий); шрифт — среднее начертание 500, не жирный; смысл не передаётся только цветом.
4. Чип группы «Субподряд» показан как «Суб»; название группы в «Настройках» остаётся «Субподряд».
5. Стартовая группа «Без кандидата», запоминание выбора и «Прочие»/«Все статусы» — как в v1.0.

**CR-история:** CR-022 (approved/Approved)


### FR-038: Логотип и фирменный вид интерфейса (светлая тема А2, цветные статус-чипы)
**Тип:** functional | **Версия:** 1.5 | Приоритет: Could  
**Owner:** Руководитель направления Аналитики  

Система ДОЛЖНА показывать логотип «regoose» (исходник design/KON-78/logo/logo_B_CandaraLight.png; в шапке — два ассета logo_head.svg и logo_wordmark.svg по design/KON-135; фавикон favicon_dark_256.png) в шапке каждой страницы и на странице входа; на форме входа логотип не меняется. Общий вид и расположение элементов ДОЛЖНЫ ориентироваться на референсы из input/Референсы (тёмная верхняя панель с разделами, таблицы со столбцами и кнопками действий, модальные окна).

Светлая тема ДОЛЖНА использовать палитру А2 по design/KON-149/decision.md (утверждена 29.10.2026; заменяет вариант 4 KON-142 и палитру CR-015): токены --bg, --accent, --primary, --nav и производные; значения — в решении KON-149. Статусы сотрудников и кандидатов ДОЛЖНЫ показываться цветными пастельными чипами: карта «статус → тип» (ok/info/err/warn/neu) в frontend/src/lib/statusTone.ts; наведённая и выбранная строки таблиц ДОЛЖНЫ заливаться (--row-hover, --row-sel) с левой полосой 3 px; вторичные кнопки — в новый акцент. Тёмная тема НЕ ДОЛЖНА меняться.

Начертание текста: везде, где использовался вес 400 (обычный), ДОЛЖЕН применяться вес 500 (средний); гарнитура НЕ меняется (system-ui), без @font-face. В шапке системы начертание названий разделов навигации и имени пользователя — 500 (среднее).

Раздел «Потребности» (CR-022, референсы владельца 24.11.2026 с поправками 25.11.2026): радиусы всех кнопок, тип шрифтов и цвета — по референсу; размер шрифта строк таблицы — на 2 пункта меньше текущего; чипы статусов потребностей в столбце «Статус» — прежние цвета фона и текста (пастельный фон, цветной текст — НЕ белый текст на яркой заливке), шрифт средний (500), шеврона у облачка нет; чипы групп статусов (FR-035) — цветовое решение как предложено в design/KON-166 (синий и яркие пилюли), шрифт средний (500), не жирный; высота кнопок внутри таблицы («Сопоставить», «ROS», «Резюме», «Назначить», «Похожая» и др.) — равна высоте облачка столбца «Статус», шрифт средний (500); радиусы углов контейнера таблицы по референсу; затемнение по контуру — как у блока фильтров, применить и к контейнеру таблицы; раскрытые блоки «Правила ⌄» и «Сопоставить ⌄»/«N кандидатов ⌄» — белые блоки на голубом фоне (как предложено в design/KON-166), но внутреннее расположение текста (заметки, навыки) — как уже реализовано, не перестраивать; ссылки-действия с шевронами на одной линии с текстом, активное состояние — ⌃; подпись «Субподряд» — «Суб» (FR-035). Кебаб-меню из референса НЕ реализуется (пункт 3.11). Иконку в кнопке «Обновить» НЕ добавлять: иконка обновления уже стоит перед текстом штампа «актуально на…» (пункт 3.2 отменён); высота шапки таблицы — прежняя (пункт 3.12 отменён). Значения новых токенов — design/KON-166/decision.md после апрува владельца.

**Критерии приёмки:** 1. В шапке каждой страницы — логотип из двух ассетов; на странице входа — логотип без меню; фавикон установлен.

4. Наведённая и выбранная строки таблиц заливаются с левой полосой 3 px.

8. Шрифт строк таблицы раздела «Потребности» — на 2 пункта меньше текущего; высота строки заголовков — прежняя (без −20%).

10. Чипы групп статусов — цвета как предложено в design/KON-166 (синий), шрифт 500 (не жирный); «Субподряд» — «Суб».
