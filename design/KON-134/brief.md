# KON-134 (Pre.UX-8) — «Сотрудники»: мультивыбор статусов и фильтр «РО», бриф

Статус: варианты на согласовании (decision.md нет, апрува владельца нет). Вместе ведётся KON-124 (тексты и переносы) — один пакет, один макет.

- **Кто и зачем:** РО, пресейл, подбор — отбор сотрудников по нескольким статусам и по руководителю отдела; несколько раз в день.
- **Требования:** FR-002, FR-028; CR-012 (Approved): мультивыбор статусов (выбрать несколько, снять один или несколько), фильтр «РО» из поля Jira «Руководитель отдела» (customfield_14401, отображаемое имя, напр. «Евгения Синицына»), по умолчанию «Все»; комбинация по И с поиском, технологией и «Показывать уволенных».
- **Что есть сейчас** (`frontend/src/pages/EmployeesPage.tsx`): ряд чипов статусов, выбирается один («Все» или один статус); панель: поиск + тумблер «Уволенные»; фильтрация на клиенте по загруженному списку; счётчики чипов — из `counts` синхронизации.
- **KON-124 (сотрудники):** кнопки «Профиль», «Резюме», «Файлы» всегда в одну строку.
- **Допущения:**
  1. Внутри выбора статусов связь ИЛИ (подходит, если статус среди выбранных); между фильтрами (статусы, РО, поиск, «Уволенные») — И. Без выбранных статусов фильтра по статусу нет.
  2. Счётчики статусов и «Все» считаются с учётом фильтров РО и «Уволенные» (не поиска) — иначе при выбранном РО цифры расходятся с результатом. Считается на клиенте по загруженному списку; если Dev оставит серверные `counts`, счётчики станут общими — это нужно зафиксировать в decision.
  3. «Уволен» остаётся тумблером, а не статусом (как `FIRED_STATUS`).
  4. «РО» — одиночный выбор из выпадающего списка («Все» по умолчанию), как сказано в CR.
  5. Значения РО — отображаемое имя из Jira, по алфавиту.
- **Пробел в требованиях (не придумываю):** CR-012 говорит о комбинации с «технологией», но на экране «Сотрудники» фильтра по технологии нет (он есть только в «Резюме»). В макетах его нет; панель переносится на вторую строку, если его добавят. Вопрос — в README.
- **Ограничения:** React/TS, токены проекта, без UI-kit. Для варианта B нужен собственный компонент выпадающего мультивыбора (новой зависимости нет).
