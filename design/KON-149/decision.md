## 3. Классы и привязка статусов
`.status` — базовый стиль: `background: var(--chip-neu-bg); color: var(--chip-neu-fg);` (вместо `var(--panel-2)`/`var(--ok)`; прочее без изменений: `border-radius: 4px; padding: 2px 8px; white-space: nowrap`). Модификаторы: `.status--ok`, `.status--info`, `.status--err`, `.status--warn` (подставляют пару `--chip-<тип>-bg/fg`); `.status--neu` = базовый. Смысл не только цветом: текст статуса всегда виден в чипе.
Dev вводит функцию сопоставления «статус -> тип» (`lib/statusTone.ts`, регистр и пробелы нормализовать как в `statusButtons`; **неизвестный статус -> нейтральный**) и применяет в местах рендера статуса.

Статусы потребностей (Jira workflow, `lib/assign.ts`):
| Статус | Тип |
|---|---|
| требуется кандидат | `warn` (янтарный: нужно действие) |
| поиск кандидата | `info` (голубой: в работе) |
| найм | `info` |
| кандидатов нет | `err` (красный) |
| кандидат назначен | `ok` (зелёный) |

Статусы сотрудников (10, `lib/employees.ts`, FR-002):
| Статус | Тип |
|---|---|
| Свободен | `ok` |
| Скоро освобождается | `warn` |
| Ожидает подключения | `warn` |
| Коммерческий проект | `info` |
| Внутренний проект | `info` |

| Недоступен для подключения | `err` |
| Уволен | нейтральный |

Места применения (`<span className="status">`): `NeedsTable.tsx:101` (статус потребности), `EmployeesPage.tsx:148` и `EmployeeProfile.tsx:87` (статус сотрудника), `EmployeeProfile.tsx:158` (статус потребности в списке), `matching/CandidateList.tsx:67` (`r.status` — Dev проверяет, чей это статус; если сотрудника — карта сотрудников, иначе нейтральный). Бейджи `.badge--paused/--stale/--reauth/--error` не меняются (остаются текстом `--warn`/`--err` на `--panel-2`).
`.pct--high/mid/low` не меняются (уже пастельные).

## 4. Заливка строки
- Наведение: `.needs tbody tr:hover { background: var(--row-hover); }`.
- Выбранная = раскрытая строка таблицы потребностей (`expanded === n.jira_key` в `NeedsTable.tsx`, строка 85): класс `is-selected` на `<tr>` (и на строке с раскрытым содержимым, если она отдельная); `.needs tbody tr.is-selected { background: var(--row-sel); box-shadow: inset 3px 0 0 var(--primary); }`. Левая полоса обязательна: заливка почти не отличается от фона (1,09:1), смысл выбора не должен передаваться только цветом.
- Карточки (`.card`) и прочие таблицы не меняются. Если в других таблицах нет понятия выбранной строки — заливка только при наведении.

## Критерии приёмки UI (для Dev и QA)
1. Светлая тема: значения токенов равны п. 1; `--secondary` `#2368b8`; нет прежних `#fdfcf9`, `#f5f3ee`, `#e4e0d7`.
2. Статусы потребностей и сотрудников отображаются чипами по таблицам п. 3 (пастельный фон + тёмный текст того же тона); неизвестный статус — нейтральный чип; статус всегда читается текстом.
3. Контраст текста во всех состояниях не ниже 4,5:1 (значения п. 5; проверка измерением на стенде).
4. Раскрытая строка потребности: заливка `--row-sel` и левая полоса 3 px `--primary`; наведение — `--row-hover`; карточки без изменений.
5. Вторичные кнопки (`.btn-secondary`, `.button:not(.primary)`) — текст/рамка `#2368b8`, hover-фон `rgba(35,104,184,0.08)`.
6. Шапка: фон `#202b36`, высота 64 px, активная вкладка `--bg`; логотип и бейдж «Админ» без изменений.
7. Экраны «Потребности», «Сотрудники», «Резюме», «Настройки», модалки, плашка Jira (светлая тема) соответствуют `pal_V_*_1280.png` по палитре; ширины 1280 и 1024 (`pal_V_needs_1024.png`).
8. **Тёмная тема не изменилась** (снимки до/после по всем экранам; новые токены в тёмной = прежний вид, все чипы статуса выглядят как сейчас).
9. Фокус (`--accent`, 2 px), выбранные чипы-фильтры и переключатель в светлой теме различимы.
