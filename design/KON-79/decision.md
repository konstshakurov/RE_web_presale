**(б) Запись ставки при назначении.**

**Оценка по чек-листу ux_design и предложения (решает владелец; Dev не меняет без апрува):**
1. Пустое отключённое поле при «Клиент» несёт placeholder «например, 3 800» — выглядит как приглашение ввода. Предложение: при `disabled` placeholder не показывать; в подсказке дописать «Ставку предлагает клиент — здесь не вводится.» (один новый текст).
2. В подтверждении при «Клиент» «Ставка: не указана» читается как пропуск. Предложение: «ставка клиента, не передаётся».
3. При частичном успехе поля «Резюме», «Файлы», «Комментарий» остаются редактируемыми, хотя уже отправлены и повтор их не передаёт — ложное ожидание. Предложение: на время «Повторить» блокировать их (или скрыть), оставив поле ставки; кнопку «Отмена» переименовать в «Закрыть» (назначение уже выполнено).
4. Блок предупреждения: контраст, `role="alert"`, текст причины — соответствуют чек-листу; замечаний нет. Шаг «Ставка» в прогрессе — замечаний нет.

## Что реализовать (вариант A, минимальный; уточняется после апрува)
**Назначение (UC-001, FR-008, FR-018, FR-010):**
- Окно «Назначить кандидата» (`Modal wide`): контекстная строка (потребность · клиент · кандидат), «Резюме» (по умолчанию Основное CV), «Ставка, руб. с НДС» (обязательна при «от производства»; рядом ставка потребности и ориентир), «Комментарий», «Файлы» (Доп. CV и Материалы), «CV по шаблону клиента…» (secondary; диалог — KON-80).
- «Назначить…» → экран подтверждения со сводкой и пояснением «Jira сама переведёт потребность в «Кандидат назначен»; вручную менять статус не нужно» → «Подтвердить и отправить в Jira».
- Прогресс по этапам, отказ Jira (текст как есть, введённое сохранено, «Повторить»), истёкшая сессия (пароль Jira в окне, данные сохранены).
- После успеха окно закрывается, статус потребности в списке обновляется из Jira (перечитывание).
- Файлы и комментарий статус не меняют (учитывается в тексте подтверждения).

**Статус (FR-011, FR-026):** ссылки-кнопки в столбце «Статус» по текущему статусу потребности — матрица и правила в `status_actions.md` (белый список «Поиск», «Найм», «Кандидатов нет» × текущий статус из кэша; без запросов к Jira при открытии списка, переходы Jira — при клике, KON-96). «Кандидатов нет» — диалог с причиной и комментарием; остальные — подтверждение одним кликом. Универсального списка переходов нет. Отказ Jira — текст как есть, введённое сохранено.

## Токены и стили
Существующие токены; secondary — `--secondary`, основная кнопка `--primary`; новых токенов нет.

## Данные и API (KON-43)
Назначение; допустимые переходы с полями; повторная авторизация Jira. Нет метода — состояние показывает «недоступно» (допущение).

## Критерии приёмки UI
1. Столбец «Статус»: кнопки-ссылки (цвет `--accent`, без рамки и заливки) по матрице `status_actions.md`; для «Отказ по кандидату» и всех статусов вне матрицы под чипом ничего нет. Кнопки строятся из белого списка и кэша статуса, без обращений к Jira при открытии списка (KON-96); переход проверяется при клике: если Jira его не отдаёт — диалог «Действие недоступно» с текстом про права/воркфлоу.
2. «Назначить» у кандидата открывает окно: контекстная строка, «Резюме», «Ставка, руб. с НДС» (обязательна при «от производства», сообщение «Укажите ставку…»), «Комментарий», «Файлы», «CV по шаблону клиента…». Основное действие «Назначить…» → экран подтверждения с пояснением, что статус «Кандидат назначен» выставит Jira → «Подтвердить и отправить в Jira». Ручного поля или шага смены статуса нет.
3. Прогресс отправки по этапам; закрыть окно во время отправки нельзя.
4. Отказ Jira: рамка `--err`, текст ответа Jira как есть, введённые значения сохранены, основное действие «Повторить».
5. Истёкшая сессия Jira: блок «Сессия Jira истекла» с полем «Пароль Jira» в том же окне; данные сохранены; пароль нигде не запоминается.
6. После успеха окно закрывается, потребность перечитывается, чип статуса и кнопки обновлены.
7. «Кандидатов нет»: диалог с обязательными «Причина отсутствия кандидата» (справочник Jira) и «Комментарий»; «Поиск» — подтверждение одним кликом; «Найм» — подтверждение с полями «Включает НДС», «Валюта», «Единица измерения» (предзаполнены из потребности, обязательны по Jira; поля ставки нет — она вносится при назначении); отказ Jira показывается как есть, введённое сохранено.
8. Обе темы, 1280 и 1024, высота окна 400px (шапка и футер окна на месте, тело прокручивается); клавиатура: Tab-порядок, Esc закрывает, видимый фокус.

## Вне объёма
CV по шаблону (KON-80), закрепление баннера Jira, массовое назначение.
