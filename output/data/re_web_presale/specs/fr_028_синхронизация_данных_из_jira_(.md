## Формулировка

> _Формулировка: «Система ДОЛЖНА [действие]...»_

Система ДОЛЖНА получать данные Jira опросом с локальным кэшем, без вебхуков. Потребности: инкрементальный JQL по updated каждые 5 минут, запрашивать только необходимые поля; при первичной загрузке загружать потребности за 6 месяцев. Сотрудники: выполнять полную выгрузку задач типа «Epic» проекта ANALYTICS раз в час и по запросу пользователя; ограничение первичной загрузки за 6 месяцев относится только к потребностям. При синхронизации сотрудника система ДОЛЖНА читать из Jira поле «Руководитель отдела» (customfield_14401, тип user) и сохранять логин в нижнем регистре, отображаемое имя и признак active. Значение-заглушка «Не назначен» ДОЛЖНО трактоваться как отсутствие руководителя (NULL). Эпики и правила клиента загружаются при открытии, срок кэша — 1 час; дети эпика — через Agile API. Перед записью в Jira система ДОЛЖНА перечитать потребность. Пользователю ДОЛЖНЫ быть доступны кнопка «Обновить» и отметка «актуально на». Фоновый опрос ДОЛЖЕН использовать токен любого активного пользователя только для чтения; если токенов нет, опрос приостанавливается.

## Обоснование

Обеспечить актуальный кэш профиля сотрудника и использовать назначенного руководителя отдела при фильтрации сотрудников.

## Ограничения и допущения

Вебхуки не используются. Список и период опроса: потребности — инкрементально каждые 5 минут, сотрудники — полная выгрузка раз в час и по запросу. Jira Epic Link = customfield_10101. Поля parent и priority Jira не отдаёт. customfield_14401 — user; заглушка «Не назначен» нормализуется в NULL. Неактивные и скрытые настройкой окружения руководители не предлагаются в фильтре РО (логика потребительского фильтра описана в FR-002). Фоновый опрос прекращается при отсутствии активных пользовательских токенов.

## Acceptance Criteria

1. Обновление списка потребностей выполняется инкрементально по updated не реже одного раза в 5 минут; первичная загрузка охватывает 6 месяцев.
2. Сотрудники загружаются полной выгрузкой задач типа «Epic» проекта ANALYTICS раз в час и по запросу; лимит 6 месяцев к этой выгрузке не применяется.
3. Синхронизация сотрудника получает поле customfield_14401 и сохраняет логин руководителя в нижнем регистре, отображаемое имя и active.
4. Если в Jira указано «Не назначен», в локальном кэше руководитель хранится как NULL.
5. Эпик и его правила кэшируются на 1 час; связанные потребности эпика получаются через Agile API.
6. Перед любой записью в Jira система перечитывает текущую потребность; пользователь может запросить обновление и видит время актуальности данных.
7. Фоновый опрос использует только токен активного пользователя и только для чтения; если доступного токена нет, опрос приостанавливается.
