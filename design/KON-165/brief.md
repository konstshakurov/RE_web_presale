# KON-165 — Предупреждение о дубле потребности (FR-014) — бриф

## Кто и зачем
РН / РО / Presale-менеджер в разделе «Потребности» (таблица из кэша Jira). Потребность может
прийти дважды: прямой запрос клиента + карточки субподряда, либо одна и та же потребность
появляется повторно. Пользователь смотрит список десятки раз в день; предупреждение должно
замечаться периферийным зрением и не мешать чтению таблицы.

## Требования (FR-014, baseline v2.1)
- Сравнение по **описанию** (не по названию), % совпадения.
- Окно сравнения: потребности на аналитиков за последние **2 недели**, во **всех статусах**
  (по статусу, не по резолюции — БП-10).
- Дубль: **15% и более** текста требований к кандидату, совпадающего в последовательном
  изложении (порог — решение заказчика, ISS-005).
- Место показа уже утверждено: FR-034 v1.0, строка 22 — столбец «Запрос» («предупреждение
  о возможном дубле FR-014»). В текущей реализации столбец «Запрос» разложен на «Название»
  (ссылка в Jira) и «Клиент»; значок размещаем у названия.

## Контекст
Таблица `.needs` с раскрытием строки (ClientRules, статус-действия, кандидаты, ROS).
Готовые паттерны: `HintButton` (контурный значок 18px, цель 24×24), пилюли процента
`.pct--high/mid/low`, статус-чипы `statusTone.ts`, раскрытие блока под строкой,
`Modal.tsx` для окон. Обе темы через токены.

## Ограничения
- Стек: React SPA + FastAPI, без новых зависимостей.
- Данные (допущение): дубли считаются при синхронизации (FR-028) и отдаются со списком
  потребностей полем `duplicates` (ключ, %, название); отдельного запроса на клик нет.
- Предупреждение **не блокирует** работу (информирование).

## Допущения (явные)
1. Порог 15% и окно 2 недели задаются кодом (конфигурация — вне этой задачи).
2. Если расчёт дублей на синхронизации недоступен — значок не показывается (молча, без ошибки
   в таблице; ошибка расчёта видна в штампе синхронизации).
