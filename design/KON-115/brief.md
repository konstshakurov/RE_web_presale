# KON-115 (Pre.UX-7) — редактор заметки сотрудника в «Резюме»: бриф

Статус: **proposed** (ожидает решения владельца). `decision.md` не создаётся до апрува.

## Цель
Дать пользователю способ изменить, сохранить и очистить заметку о сотруднике (FR-033, Could, CR-004) в таблице «Резюме», где столбец «Заметка» и кнопка «Изменить» уже утверждены (`design/KON-78/decision.md`, п. 7), но кнопка сейчас всегда disabled. Backend готов (KON-94).

## Сценарий
1. Пользователь в «Резюме» нажимает «Изменить» в строке сотрудника.
2. Видит поле с текущей заметкой (или пустое), счётчик знаков, кнопки.
3. Меняет текст -> «Сохранить» (или очищает -> «Очистить заметку»).
4. После успеха в таблице: текст, автор (логин из сессии), дата; на 4 с пометка «Сохранено» / «Заметка очищена».
5. При ошибке: текст ответа сервера как есть, введённое сохраняется, можно повторить.

## Контракт API (вход)
`PUT /cv/employees/{employee_key}/note`, тело `{"note": "..."}`; ответ `note`, `note_author`, `note_updated_at`. Лимит 2000 знаков; пустая строка очищает; 404 «Сотрудник не найден»; 422 при превышении; автор из сессии, дата — сервером.

## Ограничения
- Стек: React/TS, без новых UI-библиотек; токены только существующие (`design/tokens.md`, KON-78) — **новых токенов нет**, новых зависимостей нет.
- Таблица «Резюме»: ширины 21/22/33/24%, на 1024 столбец «Заметка» = ~228 px.
- Обе темы, 1280 и 1024. Тексты — короткие, по-русски, без новых терминов.
- Требования не меняются.

## Допущения (помечены; проверить)
1. **Автор** выводится как приходит из API — логин (`note_author`), не ФИО: в макете `ivanova`. В утверждённом макете KON-78 было «Иванова А.»; если нужно ФИО — это серверное сопоставление логина (вне задачи) или решение владельца показывать логин.
2. **422 по длине:** тело 422 у FastAPI/pydantic — массив, `errorText` во frontend даст общий «Проверьте введённые данные». Поэтому во всех вариантах превышение лимита **не даёт отправить**: счётчик краснеет, «Сохранить» disabled, подсказка «Сократите текст на N знаков». Текст ответа «как есть» показывается для 404/503 и прочих ошибок.
3. Пробелы по краям сервер, возможно, обрезает — поведение не проверялось; макет отправляет текст как набран.
4. Тексты ошибок в прототипе — образцы («Сервис временно недоступен, повторите позже», «Сотрудник не найден»); на проде выводится `detail` ответа.
5. Шапка в прототипе упрощена (без логотипа); таблица «Резюме» — вымышленные данные, столбец «Файлы» упрощён.
6. Подсказка «Учитывается при сопоставлении с потребностью» опирается на FR-005 (заметка входит в оценку соответствия); если формулировка не подходит — убрать, на решение не влияет.

## Общее для всех вариантов (не предмет выбора)
- Поле: многострочное, `textarea`, переносы строк сохраняются и показываются в таблице (`white-space: pre-wrap`), без жёсткого `maxlength`.
- Счётчик «N / 2000» всегда виден; от 1900 — жирный, свыше 2000 — `--err` + рамка поля `--err`.
- «Сохранить» активна только при изменении текста и длине до 2000.
- «Очистить» — стирает текст в поле (не отправляет); после этого главная кнопка превращается в «Очистить заметку» (текст `--err`) — двухшаговая очистка, отдельного подтверждения не нужно.
- Сохранение: поле только для чтения, кнопки disabled, «Сохраняем…» со спиннером.
- Ошибка: `role="alert"`, `--err`, текст ответа как есть; поле не очищается; фокус возвращается в поле.
- Ctrl+Enter — сохранить, Esc — отмена (в процессе сохранения не работает). Фокус после закрытия — на «Изменить» этой строки.
- Автор и дата: «ivanova, 21.10.26, 11:20» — формат как в утверждённом макете.
